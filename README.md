# cld_human_behaviour — 操作方法

人間の振る舞い・適応・相対的能力・資源・進化をテーマにした、ゲーム要素のあるシミュレーション（1人 = 1ノード）。

**この文書には「今の操作方法」だけを書きます。** 変わったら上書きし、古い記述は残しません。

| 知りたいこと | 見る文書 |
| --- | --- |
| どう動かすか | この文書 |
| いつ何が変わったか・なぜそう決めたか（設計判断ログ） | `HISTORY.md` |
| 今どうなっているか（アーキテクチャ・規約・原則・ロードマップ） | `CLAUDE.md` |
| これから何を作るか（実装計画のチェックリスト） | `PLAN.md` |
| ノードが従うルール | `NODE.md` |
| 外敵が従うルール（未実装） | `ENEMY.md` |
| パラメータの一覧と既定値 | `PARAMETERS.md` |

## 必要なもの

- Go 1.24 以上（`go.mod` は 1.24.0。動作確認は go1.24.0 linux/amd64）
- `cmd/devview` の描画に ebiten を使うので、GUIが出せる環境（WSL2 + WSLg、`DISPLAY=:0` で動作確認済み）
- 外部依存は ebiten のみ。`go run` すれば取得される

## ビルドと検証

```bash
go build ./...
go vet ./...
go test -race ./...
```

この3つが常に通ることがコーディング規約です。ホットパス（`engine` のtickループ、近傍探索、大量ノードを走査する処理）に触れたときは、変更の前後でベンチマークを取ります。

```bash
go test ./engine/... -run=^$ -bench=. -benchmem
```

`-run=^$` で通常のテストを飛ばしてベンチだけ回します。`BenchmarkEngineStep`（300体）／`BenchmarkEngineStepCrowded`（混雑時）／`BenchmarkDecide`（効用比較1回）／`BenchmarkEngineStepLarge`（同じ密度で9倍の広さ・1200体。空間インデックスは個体数が増えてはじめて効くので、既定の3本だけでは効果が見えない）の4本。

**世界を進める3本は、400tickごとに世界を作り直しています**（作り直しの間はタイマーを止める）。1つの世界を `b.N` 回進める素朴な形だと、**測っている間も世界が進むので、長く回すほど別の世界を測る**ことになり、同じコードで 82µs〜758µs までばらつきました。今の形なら `-benchtime` を10倍振っても数%に収まるので、**前後比較にそのまま使えます**。

特定のテストだけ動かす例:

```bash
go test ./engine/ -run TestCorneredAgentRunsFromTheOneKillingIt -v
```

## シミュレーションを見る（cmd/devview）

`protocol` / `server` / `client` はまだ無いので、現状の唯一の実行方法は開発用ビューアです。`engine` を直接importしてその場に描画します（ネットワークなし）。

```bash
go run ./cmd/devview                  # そのまま眺める
go run ./cmd/devview -follow 7 -slow  # ノード#7を1/5速度で追う
go run ./cmd/devview -play            # 1ノードを自分で操作して遊ぶ
go run ./cmd/devview -ask -slow       # 同じノードを「転機だけ訊かれる」形で遊ぶ（段階23）
```

| オプション | 意味 |
| --- | --- |
| `-follow <ID>` | 起動時からそのノードを選択（追跡）する。0で選択なし |
| `-slow` | 1/5速度で開始する |
| `-beliefs` | 右パネルを「他者への記憶」側で開始する（Tabで切り替えられるが、キー操作を送れない環境用） |
| `-seed <n>` | 乱数シード（既定1）。同じシードなら常に同じ結果になる |
| `-load <file>` | **保存した世界の続きから始める**（段階21）。**世界は自分の `Config` を連れてくる**ので、世界の形を決める他のフラグは無視されます |
| `-nodes <file>` | 新しい世界を作って、**他所で育った個体群をそこに入れる**（段階21） |
| `-terrain <名前>` | 世界を地形の上に敷く（段階20）。`rough`（西半分が荒れ地）／`river`（南北に川）／`plateau`（北東に2段の高台とスロープ）／`country`（全部入り）。既定は平坦。**水（`~`）は渡れますが、そこで過ごす1tickごとに溺れることがあります**（段階34。上部の `deaths` に `drowned` が出ます）。**そのぶん水辺は食料が豊かです**（段階36）——遊ぶ世界の川は、罰だけの地形ではなく取引になっています。**このとき食料も地面に結びつき**（段階33＝荒れた地域ほど痩せている）、**高いところは当てにくくなります**（段階30＝下から殴られると3割外れる）。どちらも測定用の既定は0で、**遊ぶ世界にだけ渡します** |
| `-footing <n>` | **地域ごとに「そこに立つと何がどれだけできるか」を変える**（段階57。0＝既定＝どの地域も同じ）。**見るためのオプション**——測ると何も動かないので既定は0で、右パネルに `and this body does everything x0.58 while it stands here` が出ます |
| `-homebound <n>` | **外敵が「入ってきた地域」から離れることに代価をつける**（段階64。0＝既定）。**引き戻しではなく値段**なので、短い深追いは起きます。右パネルに `home: 0.3 regions away, in its own country` が出ます |
| `-kinds` | **外敵を2種類にする**（段階59。軽いのがどこにでも・重いのが危険な土地に。`-prowl` 未指定なら 0.6 を入れます）。右パネルの `sort:` にその外敵がどの行かが出ます |
| `-prowl <n>` | **世界の外敵が地域ごとにどれだけ偏って湧くかを変える**（段階58。0＝既定＝どこにも同じだけ）。**湧く総数は変わりません**。右パネルに `and 194% of the world's enemies arrive hereabouts` が出ます |
| `-favour <n>` | **地域ごとに「どの遺伝子を贔屓するか」を変える**（段階57c。9本の平均は1に正規化されるので、**良い地域／悪い地域にはなりません**）。**パネルの読みはその身体の建て方で重みづけした値**なので、**同じ場所に立つ2つの違う身体が違う数字を出します** |
| `-play` | 起動時から1ノードを**自分で操作する**。`-follow` 未指定なら**予算上位半分のなかで一番速い成人**を選ぶ（下記）。`h` を2回押すのと同じ |
| `-ask` | 同じノードを「**転機だけ訊かれる**」形で遊ぶ（段階23）。`h` を1回押すのと同じ |
| `-boost` | 操作ノードの**速さを世界の平均まで引き上げる**（既定 true）。**足すのは速さの差分だけで、予算がその分だけ増えます**。`-boost=false` で素の身体のまま |

### 操作

| キー / 操作 | 動作 |
| --- | --- |
| クリック | ノードを選択して追跡（右パネルにそのノードの意思決定が出る） |
| Esc | 選択解除 |
| スペース | 一時停止 / 再開 |
| → または `n` | 1tickだけ進める（自動的に一時停止する） |
| `-` / `=` | 速度を落とす / 上げる（1/10・1/5・1/2・通常・高速） |
| `[` / `]` | 意思決定の履歴を1つ前 / 後に送る（直近16件） |
| Tab | 右パネルを「意思決定トレース」→「他者への記憶」→「操作」で切り替える |
| `h` | 選択中のノードの動かし方を切り替える。**AIだけ → 自分で操作する → 訊かれる → AIだけ** の3状態を回る（下の2節） |
| `z` | **ズーム**（1 / 1.6 / 2.5 / 4倍）。**操作中は 2.5倍から始まり、カメラが操作ノードを追う**（世界の端では止まる） |

### 画面の読み方

- **円＝身体。輪の大きさ＝その個体の体力上限（体力遺伝子）で、塗りつぶされている部分＝今残っている体力。** 大きくて欠けた円＝傷ついた大型、小さくて満ちた円＝無傷の小型
- **後ろに伸びる尾＝速さ（移動速度遺伝子）。** 長いほど速い。止まっている個体には出ない
- 輪の太さ＝攻撃力、下のバー＝空腹度、塗り色＝性別（青＝男性／桃＝女性）
- 輪の色＝状態: 灰＝採食／橙＝求愛／緑＝ペア／赤＝戦闘／紫＝逃走／青＝休息
- 赤い線＝殴っている相手、灰色の線＝ペア
- 選択中のノードには黒い輪が付き、そのノードが今狙っている対象（食料・相手）にも輪が付く
- **地面は下敷きとして描かれます**（`-terrain` を付けたときだけ）。**青＝水、茶＝荒れ地**（どちらも渡るコストが高い）、**淡い色＝高い場所**（段が上がるほど濃い）、**黄＝スロープ**（段をまたげる唯一のセル）、**濃い線＝崖**（そこは通れない）。地域の色（食料の豊かさ・休息の露出）は**その下**に描かれます
- **線は「誰が誰のところへ何をしに行っているか」です。** **赤＝殴りに行っている**、**オレンジ＝口説きに行っている**、**薄い黒＝成立したペア**。**近づいてくる異性が攻撃目的か交配目的かは、この2色で分かります**（どちらもそのノード自身の知覚に載っている事実＝`AttackingMe` / `CourtingMe` なので、プレーヤーだけが知る情報ではありません）。パネルの相手一覧にも `COMING FOR YOU` / `COURTING YOU` / `after a mate` と出ます
- **金色の点＝コイン**（段階51。`-terrain` を付けたときだけ撒かれます）。植物の緑・魚の水色と区別できる色にしてあります。**右パネルの `holding:` にそのノードが何を持っているかが名前で出ます**——「1個持っている」と「コインを持っている」は遊ぶ側にとって別の状況で、後者だけが「掲げている誰かのところへ行く理由」になります
- **茶色い四角＝倉庫**（段階50。`-terrain` を付けたときだけ置かれます）。**中に何か入っていれば中央が塗られます**。**円ではないのは、これが「生きて動くもの」ではなく世界を敷く側が置いた地物だから**。**画面には全部描きますが、そのノードが実際に見つけられるのはパネルの `knows N of M caches` の数だけ**——場所を知っていることが段階50 の全部なので、画面が無料で教えてしまわないようにしています。**エディタ（F3）では `k` でカーソルの位置に倉庫を置く／取り除く**
- **黄色い二重の輪＝手の中のものを掲げて知らせている身体**（段階49。`-terrain` を付けたときだけ＝`OfferTicks` が既定では0）。**掲げているあいだ、その中身はそれを見られる全員の知覚に載ります**（`AgentView.Offering`）。**立ち止まっているだけの身体は休んでいる身体と見分けがつかない**ので付けた印で、パネルにも `CRYING ITS WARES` と出ます

- **オレンジ色の輪＝調理している身体**（段階52。既定でオンなので、平坦な世界でも普通に見えます）。**`CookTicks` のあいだその場に立つ**ので、これも「立ち止まっているだけの身体は休んでいる身体と見分けがつかない」ために付けた印です。パネルには `COOKING` と出て、`holding:` の行には **`plant (cooked 100%)`** のように**どれだけ上手く調理されたか**が出ます（数字は調理した身体の腕前で、**持ち主の腕前ではありません**——人手に渡っても品のほうに付いてきます）

- **気分は円ではなくパネルに出ます**（段階54。`-terrain` を付けたときだけ）。`feels: FRIGHTENED (−0.35), so empty weighs 0.74` のように、**その身体が今どう感じているかと、そのせいで `ShockRisk` をいくつとして読んでいるか**が並びます（`wants:` の行に出ているのが**継いだ値**で、`feels:` の行が**今それをどう読んでいるか**。**差がそのまま気分**です）。**他の個体からは見えません**——気分は身体の外側に書かれていない唯一の量なので、円の描き方は変えていません
- **操作しているノードには金の輪が2つ付きます**（内側は身体の大きさ、外側は画面上で常に同じ大きさ）。全体表示だと身体は数ピクセルなので、外側の輪が「どこにいるか」を探せるようにするためのものです
- **金の輪＝自分が操作しているノード、緑の輪＝指名した後継、薄い金の輪＝あなたの血統の子、十字＝命令の狙い**（操作していないときは出ません）。子は生まれた瞬間に吹き出しで知らされますが、**画面上ではただの小さい円が1つ増えるだけ**だったので輪を付けました
- 上部の `hour 0.59` ＝**世界の1日のどこか**（段階18。1日は1000tick）。右パネルには選択中のノードの「眠りやすい時刻」と、今がその時刻に合っているかが出ます
- **ブロックの塗り＝その地面の植物の生えやすさ**（段階15a）。緑＝よく育つ、茶＝痩せている、無色＝普通。**総量は変わらず、どこに生えるかだけが違います**
- **ブロックの太い枠＝休むのに向いた地域**（段階14）。太いほど「背中が守られている」＝休息の露出が割り引かれる場所
- **地域は壁ではなく、ノードは自分がどの地域にいるかを知りません**（今立っている場所が休みやすいかを感じるだけ。植物の多さは「見えている食料」として間接的に分かるだけ）
- **水色の四角＝選択中のノードの視界**（段階13）。**ノードはその中心にいません**——セル境界に近ければ、片方向はすぐそこまでしか見えず、反対方向は遠くまで見通せます。ノードが動くと四角は連続的にではなく**セル単位で飛びます**

**「大きくて遅い個体」と「小さくて速い個体」はこの3つ（輪の大きさ・尾の長さ・輪の太さ）で見分けます。** 数値としての判定は `cmd/experiment` の予算比（`shVitality` / `shSpeed` / `shAttack` …）で行い、画面では「そういう個体が実際にいるか」を見ます。

### 右パネル（意思決定トレース）

先頭にそのノードの現在値が出ます。**体力は「今／上限」、そのあとに種族・予算・遺伝子9本（生の値と予算比）**が並びます。予算比のほうが個体間の比較に使えます（生の値は予算が動くだけで動くため）。

`age 1.4 years  grown 100%  expressing 100% of its genes` は、**年齢（`TicksPerYear` で年に直したもの）・成熟度・年齢補正**です。**expressing が100%未満なら、その個体は成長中か、衰えが始まっているか、どちらか**です。子は円が小さく（体力上限が低い）、画面でもすぐ分かります。

`looks 94 (what others can see of its build)` は、**他の個体から見えるその個体の体つき**（体力遺伝子と移動速度遺伝子の平均 × 年齢補正）です。攻撃力は見えません。

```
assumes: hit back 0.70 (8 seen)   courted 0.60 (8 seen)
wants:   risk x0.23   rival 0.098   empty 0.55
hunches: 4 of 4 rooms used
   other kind  -> rest      +9.2
   worn        -> observe   +4.1
   scarcity    -> attack    -1.4
   scarcity    -> eat       -2.7
```

**`assumes` はその個体が世界について信じていること**（殴り返される度合い・求愛が通る確率）で、括弧の中は**その裏にある証拠の数**です。**既定では学習がオフなので、この数は生涯 8（初期の思い込みぶん）のまま動きません**。`wants` は**その個体の好み**（リスクの重み・競合排除の価値・消耗の危険）で、こちらは既定でも個体ごとに違います。同じ場面でも隣の個体と違う手を選ぶ理由がここに出ます。

`hunches` は**その個体が持っているヒント**（段階12c）です。「X の状況では Y という手を Z だけ高く（低く）見る」という3つ組で、**`n of m rooms used` の m が買った枠数、n が実際に入っているヒントの数**。差が「教われる余地」で、空きがある個体だけが他人からヒントをコピーできます。**枠は空でも遺伝子予算を食っている**ので、`n < m` の個体は買った枠を活かせていません。候補の内訳行にも `hunch +2.30` として出ます。

その下の `memory 2/2 faces  forgets at x1.84` は、**今覚えている相手の数／覚えていられる上限**と、**忘却の速さ（世界の率の何倍か）**です。どちらも記憶遺伝子から決まります。上限に張り付いている個体は、新しい相手を覚えるたびに誰かを忘れています。

そのあとが `Decide()` を呼んだときの記録です。

- **asked because** — 何がきっかけで考え直したか（spawned / target lost / goal reached / attacked / vitality drop / idle / food in sight / bond ended / controller set）
- **at the time** — そのときの体力・空腹度・競合度
- **compared N options** — 比較した全候補をスコア順に表示。`=>` が選ばれた手
  - 1行目: 行動と最終スコア（`misjudged` は頭の良さによる評価のブレ。低いほど大きく、これが原因で最善手を外すことがある）
  - 2行目: 目的の内訳 `目的 価値x確率=寄与`（life 生存 / stake 争っている食料 / rival 将来の競合の排除 / offspring 子孫 / info 相手を知る / explore 探索）
  - 3行目: コスト `cost vit 体力=-減点  time tick数=-減点`、および `risk`（その相手に過去払わされた体力）

**`rest` の `life` が小さいときは、周りを見てください。** よそ者が近くにいるほど休息の価値は下がります（露出。`NODE.md` 8-1）。好意のある相手は数に入らないので、同じ体力でも「配偶者の隣」と「知らない相手の隣」で値が変わります。

### 右パネル（他者への記憶・Tab で切り替え）

先頭に `sizing up strangers: 80 readings -> an average build is worth 26.4 to it, -0.02 per point of build above that` が出ます。これは**その個体が自分の観測から引いた「体つき→強さ」の直線**で、まだ会っていない相手の推定はここから来ます。個体ごとに違い（実測で傾き −0.20 〜 +0.38）、観測が `AppearanceMinReads` に足りない間は固定値に戻ります。

そのあとに、相手ごとに `str 推定の強さ+/-不確かさ  risk 過去に払わされた体力  aff 好意  seen 観測数 [真の攻撃力]` が並びます。**`aff` はペア成立・出産・血縁（直系の親子）・共同で仕留めたことで入るもの**で、これがある相手のそばでは休みます。行数は記憶容量までしか増えません。**`seen 0` の行は一度も観測していない相手**で、その `str` は上の直線が体つきから出した値です（段階10 より前はここが全員 50 でした）。

意思決定はトリガー方式なので毎tick起きません。何も表示されないときは、そのノードにまだ再判断の理由が来ていないだけです。

### 1ノードを自分で操作する（段階19・これが既定の遊び方）

ノードをクリックして `h` を**2回**押すと、**そのノードのすべての判断を自分で出す**モードになります（`-play` で最初からこれになります）。

**`h` は「手綱をどれだけ握るか」を1方向に回します**: `AIだけ` → `訊かれる`（自分で動き、転機だけ訊いてくる） → `自分で操縦する`（テンキーで歩く） → `AIだけ`。**2026-09-06 に順序をこの向きに直しました**——以前は「操縦する」が先だったので、**訊かれるモードでテンキーが効かず `h` を押すと、手綱ではなくAIに戻っていました**（しかも手放すと選択も外れるので、次の `h` が「まずノードをクリックしてください」になり、そこから抜けられませんでした）。**手放したノードは選択されたまま残ります**（`h` で拾い直すため）。

**最初に渡される身体は、次の3つを満たす成人のうち一番速いもの**です。

1. **出産の代金を払っても生き残れる**（最大体力 ≥ `BirthVitalityCost`）
2. **魅力が集団の中央値以上**
3. その上で**予算上位半分**

順位と、世界の側の数字だけで選んでいます（絶対値の下限を発明していません。集団の配分は世代とともに動くので、絶対値はすぐ古くなります）。**3つとも、欠かすと遊べなくなることが実測で分かっています**——最速だけで選んだ身体は96tickで死に、体力20.8（出産の代金は20）の身体は**生涯の4割「求愛できない」状態**で、魅力7の身体は**200回求愛して3回しか受け入れられませんでした**。

**操作ノードには贈与があります**（`-boost`、既定オン）。**速さ**が世界の平均に届いていなければ、そして**体力**が出産の代金を払って生き残れる線に届いていなければ、**差分だけ足して予算をその分増やします**（他の遺伝子は1ポイントも動きません）。速さは操作性のため、体力は**そもそも血統を始められるようにする**ためです。パネルに `GIVEN +23 speed to be playable (now 44, budget 413), not the world's doing` と出るので、**世界がやったことではないと分かる形**にしてあります。

- **予算全体を増やして配分のまま速さを上げる、という形にはしていません。** 速さが予算の5%の身体を平均速度にするには予算が4倍必要で、攻撃力も体力も4倍になってしまいます
- **これは engine の中で唯一「継承も獲得もしていないものを個体に渡す」操作**です（`World.Endow`）。シミュレーションの側からは誰も呼びません
- **贈与は血統に残ります。** 予算は遺伝するので、主人公の子は増えた予算を継ぎます。長く続ければ集団に広がります
- **後継に乗り換えたときも、その身体に同じ贈与をします**

**effort の既定は 1.0**（全力）です。全力の移動は 1tick あたり `MoveCost` の体力を使い、普通の身体なら**30秒ほど走り続けると空になります**——遅くする側の選択にちゃんと意味があります。

**あなたの血統の子には薄い金の輪が付きます。** パネルにも `children: #90, #91 (not in sight)` と出ます——**子がいることを知っているのは自分の一生についての知識ですが、どこにいるかはそうではない**ので、視界の外にいる子はそう書きます（画面には世界じゅうが描かれているので輪は付きますが、視界の外の子は**狙えません**。段階19 の約束のままです）。

**主人公は短い吹き出しで喋ります。** 操作しながら右のパネルから必要な1行を探すのは無理なので、**起きたことはノードの頭の上に2〜4語で出ます**（2.5秒ほどで消え、最大4つまで積み上がり、新しいものがノードに近い側）。**吹き出しは操作ノードだけ**です。

```
        ate
somebody took that meal
    ready to court
        ●
```

出るのは次のとき: **殴られた**（`#12 is hitting me`）／**戦い始めた**（`fighting #12`）／**逃げ始めた**／**ペアが成立した**／**別れた**（子ができなかったときは `the bond ended with no child` と区別されます）／**子が生まれた**／**求愛を断られた**（`#59 turned me down`）／**求愛できるようになった**（`ready to court`）／**狙いが消えた**（`somebody took that meal`）／**食べた**／**体力が3分の1を切った**（`badly hurt`）／**後継に乗り換えた**。

**engine にはイベントの仕組みを1つも足していません。** 一生は「何が変わったか」で完全に記述できるので、**前のフレームの主人公と今の主人公の差分**から全部出しています（ペアの有無、子の数、狙いが消えた回数、殴っている相手、断られた印）。

**カメラは `z` で寄ります**（操作中は2.5倍から。追従し、世界の端で止まります）。体感速度は視野に対する相対量なので、**全景で10pxの点が動くのを見るのと、寄って見るのとでは同じ速さがまったく違って見えます**。

| --- | --- |

| `z` | ズーム（1 / 1.6 / 2.5 / 4倍） |

| `r` | 休む |

**命令キーを押すと、一時停止していれば時計も動き出します。** 命令は行為ではなく——17歩先の食料を食べるのは「歩く」＋「食べる」で、両方にtickが要ります——**止まったままでは置かれるだけで取り上げられません**。止め直すのはスペース1回です。1tickずつ読みたいときはテンキー（止まっていても1歩ずつ進みます）を使ってください。

**テンキーを離しても、他の命令は消えません。** 離したときに `rest` に戻すのは、**そのテンキー自身が置いた移動命令が残っているときだけ**です。以前はここで無条件に上書きしていたので、**一時停止中に `e` を押しても、時間を進めるためにテンキーを押した瞬間に命令が消えていました**（「目の前の食料を食べてくれない」の正体）。

**命令キーを押すと、その場で「今すぐ考え直せ」も一緒に送ります**ので、押せば次のtickから動きます。engine の側は変わっていません——ノードが答えるのはトリガーが立ったときだけで、**キーを押したことをトリガーにしている**だけです（トリガー名は `requested`）。`Enter` は**命令を変えずにもう一度訊かせる**ためのものとして残してあります。パネルの `asked N times, last on tick T` が、その命令がいつ取り上げられたかです。

**NumLock がオフだと、テンキーは矢印・Home・End・PgUp・PgDn として届きます**（X11 の仕様）。**どちらでも同じように歩けるように両方に割り当ててあります**ので、NumLock は気にしなくて構いません。そのぶん**操作中は `→` と `n` の意味が変わります**——`→` は東へ歩く、`n` は1tick待つ（操作していないときは従来どおり「1tick進める」）。

**テンキーだけは例外で、押した瞬間に1歩進みます**（命令を置く・今すぐ訊く・1tick進める、を1回でやる＝これが「1ターン」）。**一時停止中でも動きます**ので、`スペース` で止めてテンキーで1歩ずつ、が一番落ち着いて遊べます。押し続けると（0.25秒ほど待つと）そのまま歩き続け、**離すと止まります**（`rest` に戻ります）。ずっと歩かせたいときは離しても消えない `m`（狙いの方へ移動）を使ってください。

**求愛を断られたら、理由はパネルに出ます**（`AS A MATE` の2行と `LAST PROPOSAL`）。

```
AS A MATE you are worth 92, and want 38; everybody wants 78
  until their own patience runs out, then 38
LAST PROPOSAL #60, 159 ago: YOU said no (you made them 30, wanted 38)
```

**成立には双方の同意が要る**ので、断ったのが相手とは限りません（上の例は**自分の側が断っています**）。読み方は、`you are worth`（＝魅力遺伝子 ×0.65 ＋ 体調 ×0.35。相手にはこれに相手の誤差が乗って見える）が相手の要求（比較中は78、我慢が尽きると38）に届いているか、そして自分の要求（`and want`）に相手が届いているか、の2つです。**吹き出しも `#12 turned me down` / `I turned #12 down` / `#12 and I both said no` を区別します**（2026-09-06 まではどちらの場合も「断られた」と出ていました）。

**求愛されたら、受けるかどうかを選べます**（2026-09-06）。相手が歩いてきて到着すると世界が止まり、こう出ます。

```
#12 IS PROPOSING - [y] accept  [n] refuse  (57 ticks, then it
  decides for itself)
  #12: male, 3 away, looks worth 71 to you
```

**`y` で受ける、`n` で断る。** **答えなくても構いません**——60tick（`CourtAnswerTicks`）待つと**そのノード自身の規則**が答えます（＝AIが操作していたときと同じ結果）。**待たされるのは求愛してきた側**で、その間その個体は立ったまま時間を払います。**この60tickだけが、操作しているノードがAIノードより世界の時間を余分に使う唯一の場所**です。

**自分から求愛するときは今までどおり `c`** です（相手の側の答えは、相手がAIなら相手の規則、相手も人が操作していれば相手の人が出します）。

**見えていない相手は狙えません。** 画面には世界じゅうが描かれていますが、ノードに見えているのは視界の中だけなので、外を指定すると `no: this node cannot see that` と断られます。**狙いを定めずに `e`・`a`・`f`・`o`・`c` を押したときも、選ばれるのは視界の中で一番近いもの**です（`c` だけは異性・未ペアに限る）。食料の点は小さくてクリックしづらいので、**近くにあるものを食べたいだけなら `e` を押すだけで構いません**。

パネルの `country: knows 10 of 12 regions ... / and reckons the going hereabouts is x2.00 / fears 6 place(s); reckons a tick here risks 0.003%` が、そのノードが**地面について覚えていること**です（段階15b/15c＝食料の豊かさ、段階29＝行きにくさ、段階35＝そこで死ぬ確率）。**足元の正確な値**（`ground here`）と違い、これは**地域についての信念**で、**行ったことがなく、誰かが溺れるのを見た者から聞いただけの場所**も混ざります。

パネルの `the ground here costs x3.0 to cross, and drowns it 0.02% of ticks` は**足元の地面**です（段階20・34）。**水の上にいる間だけ後半が出ます**——**先が川かどうかは出ません**（ノード自身にも見えないため）。

パネルの食料一覧の `#123  40 away  worth x0.94  mends 45` の `mends` は、**その肉を食べたらどれだけ体力が戻るか**です（段階39）。**肉のときだけ出ます**（植物は治しません）。**これも `Perception` の中身**なので、AIが同じものを見て同じ値で採点しています——**満身創痍のときは大きく、無傷のときは小さく見える**のは、治りが「足りないぶんまで」だからです。

パネルの `carrying 1 item(s)` は**そのノードが手に持っている食料の数**です（段階40。運搬のある世界でだけ出ます）。持っていると移動コストが上がるので、**画面では「持っている個体はやや遅い」**という形で見えます。手の中のものは**食料一覧に距離0で並びます**。

パネルの `IT KNOWS` 以下が、**そのノードが知っていること全部**です（`Perception` の中身そのもの）。相手の強さは**推定と不確かさ**で、真の値は出ません——AIが読めないものは人間にも見せない、というのがこの操作の唯一の設計上の約束です。

**親が生きている間でも `t` で子に移れます**（2026-09-06）。同じ選択肢が出て、`1`〜`5` で選ぶと**その子を操作し始め、置いていった身体は世界のAIに戻って自分の一生を続けます**（死にません）。`Enter` で「今のまま」。**血統は前に進めるもので、死ぬまで待つ列ではない**、というのがこの操作の趣旨です。

**死んだら子に乗り移ります。** `k` で後継を指名しておくと、操作中のノードが死んだときに同じコントローラがその子に付け替わります（画面では緑の輪が後継、金の輪が今の身体）。**指名していなくても、生きている子がいれば世界が止まって「誰として続けるか」を訊かれます**（`1`〜`5` で選ぶ、`Enter` でここまで＝血統の終わり）。**まだ成人していない子も候補に出ます**——`k` の指名は成人した子だけですが、死んだ瞬間の選択肢はそうではありません（生まれたばかりの子しかいない血統が、その子が画面に映ったまま「終わり」と言われるのを避けるため）。**継ぐ身体がどんな状態かはパネルに出ます**（`its child, still growing (23% grown, vit 18/40)`）。**命令は身体ごと**なので、継いだ子は白紙から始まります。狙っていた相手が消えたときも同じで、命令は `rest` に戻ります（`N order(s) lapsed` と出ます）。

**`m` は「そこまで歩いて止まる」です。** engine の `ActMove` は向きしか持たない（目的地という概念が無い）ので、**到着を見て止めているのは devview 側**です。engine に目的地を足していないのは、AIが目標を持つときは相手や食料そのものを指すので、素の座標を必要としないからです。歩いている途中にテンキーを押すか、別の命令を出すと解除されます。

### 1ノードを「訊かれて答える」形で遊ぶ（段階23）

ノードをクリックして `h` を**1回**押すと、そのノードは**自分で決めて動きつつ、転機のときだけあなたに訊いてきます**（`-ask` で最初からこれにできます）。**このモードにテンキーの操作はありません**（歩くのはノード自身です）——`h` をもう1回押すと手綱が渡ります。**AIが何を考えているかを読むモード**としてはよくできていますが、**転機は112tickに1回なので、遊んでいる時間のほとんどは見ているだけ**になります。

**AIは留守番ではありません。** そのノードを動かしているのは常に効用比較で、あなたが答えるのはそのうちの一部です。**誰も答えなければ、そのノードは普通のAIノードと1ビットも違わない生涯を送ります**（テストで固定してあります）。

**訊かれるのは「殴られた・狙いが消えた・配偶者を見つけた・破局した・体力が急に減った」の5つだけ**で、実測で **112 tick に1回＝一生で20〜30回**です（全部のトリガーで訊くと 14.5 tick に1回になり、`-slow` では0.6秒に1回になります）。**戦闘中は1戦につき1回**しか訊きません。

| キー / 操作 | 動作 |
| --- | --- |
| `h` | 動かし方を切り替える（AIだけ → 訊かれる → 自分で操縦する） |
| `1`〜`5` | **並んでいる選択肢に答える** |
| Enter | 質問が出ているとき＝**任せる**（そのノードが自分で選んだ手のまま進む）／出ていないとき＝**今すぐ訊く**（何を考えているか出させる） |
| クリック | ノードを選択して追跡（遊んでいる間もクリックの意味は変わりません） |
| `k` | 後継の子を指名する（成人した子だけ。押すたびに切り替わる） |
| `y` / `n` | **求愛されたときに受ける／断る**（答えなければ60tick後にノード自身の規則が答える） |
| `t` | **今すぐ子に移る**（親は死なず、世界のAIに戻る。成人前の子も選べる） |
| `1`〜`5` / Enter | 身体が死んだとき＝誰として血統を続けるか（`Enter` は続けない） |
| テンキー / 矢印 | **このモードでは歩けません**（ノードが自分で歩くため）。押すと `#58 walks itself in this mode - press h to take the reins` と出ます。自分で歩かせたいときは `h` で操縦モードへ |
| スペース / `-` `=` / → `n` | 一時停止・速度・1tick送り（いつもどおり） |

**質問が立つと世界は自動的に止まります。** 答えるか `Enter` を押すと再開します。**何を待っているかは画面上部にも出ます**（`waiting on you: attacked. answer 1-4 on the panel, or enter to leave it to itself`）——`[PAUSED]` だけだと、止まった世界とテンキーの無反応が「壊れた」と見分けられないためです。

**遊んでいるあいだ、右のパネルは常にゲームを映します。** 何も選択していなくても（地面をクリックした・`esc` を押した）操作中のノードのパネルが出ます。**以前は選択が外れるとパネルが `no node selected` に戻り、世界が止まっている理由＝答えるべき質問ごと隠れていました。**

```
YOUR LINE: 1 bod(ies), 775 ticks, 0 born, 0 of them alive
  no heir named (k). the line ends when this body does

LAST TIME you chose observe #42 e0.30, 330 ticks ago:
  vitality 69.1 -> 58.5 (-10.6)   hunger 53.3 -> 71.2 (+17.9)
  #42 is still alive
ASKED ON TICK 775: attacked
  [1] safest   observe #49 e0.30
      for   info 0.09x1.00=0.09  lore 9.00x1.00=9.00
      costs 0.0 vit over 10 ticks
  [2] soonest  move +0.6+0.8 e0.40
      for   explore 23.85x0.52=12.36
      costs 0.0 vit over 9 ticks
  [3] boldest  attack #49 e1.00
      for   life 26.11x1.00=26.11  rival 8.40x0.53=4.41
      costs 13.5 vit over 115 ticks
[enter] leave it to itself (it has already started)
```

読み方は4つ。

- **`YOUR LINE` ＝ あなたが遊んでいるもの。** ノードの効用式には「血統が続く」という項がありません（ノードは自分の一生で採点されます）。**これがプレーヤーだけが持っているもの**で、ノードの採点に反対する理由になります（「この手が最善なのは分かるが、自分は血統最後の一人だ」）
- **`LAST TIME` ＝ 前回の答えが何を買ったか。** 体力と空腹の増減、狙った相手や食料がどうなったか。**上の例は「一番安全」を選んで体力を10.6失い空腹が17.9進んだ**ところで、安全な手が良い手とは限らないことがそのまま出ます
- **選択肢は点数順ではありません。** 最大5つ出ます: **`a meal`（一番腹の足しになる食料）**、**`a child`（求愛）**、`safest`（払うものが一番少ない）、`soonest`（一番早く片がつく）、`boldest`（一番大きく賭ける）。**食べることと求愛だけが専用の枠**を持ちます——**血統を続けるのに要るのはこの2つ**なのに、効用式はどちらも「その個体1人の一生」に対して値付けするので、**満腹なら食事は安く、寿命が残っていれば求愛は安く**なります。**まさにそこがプレーヤーがAIに反対したい場面**なので、点数で競わせません。見えている食料が無い／求愛できないときは、その枠は出ません
- **合計スコアは出しません。** 出るのは「何のために」（目的×成功率）と「何を払うか」（体力・tick・過去にその相手に払わされた体力）だけです。**片方に「最善」と書いてある選択は選択ではない**ので、重み付けはプレーヤーがします。そのノード自身の順位が知りたければ `Enter`（任せる）がそれです

**古い質問には答えられません**（60tick）。止めずに走らせていて答え損ねたら、その質問は消えます。

**求愛（＝子を作る）には条件があります。** 満たしていないと `a child` の枠は出ません。パネルの `IT KNOWS` の中に**何が足りないか**が出ます:

```
CANNOT COURT: hunger 38.5 -> under 35; vitality 52.3 -> over 50.4
```

- **成人していること**（`Maturity >= 0.9`）
- **出産の代金を払っても生きていられること**（体力 > `BirthVitalityCost/2` ＝ 20）
- **出産直後のクールダウンが切れていること**
- 相手が**同種・異性・未ペア・最近断られていない・視界の中**にいること

**「腹が減っているから求愛しない」は条件ではなくなりました**（段階25）。求愛は**いつでも選択肢に出ます**が、**出産の代金（体力20）を効用に載せてある**ので、余裕のない身体では `a child` の行に `life -18.3x100%` のような**負の項**が並びます。**それを見て払うかどうかを決めるのはプレーヤーです。**

昔の挙動（腹が減っていると候補にすら出ない）に戻したいときは `CourtNeedsSurplus = true`。そのときだけ `ReproHunger`（35）と `ReproVitalityShare`（0.70）が効きます。

**転機を待たずに、こちらから訊けます。** 質問が出ていないときに `Enter` を押すと、そのノードは今の状況で全候補を採点し直して選択肢を出します（トリガー `requested`）。**転機はわざと稀にしてあるので、これが無いと転機の間にできることが「見ている」だけになります。**

**節目には「性格」を訊かれます。** 身体を取ったとき・成人したとき・ペアになったとき・子ができたときの4つで、そのノードが**何を求めるか**を選びます。

```
A MILESTONE: it has grown up
what it wants out of life, in 3.05 shares between three.
more care has to come out of the other two.
  [1] cautious          wary 1.83  rivalrous 0.61  fearful 0.61
  [2] quick-tempered    wary 0.61  rivalrous 1.83  fearful 0.61
  [3] clings to life    wary 0.61  rivalrous 0.61  fearful 1.83
  [4] as it was raised  wary 0.75  rivalrous 1.13  fearful 1.17
```

**合計（この例では 3.05）は親から継いだもので、変えられるのは配分だけです。** 用心深くするぶんは、競争心か命への執着から出すしかありません。数字は「世界の既定値の何倍か」で、上限は4倍です。`Enter` で「今のまま」にできます。

**節目のメニューは転機の質問より下に置かれます。** 両方立っているときに出るのは質問のほう（こちらは60tickで消えるため）で、節目は `(a milestone is waiting behind this)` と予告だけ出て、質問を片付けたあとに戻ってきます。

**死んだら子に乗り移ります。** `k` で後継を指名しておくと、同じコントローラがその子に付け替わります（緑の輪が後継、金の輪が今の身体）。**指名していなくても、生きている子がいれば世界が止まって「誰として続けるか」を訊かれます**（`1`〜`5` で選ぶ、`Enter` でここまで＝血統の終わり。まだ成人していない子も候補に出ます）。

```
#58 IS DEAD.

YOUR LINE: 2 bod(ies), 3410 ticks, 3 born, 2 alive

go on as one of them?
  [1] #612   its child, grown (100% grown, vit 41/58)
  [2] #703   its child, still growing (23% grown, vit 18/40)
  [enter] stop here: the line ends
```

### 1ノードを追うときの手順

1. `-slow` で起動するか、`-` を数回押して速度を落とす
2. 追いたいノードをクリック（`-follow` で最初から指定してもよい）
3. スペースで止め、`→` で1tickずつ進める
4. 行動が切り替わった瞬間に右パネルを読む。`[` で1つ前の決定に戻れる

追跡は指定したノードだけ記録されます（全ノードを常時記録すると重いため）。

## 世界を作る（マップエディタ・段階22）

**`F3` でエディタに入ります**（世界は止まります。もう一度 `F3` で戻り、止まっていなければ再開します）。**平坦な世界に入ると 16×12 の白紙の地図が敷かれます**（描くまでは何も変わりません）。

| キー / 操作 | 動作 |
| --- | --- |
| クリック | **その下に今のブラシを置く**（押しっぱなしで塗れます。カーソルの下のセル／地域が枠で示されます） |
| `1`〜`0` | ブラシを選ぶ: 平地／荒れ地／水／1段上げる／1段下げる／スロープ／**豊かにする**／痩せさせる／**隠れやすく**／露出させる |
| `tab` と `-` `=` | **調整するルールを選び、動かす**（1回で測定済み範囲の20分の1） |
| `d` | **難易度を切り替える**（`kind` / `measured` / `hard`） |
| `k` | **カーソルの位置に倉庫を置く／そこにある倉庫を取り除く**（段階50）。**倉庫は建てるものではなく地物**なので、置けるのはここだけです。**置いた直後は誰もその場所を知りません**（知られるのは4つの道＝見つける・継ぐ・使っているのを見る・発信を聞く、を通ってから）。**取り除くと中身は世界に残ります**（倉庫の中身は世界の食料なので、倉庫が消えてもその場に落ちているだけ）|
| `g` | **選んだノードを天才にする**（段階22 の残り／2026-09-08）。**天才の出生と同じ2つ**——**学んだことを置く枠を1つ増やし**（代金は**新しい予算**なので、遺伝子から黙って取りません）、**すでに持っているスキルを跳ね上げます**。**無いカテゴリは発明しません**し、**乱数を1つも引きません**（引くと編集が世界の次の一手を変えるため。空いた枠は誰かの思いつきが埋めます） |
| スペース / `→` | **1tickだけ進める**（変えた結果を見るため。エディタは世界を走らせません） |
| `F2` | 保存（段階21 の仕組みそのまま） |
| `z` | ズーム（**エディタに入ると自動で全体表示になり、出ると元の倍率に戻ります**——描けない倍率で描くことはできないし、戻ったときに自分のノードが隅の点になっていては困るので） |

**地形と地域は別の地図です。** 地形は**移動が何を要求するか**（セル単位）、地域は**世界が何をくれるか**（4×3ブロック）。**片方を塗ってももう片方は変わりません。**

**食料は「取り分」です。** ある地域を豊かにすると、**同じ総量のうち他の地域の取り分が減ります**（段階15a の原則）。エディタで食料を増やすことはできません。

**ルールは全部は出しません**（決定事項#50）。出るのは6つ（食料の湧き・予算・予算のばらつき・競争心・戦闘の見積もり長・突然変異率）で、**それぞれ「測定済みの範囲」を併記し、外れた値にすると `!! outside what was measured` と出ます**。**止めはしません**——動く世界を壊す自由はありますが、壊していることは知らせます。

**難易度は予算だけです**（`GeneBudgetMean` / `GeneBudgetStd`）。**測定用の既定（`measured`）と、遊ぶ用のプリセットを分けてあります**——難易度でルールを動かすと、`HISTORY.md` の数値が指す世界と遊んでいる世界が別物になるためです。

**速度に `headlong`（1フレーム64tick）を足しました。** **世界の時計と描画を切り離す**という段階22 の項目で、既存の速度切替の延長です（`server` の配信間引きはこの形になります）。

## 世界を保存する・読み込む（段階21）

**`F2` でその場の世界をファイルに書き出します**（`world-<tick>.json` と `nodes-<tick>.json` の2つ）。

```sh
go run ./cmd/devview -terrain country     # 遊ぶ／眺める。F2 で保存
go run ./cmd/devview -load world-8000.json   # その世界の続きから
go run ./cmd/devview -nodes nodes-8000.json  # 新しい世界に、その個体群だけを入れる
```

**2つのファイルは別のことに答えます。** `world-*.json` は「**この世界を、ここから先へ**」、`nodes-*.json` は「**この身体たちを、どこへでも**」。

- **世界のファイルには何もかも入ります**（`Config`・地形・地域・個体の記憶や信念・食料・乱数の位置・`tick`）。**読み込んだ世界は、保存しなかった世界と1ビットも違わずに進みます**（テストで固定）
- **個体群のファイルに入るのは「その身体が何であるか」だけ**です——遺伝子（＝予算）・性別・種族・好み・世界について信じていること・ヒント・体内時計。**入らないのは、他人の名前を含むもの全部**（記憶・血統・ペア・その世界の地域についての知識）。**別の世界では、その名前は誰も指していない**からです
- **読み込んだ世界は全ノードがAIで動きます。** 誰を操作していたかは世界の状態ではなくゲームの側の話なので（段階19 の線）、遊びたければ `h` で取り直してください

## ルール変更をA/Bで測る（cmd/experiment）

devview は「世界が破綻していないか」は見えますが、「このルール変更で知能への選択圧が +3 になったのか −2 になったのか」は目で見えません。それを測るヘッドレスのランナーです。

```bash
go run ./cmd/experiment -list                                   # 用意されている条件を見る
go run ./cmd/experiment -variants baseline,nogate               # 既定 12シード x 20000tick
go run ./cmd/experiment -variants baseline,nogate,gate20 -seeds 24 -ticks 60000
go run ./cmd/experiment -variants baseline,nogate -csv out.csv  # 推移をCSVに出す
```

| オプション | 意味 |
| --- | --- |
| `-variants a,b,c` | 比較する条件（`-list` で一覧）。既定 `baseline,nogate` |
| `-base <name>` | 差分の基準にする条件。既定は `-variants` の先頭 |
| `-seeds <n>` | 条件あたりのシード数（既定12） |
| `-seed0 <n>` | 最初のシード（既定1）。全条件が同じシード列を使う |
| `-ticks <n>` | 1回あたりのtick数（既定20000） |
| `-interval <n>` | サンプリング間隔（既定200tick） |
| `-csv <path>` | 推移の時系列をCSVで書き出す |
| `-jobs <n>` | 並列実行数（既定CPU数） |

出力は2つの表です。

- **per arm** — 条件ごとの平均 ± 標準誤差
- **paired difference** — 基準条件との差を**同じシードどうしで引き算**した平均 ± 標準誤差。シード間のばらつきは条件差よりずっと大きいので、対にして引かないと何も見えません。`*` は差が標準誤差の何倍か（`*`=1倍、`**`=2倍、`***`=3倍）の目安で、検定ではありません

読み方の例: `dIntelligence +4.52 +/-0.95 ***` は「その条件にすると、20000tickで平均知能の上がり幅が 4.52 大きくなる。標準誤差0.95なので向きは信用してよい」。

**個体数が違う条件どうしを比べるときは、`births` / `deaths` のような累計ではなく `birthRate` / `deathRate` のほうを読んでください。** 個体数が半分の世界は、1人あたりの率がまったく同じでも累計の出生数は半分になります。「累計が減った＝繁殖しなくなった」と読み違えた実例が `HISTORY.md` の 2026-09-02 の項にあります。

主な指標:

| 指標 | 意味 |
| --- | --- |
| `dPower` / `dRationality` / `dIntelligence` | 平均能力が開始時からどれだけ動いたか＝**その能力への選択圧**。能力値は最後の1tickではなく末尾2割の平均で読む |
| `budget` / `sdBudget` / `dBudget` | 遺伝子9本の合計＝**その個体が何でできているかの総量**の平均・標準偏差・初期値からの変化。予算は親から継ぐので、**放っておくと世代とともに上がる**（`dBudget` がそれ） |
| `shSpeed` の注意 | **速さは9本で一番買われている遺伝子**（0.14〜0.15）だが、**何とも取引していない**（「速くて脆い／遅くて頑丈」の並存が現れない）。食料レースの勝率に速さを入れても動かなかったので、残る仮説は「速さが有利な場所と不利な場所が無いこと」＝地形（`PLAN.md`） |
| `shAttack` 〜 `shLooks` | 予算に占める遺伝子ごとの割合（9本で合計1）。**条件間で比べるのはこちら**——生の遺伝子は予算が動くだけで動くので、「攻撃力が上がった」が「よく戦う集団になった」なのか「単に大きくなった」なのか区別できない |
| `geniuses` / `greatGeniuses` | 天才・大天才が起きた回数。**`*Years` より先にこちらを見ます**（下記） |
| `geniusYears` / `greatGeniusYears` | 天才・大天才が1回起きるまでの**年数**（`TicksPerYear` 換算）。**まれな事象なので、この平均は信用しないこと**——(a) 0回だった実行では実行長そのものが入るので「一度も起きなかった」と「実行長に一度」が区別できず、(b) シードごとの間隔をシード間で平均すると、1回しか起きなかったシードに引きずられて長く出ます。正しくは **`実行長 ÷ TicksPerYear ÷ 回数の平均`**（例: 60000tick・`TicksPerYear` 500・`geniuses` 10.83 なら 120年 ÷ 10.83 ＝ 11.1年）。また発生率は出生あたりの確率なので、**同じ設定でも個体数が増えると間隔は縮みます**（実測で20000tickなら33年、60000tickなら11年） |
| `sdPower` / `sdRationality` / `sdIntelligence` | 生きている個体の能力の**標準偏差＝選択圧が働く余地**。継承則が決める値で、平均（上の行）が「どちらへ押されているか」を言うのに対し、これは「まだどれだけ押せるか」を言う |
| `killShare` | 死因に占める「殺された」の割合。食料供給を振ってもほとんど動かないので、争いの多さを見るのに使いやすい |
| `clumping` | 同じ個体数を一様にばらまいた場合と比べて、どれだけ集まっているか。**相対値**で、1が一様という意味ではない（視界の円が世界の端で切れるぶん低めに出る）。条件間で比べる |
| `neighbours` / `nearest` | 平均的な個体の視界内にいる他個体数／最近傍までの距離 |
| `clusters` / `clusterSize` | 集団の数（2体以上の連結成分）と、その平均サイズ。連結の距離は 30（`engine.DefaultClusterLinkDist`）で固定。**距離が違う測定値どうしは比べられません** |
| `gap` / `gapP10` | **集団間の距離分布** — 各集団から最も近い別の集団までの距離（メンバー間の最短距離）の平均と下位1割。**連結距離30より短い値は原理的に出ません**（30以内なら同じ集団になるので）。`gapP10` が30に張り付いているなら、近い集団どうしは接触寸前 |
| `gapRel` | 上の平均を、同じ数の集団を無作為にばらまいた場合の期待値で割ったもの。**1が「構造なし」**（実測で0.98。`TestClusterGapsRelativeOfARandomLayout`）。1未満＝偶然より寄り集まっている、1超＝互いを避けている |
| `halfLife` | **membership half-life** — 同じクラスタにいた2体の組のうち半分が離れるまでのtick数。「集団」と「たまたま近くにいる塊」を区別する唯一の指標。片方が死んだ組は**離れたとは数えません**（在籍時間ではなく寿命を測ってしまうため） |
| `together` / `censored` | 500tick後もまだ一緒にいる組の割合／半減が窓（2000tick）の中で起きなかった実行の割合。`censored` が0でないなら `halfLife` は窓の端に張り付いた**下限値**なので、`together` のほうを比べます |
| `fightCompanion` / `fightStranger` | 遭遇100回あたりの戦闘数（%）。**遭遇＝`CombatRadius` 以内にいる組**で、`fightCompanion` は200tick前から同じクラスタにいた組、`fightStranger` はそうでない組 |
| `fightRatio` | 上の比（仲間 ÷ よそ者）。**1を下回るほど「集団の中では戦闘が少ない」。** 素直な「集団内戦闘率 ÷ 集団間戦闘率」が測れない理由は下記 |
| `species` | 最後の観測時点で生き残っている種族の数。**今は必ず1**（human だけ）。0なら絶滅 |
| `rareShare` / `rareTrough` / `rareSwing` | **種族ごとの個体数** — 一番少ない種族（今は human＝全体）の、直近5000tickの窓での「全体に占める割合」「窓の最小値 ÷ 平均（＝**振動の谷がどこまで下がるか**）」「(最大−最小) ÷ 平均（＝振動の大きさ）」。読むのは `rareTrough` のほうです。あるべき状態Aは**振動そのものは許す**ので、振れ幅の大きさは単独では何も言わず、**谷が0にどれだけ近づいたか**だけが「その種族が消えるか」を決めます。1に近いほど平ら、0なら絶滅 |
| `grouped` / `largestShare` | 2体以上の集団に属する個体の割合／最大の集団に属する割合。`largestShare` は他の3つの信頼性チェックで、1に近いなら世界が1つの塊につながっただけ（単連結は数珠つなぎになる）で、集団数は何も意味しません |
| `age` / `maturity` / `ageFactor` / `childShare` | 平均年齢（年）／平均成熟度／**遺伝的素質のうち今出せている割合**／未成年の割合。`ageFactor` が1を割っていれば、集団が若いか老いているかのどちらか |

| `kinds` / `kindMix` / `kindGap` / `kindHomed` | **外敵の種類の表が何を生んだか**（段階59）。**表の長さに依らない形で書いてある**ので、行を増やしても列は増えません。`kinds` は行数、**`kindMix` は湧きの内訳と表の差**（**底は標本**——1実行の到着は48体なので 1/√48 ≈ 0.07 より下がらない）、**`kindGap` は一番重い行と一番軽い行が生んだ身体の予算比**（1なら「名前だけ違う同じ生き物」）、`kindHomed` は各行の `Homing` で重みづけした「自分の土地にいる度合い」。**読むときは baseline ではなく「同じ中身を2行に分けただけ」の対照と比べること**——baseline と比べると `EnemySpread`（段階58）のぶんが混ざります |
| `prowlArrive` / `prowlGain` / `prowlKept` / `enemyBorn` / `enemyCrowd` / `prowlBite` | **外敵の湧きを地域に偏らせたときの、規則の効き目と世界に残る効き目**（段階58）。**`prowlArrive` は湧いた瞬間の偏り、`prowlGain` は今いる場所の偏り**で、**この2つを必ず並べて読むこと**——**規則が完璧に発火しても世界がそれを消すことがある**（実測: +0.25 \*\*\* に対し ±0.01＝**残るのは6%**）。**`prowlKept` はその比だが、分子がゼロ付近だと暴れる**ので補助にとどめる。`enemyBorn` は外敵のうち世界の中で生まれたものの割合（0.38〜0.41＝**湧きの重みが触れていないぶん**）、`enemyCrowd` は外敵の偏り（1が均等。**偏らせると下がる**＝既定で固まって見えるのは人間を追っているから）、`prowlBite` は地域ごとの「外敵の多さ」と「死因に占める殺しの割合」の相関 |
| `standGain` / `suitGain` / `suitCeiling` / `regionsSeen` / `oneRegion` / `regionShare` | **人間が立っている地面の「そこに立つと何がどれだけできるか」**の世界平均からの差（段階57）と、**一生に何地域を歩いたか**（`regionShare` はそれを地域数で割ったもの、`oneRegion` は1地域だけで終えた割合）。**既定の世界では `standGain` は必ず 0.00**（地面に差が無い）。**`regionsSeen` は既定で 6.28／12＝一生に世界の半分を歩く**ので、「居着かせる」規則の的はここにあります。**`RegionAbilitySpread` を入れても動きません**——理由は `HISTORY.md` 2026-09-12。**`suitGain` / `suitCeiling` は段階57c 用で、単位は％**（その身体の建て方に足元の地面がどれだけ合っているか／一番合う地域なら何％良かったか）。**必ず2つ並べて読むこと**——**`suitGain` 単独では「小さい」としか言えず、天井に対して何％取れたかで初めて意味を持ちます**（段階38 が畳んだ形） |
| `restShelter` / `shelterAll` / `shelterGain` | **休んでいる個体の下の地面の「休息の露出係数」**／集団全体の平均／その差（`shelterAll − restShelter`）。**係数は低いほど安全な地面**なので、`shelterGain` が正なら「良い場所で休んでいる」。**地域差の無い条件で 0.00 になることを確認してから読むこと**——最初の実装は「その瞬間に誰も休んでいない」を0として平均し、地域差ゼロの世界で 0.14 という嘘を出しました |
| `flees` / `escapeShare` | **逃走の試み**（1万のべ人-tickあたり）と、**そのうち追手が視界から消えて終わった割合**。段階13（視界のブロック化）の完了条件の指標。**面積を合わせて較正すると逃走成功率は動かない**（異方性は分散を増やすが平均をずらさない）ので、動くのは `killRate` のほう |
| `restNear` | **休んでいる個体の視界内にいる「好意の無い相手」の数**（休んでいる個体で平均）。`RestExposureWeight` が効いているかを見る指標。0にすると6.4、既定の0.05で2.0 |
| `birthRate` / `deathRate` / `killRate` / `starveRate` / `fightRate` | 同じ出来事を**1万のべ人-tickあたりの率**にしたもの（1のべ人-tick ＝ 1個体が1tick生きること。1万は「100体が100tick生きる」くらい）。窓は能力と同じ**末尾2割**。**個体数が違う条件を比べるときはこちらが本命**で、上の累計は水準なので比べられません。**両種族こみ**の率です（外敵も繁殖し死ぬが、地図の外から入ってくるぶんは出生に数えないので、人間だけの率が要るときは `noenemies` 条件で見る） |
| `drowned` / `drownShare` / `drownRate` / `onWater` | **溺死の数・死因に占める割合・率**（段階34）と、**水の上に立っている個体の割合**。地形の地図に水（`~`）が無ければ全部0。既定の `river` 条件で死因の11%、`onWater` は 0.14（＝地図に占める割合そのままで、**個体は水を避けない**） |
| `drownSeen` / `dangerRank` / `dangerKnown` | **溺死1件あたりの目撃者数**（既定の川で6.3人）、**「その地域は危ない」という信念と真値の相関**（1が完全）、**危険だと思っている地域の数**（段階35）。伝承を切ると相関が 0.77 → 0.33 に落ちるので、**知識を作っているのは目撃ではなく伝承**だと読める |
| `bankSplit` / `crossShare` / `crossIndex` | **世界の中央の線で割った両岸**（段階37）。少ないほうの岸が占める割合／視界に入っている組のうち**線をまたぐ組**の割合／それを「岸を無視して組にしたときの期待値」で割ったもの。**`crossIndex` を単独で読まないこと**——個体は地形と関係なく近くに集まるので**平坦な世界でも 0.17 しかありません**（`gapRel` と同じ性質）。**読むのは腕と対照の差**で、対照は**水の面積とコストを合わせた地図**（`ponds` / `pools`）を使います |
| `crossDry` | 上の `crossIndex` を、**水の上に立っている個体を除いて**数えたもの。**この世界の水は渡るものではなく住むもの**（1回の滞在が平均127tick）なので、川の真ん中の身体は両岸を同時に見ており、それを数えると「両岸は交流している」と読めてしまいます。**川で 0.01、幅を視界より広げると 0.00**（対照の池は 0.13〜0.18）＝**両岸はほとんど互いを見ていません** |
| `bankGeneGap` / `bankCountryGap` | **両岸の乖離**（段階37）。予算比のベクトルの全変動距離（0＝同じ配分、1＝共通の遺伝子なし）／同じ地域についての信念の差を信念の平均で割ったもの。**どちらも川で動きません**（+0.01 / −0.00）＝**視界が分かれても集団は分かれない** |
| `bankMoves` / `bankBoth` | **線をまたいだ回数**（1万のべ人-tickあたり）と、**一生のうち両岸に立った個体の割合**（`engine.BankTracker`）。**川があっても 0.53** で、池の対照（0.48）より**むしろ多い**。**渡るのに3倍かかり居座れば溺れる帯が、交通を1つも減らしていない**という、段階37 の答えそのもの。**またいで戻ってきた個体は数えない**ので下限値です |
| `killSeen` / `killLearned` / `avengeSeen` | **1件の殺害あたり、目撃者が取れる強さの観測の数**（既定 24.3）と、**そのうち実際に取り込まれた割合**（0.21）、**好意側の組の数**（2.0）。段階31。**`killLearned` が本命**——集団の95%は記憶が上限（`memFull`）なので、**ただで配られる情報の上限は重みではなく受け取り手の枠**です |
| `skillHeld` / `skillNominal` / `skillReal` | **スキルを持っている個体の割合／持っている名目の習熟度／その身体が実際に出せる値**（段階38a。既定オフなので地形の腕でのみ非ゼロ）。**名目と実効の差が「支えられない分」**（天井 = 適性遺伝子/100）。`roughskill` で 0.37 / 0.80 / 0.70 |
| `swimHeld` / `swimNominal` / `swimReal` | **3種類目のスキル（泳ぎ）**の保有率・名目・実効（段階38b）。**3つで唯一、狙った量を有意に動かしました**（溺死 −1.83 \*）——**打ち消す相手が死因の11%あったから**で、**効かない対照では動きません**。**それでも `onWater` は動きません** |
| `forageHeld` / `forageNominal` / `forageReal` | **2種類目のスキル（採取）**の保有率・名目・実効（段階38b）。**名目 0.55 に対し実効 0.18** ＝ 記憶の天井がはっきり効いています。**それでも `dietDiscount` はほとんど動きません**（+0.00 \*）——**打ち消す相手（飽きの割引）がそもそも5%**だからで、**スキルはそれが打ち消す規則の大きさ以上にはなりません** |
| `skillGap` | **荒れ地に立っている個体と平地の個体の、実効スキルの差**。正なら**上手い者が荒れ地にいる**（+0.05 \*\*\*）。**ただし `onDear` はほとんど動かない**ので、これは選別であって移住ではありません |
| `skillBornRate` / `skillCopyRate` / `skillLeaps` | **出生地から／観察から**スキルを得た回数（1万のべ人-tickあたり）と、**天才の跳躍の回数**（1実行）。**跳躍を切ると集団の名目値が出生地の値そのもの（ばらつきゼロ）に落ちます**——**跳躍が作り、模倣が配る** |
| `callShare` / `joinShare` | **「一緒に倒そう」と呼んだ決定の割合**と、**誰かが宣言済みの相手を殴ることにした決定の割合**（段階32。どちらも既定 0.01＝全決定の1%）。**群れ狩りが現れたかは `packSize` で見ますが、規則が発火しているかはここで見ます**——「動かないのは発火していないからか」を先に潰すため |
| `watchShare` | **全決定のうち `ActObserve`（誰かを観察する）が選ばれた割合**（既定 0.34）。#55 の完了条件——目撃がただで教えることで観察という選択肢が死んでいないかを見る指標。**重みを払った観察と同格にしても動きません**（`observe` は観測だけでなく**伝承の交換と「相手を選べること」**を買っているため） |
| `drawShare` | **全決定のうち「良いと思う地面へ行く」手が選ばれた割合**（既定 0.07＝14回に1回）。**地域についての信念（15b・29・35）が身体に届く唯一の扉**なので、その信念が何かをできる上限でもある |
| `starved` / `killed` / `aged` | 死因の内訳。**`drowned` を引いた残りが `starved`。** 合計が `deaths`。`aged` は寿命の残量が0まで達したケース（飢え・食べすぎ・長期の低体力が背景で削る）で、**既定では死因の約4%**。`brittlelifespan` 条件にすると15%まで上がるが、そこでは世界が壊れる |
| `extinct` | 絶滅した回数の割合。0でないなら他の数字は読む価値がない |

`fightRatio` の注意: **「集団間の戦闘」は書かれたとおりには測れません。** 打撃が届くのは `CombatRadius`（15）以内だけで、これはクラスタの連結距離（30）より短いので、殴り合っている2体は**その瞬間つねに同じクラスタにいます**（実測で20000tick中、クラスタ内5994・クラスタ間0）。そこで「同じ遭遇を、**200tick前から一緒にいた組（仲間）か、そうでない組（よそ者）か**で分ける」形にしてあります。どちらも遭遇あたりの率なので、仲間のほうが近くにいる回数が多いことだけで答えが決まることはありません。

新しい条件を試すときは `cmd/experiment/main.go` の `variants` に1項目足します（`engine` 側に分岐を作らず、`Config` を書き換える関数として書く）。両方の条件が同じバイナリに入っていないと、同じシードで対にして比べられません。

## 集団のようすを画像で残す（cmd/snapshot）

数値（`clusters` や `halfLife`）は「集団がいくつあるか」「半減期が何tickか」を言いますが、**その集団がどんな形をしているか**や**曲線がどんな形か**は言いません。`cmd/snapshot` は記録用の画像をPNGに描き出す、ヘッドレスの開発用ツールです。

```bash
# 世界の1瞬間（クラスタごとに色分け）
go run ./cmd/snapshot -seed 1 -ticks 50000 -out docs/images/clusters-<commit>.png

# membership の生存曲線（複数シードの平均）
go run ./cmd/snapshot -mode curve -seeds 8 -out docs/images/membership-<commit>.png

# 能力の分布（開始時の分布と重ねる。継承則を変えたときの比較用）
go run ./cmd/snapshot -mode genes -seeds 8 -ticks 20000 -out docs/images/genes-<commit>.png
```

| オプション | 既定値 | 意味 |
| --- | --- | --- |
| `-mode` | `world` | `world`＝世界の1瞬間、`curve`＝membership の生存曲線、`genes`＝能力の分布（灰＝開始時／青＝終了時） |
| `-seed` | 1 | 実行のシード（`world`） |
| `-seeds` | 8 | まとめるシード数（`curve` / `genes`。1〜この数を使う） |
| `-ticks` | 50000 | 描く前に進めるtick数 |
| `-link` | 30 | クラスタの連結距離（`engine.DefaultClusterLinkDist`） |
| `-scale` | 2 | 世界の1単位あたりの出力ピクセル数（`world`） |
| `-terrain` | （空） | 世界を地形の上に敷く（`world`）。`river` / `ponds` / `gorge` / `pools`（段階37 の4つ。`cmd/experiment` の同名の条件と同じ地図で、食料も遊ぶ世界と同じく地面に結びつけます） |
| `-commit` | （空） | 画像に焼き込むコミット。省略すると現在のHEADを `git` から読む（作業ツリーが汚れていれば `-dirty` が付く） |
| `-out` | `snapshot.png` | 出力先 |

`-mode world` の画像の読み方:

- **同じクラスタの個体は同じ色**で、その間に細い線が引かれます。**色は使い回されるので、離れた別のクラスタが同じ色になることがあります** — 何が1つの集団かを決めているのは線であって色ではありません
- **灰色の点は singleton**（連結距離の中に誰もいない個体）。1体は集団ではないので色を与えていません
- 薄い緑の点は食料
- `-terrain` を渡すと**水が薄い青**で、**両岸を数える線**（世界の中央）が細い縦線で入ります。**帯には両岸の割合と遭遇率（`crossIndex` と `crossDry`）も出ます**——`clusters` が「塊がいくつか」しか言えないのに対し、川沿いの集まりは**塊ではなく帯**なので、絵と両岸の数字を並べないと読めません（段階37）
- 下の帯に seed / tick / 連結距離 / 個体数 / クラスタ数 / 平均サイズ / 集団に属する割合 / 最大成分の割合 / **コミット** が入ります。画像がリポジトリの外に出ても、どの条件のどのコミットのものか分かるようにするためです

`-mode curve` の画像の読み方:

- 横軸は**ラグ（tick、対数）**、縦軸は「その時点でまだ同じクラスタにいる組の割合」。半減期が60tick付近なのに末尾が2000tickまで伸びるので、対数軸でないと片方が潰れます
- **薄い線が各シード、濃い線がその平均。** 平均だけを見て「どの実行でもこうなる」と読まないため
- 赤い破線が平均の半減期。**片方が死んだ組は「離れた」と数えていません**（在籍時間ではなく寿命を測ってしまうため）
- 曲線が対数軸で直線にならない＝**単一の指数関数ではない**ことがこの絵の要点です。速い成分（すれ違い）と遅い成分が混ざっています

どちらのモードも、同じオプションなら常に同じ画像になります（`engine` が決定的なので）。`-link` を振ると、連結距離という「目盛り」を変えたときに見え方がどう変わるかを比べられます（値の決め方は `HISTORY.md` の 2026-08-31 の項）。
