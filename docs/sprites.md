# 絵の頼み方と、シートの作り方

**この文書は、画像生成（Sora）に身体の絵を頼むときの指示と、返ってきた1枚を `cmd/devview` が読むシートに変える手順です。** 2026-09-21 に人間の絵が生成物に替わったときに作りました。

**ここに書くのは「今どう頼むか」だけです。** どう転んだか・何を測ったかは `HISTORY.md`、絵がどう描かれるかのルールは `docs/features/game.md`、灰色の置き絵を描くツールは `cmd/tiles`。

## 1. なぜ指示がこの形なのか（3つの測定）

**生成器は「ドット絵」ではなく「ドット絵の絵」を返します。** 最初の1枚は 1312×1199 で **213,696 色**、同じ行も同じ列も1つも繰り返しがなく、1ドットの実寸は **約 3.7px の非整数**でした。**だからドット数を指定しても無駄で、大きく描いてもらって縮小するしかありません。** 以下の3つは、そのうえで指示が守らなければならないことです。

**① 同じ画像の中なら縮尺が揃う。別画像にすると揃わない。**

| | 高さのばらつき |
|---|---|
| 同一行の中（髪色8種の頭） | 61〜62px = **±1.6%** |
| 同一行の中の A/B フレーム | **完全一致**（118/118、104/104、459/459） |
| 画像・パネルをまたぐ | 118 / 104 / 102 = **最大12%差** |

→ **揃っていてほしいものは必ず1枚の中に入れる。** アニメの2コマも、男女の対比も、髪色の並びも。

**② 白背景は使えない。** 白髪の頭を数えたら **3520画素中1919画素**が「ほぼ白」でした。白背景で抜くと白髪と白肌が背景ごと消えます。→ **背景は `#FF00FF`（マゼンタ）。**

**③ 髪と肌は後から色を変えられない。** 色相を数えたら茶髪（hue 20〜30）と肌（hue 25〜35）が**完全に重なっていました**。「1体だけ描いてもらって変換側で髪色8種を作る」は不可能です。→ **髪色のバリエーションは描いてもらうしかない。**（服は青 hue 200〜219 とピンク hue 340〜359 で分離できるので、こちらは変換側でもできます。）

## 2. 共通ルール（毎回、指示の頭に付ける）

```
以下のルールを厳守してください。

- 背景は #FF00FF（純粋なマゼンタ）のべた塗り。影・グラデーション・
  枠・地面・装飾を一切描かない。
- 画像の中に文字・ラベル・番号・タイトル・枠線・パネルを描かない。
- 横長の画像に、1行 = 1種類の動作として並べる。
- 各行のいちばん左に「基準キャラクター」を1体だけ描く。これは
  アニメーションのコマではなく、大きさを揃えるための基準です。
  基準キャラクターは全行で同一の成人男性とし、その行の内容
  （子供・老人・倒れている など）に合わせて変えてはいけない。
- 2コマのアニメーションは必ず横に隣り合わせで並べ、組と組のあいだは
  組の中より広くあける。
- 全員の足の裏を同じ高さ（同じ水平線上）に揃える。
- 出力は PNG。シャープネス処理や後処理をかけない。
- 32×32ドットのドット絵として読める粗さで描く。
```

**「文字を入れるな」がいちばん効きます。** 最初に届いた1枚は日本語のラベルと枠つきの仕様書で、それが素材にならなかった最大の理由でした。

**「基準キャラクターを行の内容に合わせて変えるな」は2回とも守られませんでした。** 1枚目は10行中2行、2枚目は11行中3行で、基準が白いオムツの子供として描かれています。**守られないものとして扱い、変換器は基準を「割り算の分母」ではなく「ドリフト検出器」として使います**（第4節）。

## 3. 人間のシート（2026-09-21 に実際に頼んだ形）

**1行1動作、各行に3組×2コマ。** 男性の組・男性の組・女性の組の順（真ん中の組は予備）。

| 行 | 内容 |
|---|---|
| 1 | **立ち**（直立と、呼吸で上下しただけの2コマ） |
| 2 | **歩行**（**片脚を前に大きく踏み出し、もう片脚を後ろに残す。2コマで左右の脚を入れ替える**） |
| 3 | **食事**（しゃがんで食べ物を口に運ぶ） |
| 4 | **攻撃**（腕を突き出す。当たった線を添える） |
| 5 | **被弾**（腕を上げてかばう。目を閉じ、赤い衝撃を添える） |
| 6 | **水中**（腰まで水に入っている） |
| 7 | **死亡**（倒れている） |
| 8 | **子供**（男の子・女の子） |
| 9 | **老人**（老人・老婆） |
| 10 | **髪色**（黒・金・赤・白・青・緑・ピンクを横一列。髪型・肌・目・服・身長は全体で同一） |
| 11 | **アイテム**8個（草・魚・肉・石・コイン・本・飾りの首飾り・毛皮） |

**歩行の括弧の中は必ず書いてください。** 1回目は「歩行」とだけ頼んだら**立ちと区別のつかない絵**が返ってきました（コマ間の差が89画素に対して立ちとの差が101〜181画素＝ポーズが変わっていない）。脚の動きを明示した2回目は、コマ間214画素・立ちとの差347画素で通っています。

**2枚目以降は1枚目を参照画像として毎回添付してください。** 同じキャラであり続けさせるためです。

## 4. 変換（`tiled/tools/pack_sprites.py`）

```
go run ./cmd/tiles -out /tmp/grey
python3 tiled/tools/pack_sprites.py tiled/samples/<sheet>.png cmd/devview/assets --carry /tmp/grey
```

1行目が**灰色の置き絵**（外敵。まだ描いてもらっていないもの）を出し、2行目が**生成シートから人間と物を切り出して1枚にまとめ**、`--carry` で置き絵のうち自分が作らなかったクリップを引き継ぎます。**外敵のクリップは16px のまま同じシートに入り**（クリップは自分の `w`/`h` を持つ）、**画面上では同じ大きさに描かれます**。

`--dump` を付けると**行と体の数と高さだけを出して止まります**。**新しいシートが届いたら必ず最初にこれを回し**、`pack_sprites.py` の `PICKS`（どの行のどの体がどのクリップか、と各行の立ち高さ）を突き合わせてください。**`PICKS` はそのシートのものです**——生成のたびに行も縮尺も変わります。

変換器がやっていることは3つだけです。**色相で背景を抜く**（明度で抜くと白髪が消える＝1節②）。**クリップのコマは必ずまとめて縮小する**（別々に正規化すると、459と460の1px差が「呼吸すると体が伸び縮みする」に化ける）。**地面に立っているクリップは、それぞれを同じ高さに正規化する**。

3つ目の理由は測定です。2枚目のシートでは、同じ体が**立ち90・歩き83・攻撃81・被弾79** と**戦闘中に12%縮み**、いっぽう**頭の幅は52→56 と太って**いました。**単純な縮尺ずれではなく、行が進むほどチビ寄りになる画風のドリフト**で、頭に合わせると胴の縮みが増幅され、身長に合わせると頭が揃いません。**身長側に寄せます**——地面と他の体に対して目が比べるのは身長のほうだからです。**しゃがむ・水に入る・子供・倒れる**は高さが言いたいことそのものなので、正規化せず立ちに対する比を保ちます。

## 5. まだ頼んでいないもの — 外敵

**外敵の絵は1枚もありません。** `cmd/devview` は `enemy.idle` / `enemy.walk` / `enemy.eat` / `enemy.fight` を引くので、今はそこだけ `cmd/tiles` の灰色の置き絵が出ています（色は性別と個体ごとのゆらぎで付きます）。

外敵は**人間とまったく同じ `Agent`・同じ遺伝子・同じ意思決定**で動き、違うのは**予算の抽選範囲**（外敵のほうが大きい）と**食性**（肉のみ）だけです。**種類（`EnemyKinds`）は種ではなくタグ**で、種類どうしは交配します。だから**絵も「4種の別の生き物」ではなく「同じ獣の見た目違い」**として頼むのが、世界の側と食い違いません。

見本の地図（`tiled/samples/001_3division.tmj`）が名前で呼んでいるのは4種類です。

| 名前 | 世界の側の事実 | 絵に要るもの |
|---|---|---|
| `brute` | 予算が大きい（平均700）。危険な土地に寄る | **大きく重い。**人間の1.5倍の背丈 |
| `stray` | 予算が小さい（平均380）。どこにでも湧く | **小さく痩せている。**人間と同じくらい |
| `flyer` | 予算が小さい（260）。**飛ぶ**。食べるときと殴るときだけ降りる | **翼。**地上にいる絵と**空にいる絵**の2つ（空にいる身体は浮かせて描かれ、地面に影が残ります） |
| `lurker` | 水から湧き、水で溺れない | **水生。**腰から下が水に隠れていてよい |

頼むときの指示（第2節の共通ルールに続けて）:

```
四足の獣を、横長の画像に1行 = 1種類の動作として並べてください。
各行のいちばん左に基準キャラクター（成人男性の人間、直立、
上半身裸に青い短パン、茶髪）を1体だけ描いてください。獣の
大きさはこの人間と比べて読めるようにします。

行1: 立ち（2コマ）
行2: 歩行（脚を大きく踏み出し、2コマで前後を入れ替える）
行3: 食事（地面の肉に顔を下げて食べる。2コマ）
行4: 攻撃（前脚を振り上げて飛びかかる。2コマ）

各行に3組、左から順に:
  組1 = 大型（人間の1.5倍の背丈。重く、毛が厚い）
  組2 = 小型（人間と同じくらい。痩せて素早い）
  組3 = 水生（腰から下が水に隠れている。ぬめった肌）

すべて同じ種類の獣の見た目違いとして描き、まったく別の生き物には
しないでください。
```

**獣と一緒に、物の絵を1つ頼んでください**——**人の遺体（骨）**です。**engine は肉が誰の種族から来たかを覚えていて**（`Food.From`。自分の種族の肉は食べられない）、**外敵の肉と人の遺体は別のものです**。今は `cmd/tiles` の灰色の置き絵（`remains`）が出ています。

```
横長の画像に、地面に落ちている物のアイコンを1つ描いてください。
人の遺体を表す、白い骨が2〜3本重なったもの。
32×32ドットのドット絵として読める粗さで描く。
生々しい表現（血・肉片）は避け、記号としての骨にしてください。
```

**飛ぶものは別の1枚にしてください**（地上と空中で高さが変わるので、同じ行に混ぜると正規化の基準が壊れます）。

**外敵が届いたら `PICKS` に `enemy.*` を足し**、`--carry` から落ちるのを確かめてください（`--carry` は自分が作らなかったクリップだけを引き継ぐので、作った時点で置き絵は自動的に使われなくなります）。

## 6. これまでに起きた失敗（同じ穴を2度踏まないために）

| 起きたこと | どう扱ったか |
|---|---|
| ラベル・枠・パネルつきの仕様書が返ってきた | 共通ルールに「文字を描かない」を入れた |
| 基準キャラクターが行の内容に合わせて小さく描かれた（2回とも） | **諦めた。**基準は検出器として使い、縮尺は一致している行から取る |
| 「歩行」が立ちと区別できなかった | 脚の動きを指示に明示した |
| 女性の組の中に青い短パンの男性が1体混ざった | その組を使わず隣の組から取った |
| 1体だけ髪が黒くなった（基準は茶髪） | その体を使わず隣から取った |
| 倒れた体が34〜38px幅で32pxのタイルに入らない | 幅で合わせて11%縮めた（倒れた体の大きさは何も読ませていない） |
| 老婆が成人より背が高く出た（92 対 90） | 老人も立っているものとして正規化した。**老いは白髪と禿頭が言っている** |
| 「水中」の1組が水に入っていなかった | その組を使わなかった |
