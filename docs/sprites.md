# 絵の頼み方と、シートの作り方

**この文書は、画像生成（Sora）に身体の絵を頼むときの指示と、返ってきた1枚を `cmd/devview` が読むシートに変える手順です。** 2026-09-21 に人間の絵が生成物に替わったときに作りました。

**ここに書くのは「今どう頼むか」だけです。** どう転んだか・何を測ったかは `HISTORY.md`、絵がどう描かれるかのルールは `docs/features/game.md`、灰色の置き絵を描くツールは `cmd/tiles`。

## 1. なぜ指示がこの形なのか（3つの測定）

**生成器は「ドット絵」ではなく「ドット絵の絵」を返します。** 最初の1枚は 1312×1199 で **213,696 色**、同じ行も同じ列も1つも繰り返しがなく、1ドットの実寸は **約 3.7px の非整数**でした。**だからドット数を指定しても無駄で、大きく描いてもらって縮小するしかありません。** 以下の3つは、そのうえで指示が守らなければならないことです。

**① 同じ画像の中なら縮尺が揃う。別画像にすると揃わない。**

| | 高さのばらつき |
|---|---|
| 同一行の中（髪色8種の頭） | 61〜62px = **±1.6%** |
| 同一行の中の A/B フレーム | **完全一致**（118/118、104/104、459/459） |
| 画像・パネルをまたぐ | 118 / 104 / 102 = **最大12%差** |

→ **揃っていてほしいものは必ず1枚の中に入れる。** アニメの2コマも、男女の対比も、髪色の並びも。

**② 白背景は使えない。** 白髪の頭を数えたら **3520画素中1919画素**が「ほぼ白」でした。白背景で抜くと白髪と白肌が背景ごと消えます。→ **背景は `#FF00FF`（マゼンタ）。**

**③ 髪と肌は後から色を変えられない。** 色相を数えたら茶髪（hue 20〜30）と肌（hue 25〜35）が**完全に重なっていました**。「1体だけ描いてもらって変換側で髪色8種を作る」は不可能です。→ **髪色のバリエーションは描いてもらうしかない。**（服は青 hue 200〜219 とピンク hue 340〜359 で分離できるので、こちらは変換側でもできます。）

## 2. 共通ルール（毎回、指示の頭に付ける）

```
以下のルールを厳守してください。

- 背景は #FF00FF（純粋なマゼンタ）のべた塗り。影・グラデーション・
  枠・地面・装飾を一切描かない。
- 画像の中に文字・ラベル・番号・タイトル・枠線・パネルを描かない。
- 横長の画像に、1行 = 1種類の動作として並べる。
- 各行のいちばん左に「基準キャラクター」を1体だけ描く。これは
  アニメーションのコマではなく、大きさを揃えるための基準です。
  基準キャラクターは全行で同一の成人男性とし、その行の内容
  （子供・老人・倒れている など）に合わせて変えてはいけない。
- 2コマのアニメーションは必ず横に隣り合わせで並べ、組と組のあいだは
  組の中より広くあける。
- 全員の足の裏を同じ高さ（同じ水平線上）に揃える。
- 出力は PNG。シャープネス処理や後処理をかけない。
- 32×32ドットのドット絵として読める粗さで描く。
```

**「文字を入れるな」がいちばん効きます。** 最初に届いた1枚は日本語のラベルと枠つきの仕様書で、それが素材にならなかった最大の理由でした。

**「基準キャラクターを行の内容に合わせて変えるな」は2回とも守られませんでした。** 1枚目は10行中2行、2枚目は11行中3行で、基準が白いオムツの子供として描かれています。**守られないものとして扱い、変換器は基準を「割り算の分母」ではなく「ドリフト検出器」として使います**（第4節）。

## 3. 人間のシート（2026-09-21 に実際に頼んだ形）

**1行1動作、各行に3組×2コマ。** 男性の組・男性の組・女性の組の順（真ん中の組は予備）。

| 行 | 内容 |
|---|---|
| 1 | **立ち**（直立と、呼吸で上下しただけの2コマ） |
| 2 | **歩行**（**片脚を前に大きく踏み出し、もう片脚を後ろに残す。2コマで左右の脚を入れ替える**） |
| 3 | **食事**（しゃがんで食べ物を口に運ぶ） |
| 4 | **攻撃**（腕を突き出す。当たった線を添える） |
| 5 | **被弾**（腕を上げてかばう。目を閉じ、赤い衝撃を添える） |
| 6 | **水中**（腰まで水に入っている） |
| 7 | **死亡**（倒れている） |
| 8 | **子供**（男の子・女の子） |
| 9 | **老人**（老人・老婆） |
| 10 | **髪色**（黒・金・赤・白・青・緑・ピンクを横一列。髪型・肌・目・服・身長は全体で同一） |
| 11 | **アイテム**8個（草・魚・肉・石・コイン・本・飾りの首飾り・毛皮） |

**歩行の括弧の中は必ず書いてください。** 1回目は「歩行」とだけ頼んだら**立ちと区別のつかない絵**が返ってきました（コマ間の差が89画素に対して立ちとの差が101〜181画素＝ポーズが変わっていない）。脚の動きを明示した2回目は、コマ間214画素・立ちとの差347画素で通っています。

**2枚目以降は1枚目を参照画像として毎回添付してください。** 同じキャラであり続けさせるためです。

## 4. 変換（`tiled/tools/pack_sprites.py`）

```
python3 tiled/tools/pack_sprites.py tiled/samples/10humans_new.png /tmp/step1 --layout humans
python3 tiled/tools/pack_sprites.py tiled/samples/enemies.png /tmp/step2 --layout enemies --carry /tmp/step1
python3 tiled/tools/pack_sprites.py tiled/samples/elder_children.png cmd/devview/assets/set2 --layout children --carry /tmp/step2
```

**最後の行き先が「絵のセット」です**（2026-09-22。次の節）。**地面は身体とは別の道を通ります**（`--layout terrain` / `water`。9節）。

**シート1枚につき1回回し、`--carry` で前の結果を持ち越します。** `--carry` は**自分が作らなかったクリップだけ**を引き継ぐので、**同じ名前の絵を新しく作れば古いほうは自動的に落ちます**（外敵の灰色の置き絵はこうして消えました）。

`--layout` は**そのシートに何が入っているかを言う表**で、`pack_sprites.py` の中に `humans` と `enemies` があります。`--dump` を付けると**行と体の数と大きさだけを出して止まります**。**新しいシートが届いたら必ず最初にこれを回し**、表と突き合わせてください。**表はそのシートのものです**——生成のたびに行も縮尺も変わります。

**縮尺の取り方は2つあり、被写体の形で決まります。** **人は縦に長く地面に立つ**ので、クリップどうしで揃えるべきは**身長**です（戦闘中に身体が1割縮むのは、ドリフトの中で唯一見逃せない崩れ方）。**獣は横に長く、しかも画面上の大きさは絵から来ません**——ビューアは**予算から大きさを読む**（`bodySize`）ので、**大型が大きく描かれるのは大型だからです**。**絵の側でも人の1.5倍にすると同じ事実を二度数えます。** だから獣は**体格ごとに1つの縮尺**（その体格の一番幅広いコマから取る）で、**タイルを同じだけ埋める**ように揃えます。

変換器がやっていることは4つだけです。**色相で背景を抜く**（明度で抜くと白髪が消える＝1節②）。**クリップのコマは必ずまとめて縮小する**（別々に正規化すると、459と460の1px差が「呼吸すると体が伸び縮みする」に化ける）。**地面に立っているクリップは、それぞれを同じ高さに正規化する**。**タイルからはみ出したときも、まとめて縮める**（2026-09-22。下）。

**4つ目は3枚目のシートが強いたものです。** 32px のタイルは正方形で、**倒れた身体はそこに収まりません**（立った身体が30のとき幅34〜38）。それまでは**コマごとに幅で縮めていた**ので、**コマ1が14px・コマ2が15px の死体**ができていました——「まとめて縮小する」と書いてあるのに、幅だけが例外だったということです。**今は幅の超過も全コマで測って、クリップごと同じだけ縮めます。**

**そのとき「身体の幅」と「絵の幅」を分けます。** 殴った線・当たった赤は絵の一部で、**取り込みのときに身体へ糊付けしてあります**（別々にすると行の中の体の数が合わなくなる）。**3枚目のシートでは、この線が身体の幅の倍近く飛びます**（身体68に対して絵130）。**これをタイルに合わせると、身体のほうが縮みます**——**老人が殴るときだけ1割小さくなる**、というのが実際に出た絵でした。**だから幅を測るのは「いちばん大きな塊」だけ**（糊付け前の連結成分で取る）で、**そこからはみ出した線はタイルの縁で切れます**。**線の先が2px切れていることは目が比べる相手を持たず、身体が1割縮むことは持ちます。**

3つ目の理由は測定です。2枚目のシートでは、同じ体が**立ち90・歩き83・攻撃81・被弾79** と**戦闘中に12%縮み**、いっぽう**頭の幅は52→56 と太って**いました。**単純な縮尺ずれではなく、行が進むほどチビ寄りになる画風のドリフト**で、頭に合わせると胴の縮みが増幅され、身長に合わせると頭が揃いません。**身長側に寄せます**——地面と他の体に対して目が比べるのは身長のほうだからです。**しゃがむ・水に入る・子供・倒れる**は高さが言いたいことそのものなので、正規化せず立ちに対する比を保ちます。

## 4-2. 絵のセット（2026-09-22）

**絵は全部描き直すことがあるので、古いものを残したまま並べて置けるようにしました。** **1セット = `cmd/devview/assets/<名前>/` の1ディレクトリ**（シート1枚と manifest）。

| | |
|---|---|
| 一覧と既定 | **`cmd/devview/assets/sets.json`**。**名前と「それが何か」を1行**。**手で書きます**——絵を見ても、その日に何を変えたかは分かりません |
| 選ぶ | **`cmd/devview -art <名前>`**、または**走らせたまま F4**（次のセットへ。最後まで行くと先頭に戻る） |
| 今あるもの | **`set1`**（子供と老人が立ち姿だけだった頃）と **`set2`**（6ポーズ入り。既定） |
| ネイティブ | **全セットを実行ファイルに埋め込みます**（1セット数百kB。持ち歩く代金より「見比べられない」ほうが高い） |
| ブラウザ | **選ばれたセットだけ `fetch` します**（名前がそのままディレクトリなので、要らないセットは回線を1バイトも使いません） |

**新しいセットの入れ方**: `pack_sprites.py` の最後の行き先を `cmd/devview/assets/<新しい名前>` にして、`sets.json` に1行足すだけです（**既定にするなら `"default"` も**）。**`sets.json` に書き忘れるとテストが落ちます**（`assets/` の中身と突き合わせています）。

**既存のセットは `--carry` の相手にできます。** **シートを半分だけ描き直したときは、前のセットを持ち越せば、描き直していない半分がそのまま入ります**:

```sh
python3 tiled/tools/pack_sprites.py tiled/samples/<新しい人間>.png cmd/devview/assets/set3 \
    --layout humans --carry cmd/devview/assets/set2
```

### 何が足りないかは `-artgaps` が言う

**絵を頼む前に、まずこれを回してください。**

```sh
go run ./cmd/devview -artgaps
```

**セットごとに3つ出ます。**

| | |
|---|---|
| `missing` | **ビューアが訊くのに、そのセットに無い絵**と、**代わりに何で描いているか**。**一覧は誰も書いていません**——`clipFor` に全組み合わせを訊いて作るので、**規則が新しい絵を訊き始めた日から自動で数に入ります** |
| `wrong` | **ある**のに測ると間違っている絵。**今は2つ測っています**——**歩きの2コマが、同じ身体の立ち姿より動いていない**（＝脚が見えていない。**目盛りは同じセットの同じ身体**で、外から持ってきた数字ではありません）と、**立っているはずのポーズ（歩き・攻撃・被弾）の背丈が立ち姿と5%以上違う**（**獣は除きます**——獣はタイルを幅で埋めるので、ポーズごとに背丈が違うのが正しい） |
| 最後の段 | **どのセットにも無いので、ビューアが訊きもしないもの**（獣の被弾・髪の2層）。**これだけは手で書いた一覧**です——**無いものをビューアは訊かないので、機械には見つけられません**。**届くとテストが「その行を消せ」と言います** |

**2026-09-22 時点で `wrong` が言っていること**: **女性側の歩きが3つとも弱い**（`human.f.walk` / `child.f.walk` / `old.f.walk`。2コマの差が立ち姿の差以下）と、**獣4体格の歩きも弱い**。**次の依頼文には「スカートの裾から脚が見えるように」と「四つ足の脚がはっきり動くように」を足してください。**

### 欠けた絵は穴にならない

**古いセットは、今のコードが訊く絵を全部は持っていません**（`set1` には歩く子供がいない）。**そのときは一番近いものを描きます**。**諦める順は 年齢 → 性別 → ポーズ**で、**ポーズが最後**です:

- **ポーズは、隣の身体と見比べられる唯一の部分です。** 大人が歩いている横で子供だけ立ち姿のまま地面を滑ると、**「子供」ではなく「壊れた絵」に見えます**
- **年齢を先に諦めても嘘になりません。** **身体を小さく描くのはビューアの仕事**（`AgeFactor`）なので、**大人の絵を小さく描いた子供**は 2026-09-22 より前の世界そのものです
- **性別はその次**（服の色を失う）。**ポーズの絵が1つも無いときだけ立ち姿に落ち**、そのときは**そのセットが持っている一番細かい身体**を使います
- **獣は体格だけは諦めません。** 重い獣を水生の絵で描くのは**どの型かを偽る**ことで、それはこの画面が唯一間違えてはいけないことです

## 5. 外敵と骨（2026-09-22 に入った）

**依頼文は下に残してあります**（次に獣を頼むときの雛形。3回目にして**基準キャラクターが全行で人間のまま**返ってきました——122〜124px の±1.6%）。

届いたのは7行で、**頼んだ「被弾」の行だけが返ってきませんでした**。何も困りません——`clipFor` は外敵の被弾を引かないので、**もともと後のための予備**でした。

| 行 | 中身 | 使われ方 |
|---|---|---|
| 1〜4 | 立ち・歩行・食事・攻撃、各4体格×2コマ | **`enemy.<体格>.idle/walk/eat/fight`** |
| 5 | 死亡、4体格×2コマ | シートに眠っている |
| 6 | 飛行の空中（滑空・羽ばたき） | **`enemy.fly.air` / `enemy.fly.flap`**（浮いているときに出る） |
| 7 | 骨1つ | **`remains`**（置き絵を置き換えた） |

**これで灰色の置き絵は1つも残っていません。** `cmd/tiles` は次に誰も描いていないものが出たときのために残してあります。

### 体格はどう選ばれるか

**`clipFor` → `enemyBuild` が、地図が何と名付けたかではなく、世界がその型を何だと言っているかで選びます**（決定#133: 名前と場所は地図が、何であるかは行が持つ）。

| 条件 | 絵 |
|---|---|
| `Flies` | `fly` |
| `Water` | `water` |
| `BudgetMean` が世界の `EnemyBudgetMean` より大きい | `big` |
| それ以外（`BudgetMean` 未指定を含む） | `small` |

**大きさはここに入っていません。** ビューアは**予算から大きさを読む**ので、4体格は**タイルを同じだけ埋めて**描かれ、差は予算が作ります。**地図が重い獣を別の名前で呼んでも重い絵になり**、**表に無い型の身体が来ても穴ではなく `small` になります**（テストで固定）。

### 世界の側の事実（絵と食い違わせないために）

- **外敵は人間とまったく同じ `Agent`**で、同じ遺伝子・同じ意思決定で動きます。違うのは**予算の抽選範囲**と**食性**（肉のみ）の2点だけ

## 9. 地形（2026-09-22 に入った）

**身体ではなく地面のシートです。** 届いたのは **`mononoke.png`**（793×1983、10行30枚）と、**水だけを描き直した `water.png`**（1672×941、1行4枚）。**世界観は「もののけ姫の森」**——苔むした照葉樹の森・渓流・露出した岩と巨木の根。

**身体の規則はほとんど当てはまりません。** 身体は背景から抜いて、立ち姿の背丈に正規化して、足を床に付けてセルに置きます。**タイルはセルそのもの**で、**揃えるべき相手は他のタイルではなくグリッド**です。だから変換も別の道を通ります——**四角を見つけて、縁の滲みを削って、セルの大きさに縮める**。抜きも正規化もしません（**図と地が無く、絵が地そのもの**だから）。

### 測ったこと（次に頼むときの目安）

- **1行1種類・基準キャラクターを毎行いちばん左**は、**5回連続で守られました**（51×92〜93px ＝ **±1%**）。**「その行が何の行であっても基準は同じ人間」と書けば通る**（2節）

### 一番効いたのは絵ではなく貼り方

**セルごとに90°回転＋左右反転（8通り）をハッシュで混ぜると、繰り返しがほぼ消えます。** 最初に組んだときは32pxの格子がはっきり見えていて、向きを散らしたら地面として読めるようになりました。**乱数は引かず座標のハッシュ**なので、世界の指紋は1ビットも動きません。**向きのあるタイル（縁・坂・水際）には使いません。**

### 水の描き直し（「2コマ」は通じない）

**1枚目の組2は、2コマが別の絵でした**——片方にだけ大きな岩があり、交互に出すと点滅します。**「1コマ目を複製して、白い泡だけを1マスの10分の1ずらす。石と色は1ピクセルも変えない」と書き直したら通りました**: **ぼかしてから比べた構図の差が 11.0 → 4.7**（採用済みの組1が6.3）。**歩行が立ちと区別できなかったときと同じ形の教訓で、「2コマ」とだけ書くと2枚の絵が返ります。**

**ただし色が別物で来ました**（平均 (25,117,141)・(68,136,132)、彩度118と77。**シートの水は彩度31〜36**）。**水は変換側で直せます**——**髪と肌と違って色相が他と重ならない**（1節③）ので、**平均と標準偏差を置き換える水に合わせました**（`WATER_MATCH`。**組の2コマには同じ変換**を当てる。別々だと色がちらつく）。**深い流れのほうは描き直しのほうが悪かった**（構図の差 9.0 対 6.3）**ので採らず、浅瀬だけ差し替えました。**

### 色を引き離した（2026-09-22、届いた日の夕方）

**届いたシートは美しく、そしてほとんど一色でした。** 家族ごとに平均を取ると、**平地と荒地の差は10.6、平地と幹は9.3**（0〜255の尺度）で、**明るさは 77.0・78.7・79.1**。**セル27pxで見て、台地と平野の区別も、荒地とそれ以外の区別もつきません**（画面を見た最初の一言がこれでした）。

**だから変換のときに1度だけ引き離します**（`PALETTE`。**チャンネルごとの倍率**なので、**絵はそのままで、乾いた光や日陰の光で見ているだけ**になる）。

**明暗は1つのことだけを、2段階で言います**——**世界の床は暗く、台地の上は明るい**。**段数に比例させません**（2段目の台地が1段目より明るいということは無い）。**4段階のグラデーションは、4つとも中くらいの緑にしかならなかった**からで、**今そこが何段目かを言うのは段差の線のほうです**。**残りは同じ明るさの中で色相が言います**——**荒地は乾いて赤、幹は茶でさらに暗く、岩は灰色で冷たく、川は青。**

| | 前 | 後 |
|---|---|---|
| 明るさ（床／荒地／台地／幹／岩） | 77 / 79 / 87 / 79 / 79 | **66 / 66 / 124 / 49 / 72** |
| 床と荒地の距離 | 10.6 | **26.6** |
| 床と台地 | 20.5 | **98.2** |
| 床と幹 | 9.3 | **30.1** |

**飽和した画素は1万分の1。** **押さないのは、1枚の中に平地を含むもの全部**（水際・根の縁・坂・巣・そして川）——**半分が野原のタイルは隣の野原と同じ緑でないと継ぎ目が出る**からです。**巨岩だけは家族から外します**（幹と一緒に茶へ押すと**土の山**になった）。

**同じ絵を2つの光で出すこともできます**（`ground.scree.*` ＝ 岩の縁を床の明るさで焼いたもの）。**巨岩の足元に台地の縁を使うと、岩のまわりだけ明るい輪ができる**ので、**同じ3枚を暗い光でもう一度焼いて、そちらを使います**。**新しい行を頼む必要はありません。**

## 10. 精霊のキャスト（2026-09-22。4枚で全部入れ替わった）

**世界の住人を人間から精霊に描き替えました。** 届いたのは4枚——**`yousei_seinen.png`**（大人）・**`yousei_humans.png`**（子供と老い）・**`yousei_eat.png`**（その食事の行だけ）・**`yousei_enemy.png`**（獣）。**絵のセットは `set5`**（既定）。

### この cast が今までと違う1点

**色を持っていません。** 彩度の中央値が **1〜5**（人間の絵は髪と肌で 20〜40）、**ほぼ白 60〜72%・暗い輪郭 20〜26%**。**白×色＝その色**なので、**貼るときに色を掛けられます**。

**これは1節③の裏返しです**——人間の絵では**茶髪(hue 20〜30)と肌(hue 25〜35)が完全に重なっていた**ので、色を掛けると水死体か赤鬼になり、**髪色は8種描いてもらうしかありませんでした**。**精霊なら系統の色をビューアが無限に作れます。**

**代わりに、色が言っていたことを形が言います**——**性別＝頭の形**（丸い耳／炎のような房）、**年齢＝形**（子供は頭が大きい／老いは房が垂れ輪郭がほつれる）。**大きさは絵で言いません**（ビューアが `AgeFactor` で縮める）。

### 変換に足した3つ

- **行の中身を「数」で切る**（`COUNTS`）。**攻撃の線・消滅の粒・光の粒で、1行が最大22個に割れます**。**糊を強くするのは逆**——粒の雲を集められる強さは隣の身体も集める。**大きい塊を核にして小さいものを近い核へ寄せ**、核が無い行（光の粒）だけ**広い隙間で切ります**。
- **遠すぎる欠片は別の行のもの**（核の幅より遠ければ拾わない）。**帯の切れ目で飛ぶ獣の翼の先が下の行に残り、亡骸のクリップが横1052pxに伸びました。**
- **`--drop`**——**古い人間の子供の絵を持ち越さない**ため。**茶色い人間が精霊の横に立つより、大人の精霊の食事を小さく描くほうがまし**です（`standIn` がそうします）。

### 高さの上限も「身体」で測る（`tall`）

**幅だけは身体（連結成分の最大）で測っていたのに、高さは絵で測っていました。** **被弾は頭上に衝撃線が飛ぶ**ので、絵で測ると**身体が7%縮みます**——2026-09-22 の朝に幅で塞いだ穴が、高さに残っていました。

### 残っている指摘（そのまま使える範囲）

- **殴る姿勢が立ちより 7〜13% 低い**（`human.fight` / `old.fight` など）。原因は高さではなく**幅**——**腕を伸ばすと身体ごと136px幅**（立ちは104）で、**正方形のセルでは広い姿勢が高さを譲ります**。次に頼むときは「**腕を前に出すぶん身体を縮め、横幅は立ちの1.2倍まで**」。
- **`child.walk` と `enemy.water.walk` の「歩き」が弱い**。ただし**分母のほう**（立ちの2コマ）**が動きすぎている**のが実態です（子供の立ちは2コマで15%変わる）。
- **`human.f.walk`** は4枚目・5枚目と同じ癖（女性の歩きが弱い）。

### 色の配線（2026-09-22 の夕方に入った）

**明るさが「誰の血筋か」を言います**——**プレーヤーの身体と、その血筋が産んだ子は、絵に描かれたまま**（世界で一番明るい）、**それ以外は暗く**（`colorStranger`。ID から小さなゆらぎ）。**子は「少し暗い」ではなく「まったく同じ」**——**血筋は1つのもので、60体の中から自分のを一目で見つけられることが要求だから**です。**誰も操作していない世界では全員が明るいまま**（対比する相手がいないのに世界を暗くしても、ただ暗い世界になるだけ）。

**獣は色を掛けません。** **変換のときに裏返してあります**——**白いところが暗く、暗い輪郭が明るく**（`SHADOW`。掛け算では作れません。掛け算は明るさを引くことしかできないので、白はどんな色でも一番明るいまま）。**これで獣は「人と同じ光でできていないもの」として、色を1つも使わずに読めます。**

**`tint` は絵の大きさではなく並びが決めます**（`TINTED`）。**以前は「16pxなら灰色の置き絵、32pxなら描かれた絵」**でしたが、**精霊は32pxで、かつ色を掛けるために白く描かれている**ので、大きさでは区別できません。**`--carry` もこの旗を持ち越します**——持ち越さなかったせいで、**3枚を経由した精霊が灰色で届きました**。

### 光の3種の使い道（2026-09-22 に敷いた）

**プレーヤーの身体＝足元の波紋＋身体を囲む輪**（金）、**血筋の子＝舞う粒**（淡い金）。**明るさがもう言っていることを、操作している1体にだけもう一度言います**——**60体の中で最初に見つけなければならないのはそれで、画面外へ出て戻ってくるのもそれ**だから。**波紋は群衆に強い**（身体が重なっても縁が残る）、**輪は引いた絵に強い**（小さく描かれても輪郭に沿って出る）、**粒は「あなたではない、あなたの血」**（輪と見間違えようがない形）。**眠っている絵はもうありません。**
