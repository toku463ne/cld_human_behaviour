- **性差（段階53、`SexBias`）** — **既定はオフ**（全ゼロ＝性別が決めるのは「誰と組めるか」だけ）: **実効値 ＝ 遺伝的素質 × 年齢補正 × 性別補正**で、**掛け算は `Agent.Ability` の1か所のまま**。**継承には触らない**（両性は同じ遺伝子プールから出る＝#4 の「性染色体も連鎖群も作らない」を壊さない。繁殖と測定が読むのは継承値）。**門ではなく平均をずらすだけ**。**振り分けは 53a の役割から逆算した**（#85。母＝理性・防御力・記憶／父＝パワー・速さ・頭の良さ／体力・回避率・魅力は中立）。**測定（48シード）: 0.15 で個体数 −15.96 \*\*、0.30 で −31.60 \*\*\* と用量にほぼ比例**。**そしてこの段階の発見は、役割どおりの配分が役割を逆にした配分（−7.94 \*）より悪いこと**——**この世界が金を払っている遺伝子と役割が要求する遺伝子が別**だから（速さ 0.22・頭の良さ 0.11 に対し、防御力・理性・記憶は各 0.06）＝**役割から逆算した配分は、動けない母に一番払われない3本を持たせ、一番払う2本を取り上げる**（母の寿命 −212.79 \*、入れ替えると +282.48 \*）。**筋が通っていることと世界が報いることは別**。**それでも `shMemory` が6度目に動いた**（強い用量で +0.01 \*、**性を入れ替えると −0.01 \* と符号が役割についてくる**。**測っているのは継承値なので本物の選択**）——**記憶に値段をつけることはできるが、そのためには世界を貧しくするしかない**（代価は個体数の3分の1）。**どの腕でも `clumping` +0.12〜0.16 \*\*\*・`halfLife` +10〜11 \***（あるべき状態D）

- **育児中の母は遅くなる（段階66、`NursingSpeedShare`）** — **既定は 1.0（無効）**（`cmd/devview -nursing`）: **子が `RearingRadius` の内側にいるあいだ、母の実効速度が下がる**。**新しい強制は作っていない**——**母も子も今までどおり全候補を効用比較**し、変わるのは母の身体の1つの数字だけ。**`MaxSpeed` の掛け算には入れない**（あれは世界を知らない静的な鎖＝#99）。**形は段階54・57 と同じ「毎tick書き直される事実の写し」**（`Nursing`）で、**速さを読む3か所（`moveDir` / `evasion` / `selfView`）は同じ値を読む**（揃えなければ3つの別の身体になる）。**判定は tick の先頭の専用の走査**——`keepToGuardian` の中では移動ループの途中で間に合わず、**`stillReared` は答えると同時に子ども時代を1tick使うので呼べない**（訊くだけの述語を別に書いた）。**測定: 狙ったものは全部動く**（`rearNear` 0.73 → 0.90、`rearMoved` +190.01 \*\*、`grewUp` +0.04 \*\*\*、子の死亡割合 −0.03 \*\*\*、代価は `humans` −5.17 \*・出生 −17.62 \*）**が、対照も同じだけ動かす**——**「同じ平均の遅さを、子がそばにいるかどうかと無関係に与える」腕**（段階54 の `moodflat` と同じ形。**用量は 1.005倍で揃えた**）**のほうが `rearMoved` +251.69 \*\*\* と大きい**＝**買っているのは「遅い母」であって「子のそばで遅い母」ではない**。**構造が効いたのは集団の持続だけ**（`halfLife` +17.26 \*\* 対 +4.22 \*）。**母の状態が変わるのは 18 nursing-tick に1回**なので、**境界でのガタつきは無い**

- **母が育て、どちらの親も養える（段階53a・53b）** — **既定オン**（`GuardianIsMother` / `ParentFeedByKin`。どちらも false で以前の世界）: **子がそばに留まる相手を母に固定した**（2026-09-11 まで「どちらでもルール上は関係ない」として番号の若いほうで、**実測でも 50.5% が父**だった）。**妊娠・出産・育児が同じ身体の仕事であることを構造にしたもの**で、**段階53 の遺伝子の振り分けはこの役割から逆算する**（#85＝先に役割、あとから遺伝子）。**出産の代金の折半は変えていない。** **ただし `mouthsToFeed` が `GuardianID` 一致で弾いていたので、53a だけでは父が給餌から完全に締め出される**（#86）——**判定を「血縁かつ `RearingRadius` 圏内」に緩めた**（**新しい所有も状態も作らず、段階7d の受動的な `share()` のまま**。**`ActGive` には頼らない**＝**配偶者への贈与は実測 0%** で、信頼が飽和しているので贈与の値付けでは物が動かない）。**実装前に数えた的**: ガーディアンが圏内 0.774／**ガーディアンでない親も 0.475**＝**給餌の機会が約1.6倍**。**測定（48シード、給餌 0.5 の世界）: 53a 単体 −2.96 ± 4.63、53a+53b +1.19 ± 4.62**（**向きは予想どおりだが、どちらも誤差内**）。**はっきり動くのは子の側**（`childDeathShare` −0.02 \*\*\*、`grewUp` +0.01 \*）**と父の寿命**（53a 単体 +259.60 \*\* → 53b で +132.81 \* ＝**役の代価はおよそ260tick の寿命で、その半分を給餌が返す**）＝**集団の数字が動かないことは、規則が何もしていないことではない**。**給餌オフの既定の世界では 53a 単体が −4.31 ± 6.68**（`clumping` +0.10 \*\*）。**そして `shMemory` が +0.01 \* と、遺伝子の振り分けを入れる前から動いた**（5度不発だった量）。**説明のつかないものを1つ残した**——`dadNear` が 0.47 → 0.40（**規則は両性で同一なので、規則の差ではなく振る舞いの差**）

- 状態モデル: 体力（`Vitality`）・空腹度（`Hunger`）・**成熟度（`Maturity`）**・世界に湧く食料。食べる→空腹度↓、満腹かつ無理をしなければ体力↑、動く/戦うと体力↓、空腹が進むと体力↓。死因は餓死・戦闘・消耗（寿命）の3つで、既定でおよそ 34% / 62% / 4%。

- 成長と老い（`Agent.AgeFactor`）: **遺伝子の実効値 ＝ 遺伝的素質 × 年齢補正**で、掛け算は `Agent.Ability` の1か所だけ（`Gene()` は遺伝的素質のまま＝繁殖と測定はこちらを読む）。曲線は1本で、**若い端が成長**（`Maturity` が食事で 0→1、`ChildhoodYears` = 2年）、**老いた端が衰え**（`SenescenceYears` = 12年から `SenescenceFloor` まで）。**成人（`ReproMaturity`）まで求愛は候補に挙がらない**——これが子ども期のコストの本体で、死亡率ではなく世代時間に乗る。

- 育児期間: 出産後 `ChildRearingTicks`（1000＝2年）、子は親から `RearingRadius`（130＝**視界と同じ**）以上離れると戻る。**既定では給餌なし・親側の負担なし・親の効用に子は入らない**（`ParentFeedShare = 0`。2026-09-06 に給餌を実装して測ったが既定にはしなかった＝下記）。 半径を短くすると子を食料から引き離して殺す。実測された効き方は**保護ではなく凝集**（子の生存率は動かず、死亡率と個体間距離が動く）。**紐の終わりは時計であって「独り立ち」ではない**（`RearingUntilGrown = false`）——2026-09-06 に「成熟度が1になるまで親についていく」版を実装して測ったが**既定にはしなかった**。**伸びるのは中央値ではなく裾**（1000 → 中央値1180・p90 2000〜2800tick）で、**長く縛られるのは飢えている子だけ**＝成長は食事で買うので、紐が妨げるものと紐を解くものが同じ1つの資源。結果は `grewUp` −0.03 \*\*・`starveRate` +0.29 \*・`killRate` −0.35 \*\*\* で、**凝集は買えない**（`clumping` −0.03、誤差内。動いたのは密度依存の指標だけ＝個体数が減ったぶん）。**固定2500tickの対照（`longrearing`）は同じ向きにもっと強く出る**ので、効いているのは「規則の種類」ではなく「長さ」。**出産のバグを直した世界で測り直すと代価はさらに大きい**（個体数 −10.62 \*、出生 −41.08 \*\*\*。買えるのは `clumping` +0.08 \* だけ）。

- 給餌（`engine/provision.go`、`ParentFeedShare`）— **既定でオフ**: 親の一口の一部が、そばにいる育児中の子に回る。**世界で初めて「ある個体が別の個体のために払う」規則**だが、**新しい行動も新しい状態も判断も作らない**（`eat` の分配が変わるだけで、誰も「食べさせる」ことを選ばない）。**分けるのは一口であって食料そのものではない**（所有・競走・奪い合いは不変）。**親は知る**（`Perception` の栄養価に載る＝`ParentFeedKnown`）。**毒も分け前の割合で子が受ける。** **測定は2度した**——**出産のバグ（下記）を直す前は「個体数 −4.67 \* を払って `grewUp` +0.03 \*\*\* を買う取引」だったが、直した世界では費用が消えた**: 0.5 で個体数 +5.08（誤差内）・`gen` +0.48 \*\*・`grewUp` +0.04 \*\*\*・子の死亡割合 −0.02 \*\*\*・`starveRate` −0.04 \*（48シード）。**費用だけの対照（`ParentFeedWasted`）は今も −7.54 \*** ＝**親への課税は実在し、給餌がそれを上回って返している**。**既定は0のままだが、上げる根拠は測定の側にある。** **親の効用式には今も子の項が無い**——親は給餌を望むことも拒むこともできず、うまくやることで選択もされない。選択が見ているのは血統だけ。

- 慢性的な低体力（#33）: 体力が `FrailVitalityShare` を下回る状態が続くと寿命が減る。**`ShockRisk`（効用式に載る今の危険）とは別物**で、`Perception` にも効用式にも出てこない。

- 寿命消費（背景処理・`World.spendLifespan`）: `Agent.Lifespan` が空腹度過多（`StarveHunger` 超）または過度な満腹（`OverfedHunger` 未満＝「腹八分目」超）の間だけ毎tick減り、0で死ぬ（`Stats().AgingDeaths`）。完全にバックグラウンドの機械的処理で、`Perception` に載らず効用式にもゴール項が無い。ノードは自分の寿命も、死因としての老化も知らない。選択圧は世代を超えた差次的生存だけを通じてかかる。既定値は 2026-09-02 に較正した（`MaxLifespan = 3000`。6000では標準実行長で一度も発火せず、1500では世界が壊れる）。

- 出産（`stepPaired` → `tryBirth`）: **走り終えたペアは必ず1人産む。** 2026-09-06 まで、出産は「番号の小さいほうが実行する」というID条件に掛かっていて、**両者が同じ時計を減らすので先に0に達したのが番号の大きいほうだと、そのまま解散して何も産まれなかった**——**実測で完走したペアの約半分**。直すと**個体数 51.75 → 87.96（+36.21 \*\*\*）、出生 113 → 244（+130 \*\*\*）、世代 7.17 → 9.00（+1.83 \*\*\*）**。世界は混み合い荒れる（`killShare` +0.09 \*\*\*、`neighbours` +3.55 \*\*\*、`grewUp` −0.07 \*\*\*、`childShare` 0.25 → 0.42）が、**頭の良さへの選択圧が大きく上がる**（`dIntelligence` +15.93 \*\*\*）。**`BirthNeedsLowerIDFirst = true` で以前の世界に戻せる——2026-09-06 より前の測定値はすべてその世界のもので、個体数・出生に触れる結論は読み直す必要がある。**

- 求愛への答え（`engine/courtship.go`、2026-09-06）: **求愛は2人でするのに、訊かれるのは片方だけだった**——求愛者が歩いていくのは行動（人も選べる）だが、**着いた瞬間の答えは世界の規則**（`willCommit`）で、求愛された側は事後に知るだけだった。**答えをコントローラに出せるようにした。** 形は「engine は誰が後ろにいるかを知らない」といういつもの線: **`CourtAnswerer` を実装したコントローラにだけ訊き、実装しないコントローラ（AI全部）では1ビットも変わらない**（指紋テストが無変更で通る）。**待ち時間は `CourtAnswerTicks` = 60 で打ち切り、そのノード自身の規則が答える**——**誰も答えないノードはAIと同じ結末**になり、席を外した人が他人の一生を止められない。**`GuidedController` は既定で「答えない」**（`AnswerProposals(true)` を UI が呼ぶ）＝**段階23 の「誰も答えない誘導ノードは純粋なAIノードと1ビットも違わない」を守るため**（待たせること自体が違いになるので、既定で待たせない）。

- 求愛の可否（`Agent.CanReproduce`、段階25）: **「身体にできないこと」と「今は割に合わないこと」を分ける。** 前者（成人前・出産の代金 `BirthVitalityCost/2` を払うと死ぬ・クールダウン中）は**候補から消す**。後者（空腹・低体力）は**効用式が決める**——`addCourt` が代金と `Life` の負の項を載せるため。**閾値は効用式から抜けていた項の代わりだった**（求愛はそれまで「そこまで歩く代金」しか払っていなかった）。**代金を入れるだけで個体数 39.6 → 28.1、閾値を外すと 38.0 に戻る**＝2つはほぼ打ち消し合い、正味は個体数・出生ほぼ同じで `killShare` 0.65 → 0.60、餓死は増える。**予想の「pop は下がる」は外れ**（上がった）——閾値のほうが厳しすぎた。`CourtNeedsSurplus = true` で昔の挙動に戻せる。

- 相手選び（`willCommit`、段階26・28）: **「待つ」が数えるのはその個体が配偶者を探し始めてからの時間**（`CourtClockResets = false`、段階28）——**求愛のたびに振り出しに戻していたので、断られた個体は我慢が尽きることがなく、誰も誰にも妥協しなかった**。直すと個体数 **+16.79 \*\***・出生 **+48.00 \*\*\***・世代 **+1.75 \*\*\***（代償は `killShare` +0.10 \*\*\*）。**この修正で集団の100%が「待ち疲れ」になり、床が常に効くようになった**ので段階26 の較正を測り直した——**床0 にすると個体数 +6.96 \* だが `shLooks` が 0.16 → 0.10（−0.05 \*\*\*）＝魅力遺伝子を買う理由が消える**ので 38 のまま（求愛の3分の2は成立している）。**待つことは要求を下げるが、下げ切らない**（`CommitFloor` = 38）。**段階26 まで、我慢が尽きると要求は下がるのではなく消えていた**（誰でも受ける）——しかも `CommitFitness` = 78 は集団の上位1割より上なので、**実際の受諾のほとんどがその「消える」経路を通っていた＝体調が効かなくなる唯一の場所が、ほぼ全部の受諾だった**。**床は体調についての新しい規則ではなく、すでにあった規則（体調は魅力の35%）を待っている個体にも届かせるもの**。**個体数の代償はゼロ**（−1.71、誤差内）で、`killShare` −0.05 \*\*\*・子の死亡率 −0.01 \*・寿命 +1.38 \*\*・集団の持続 +7.45 \* を買い、**魅力遺伝子に初めて選択圧がかかった**（`shLooks` は床50 で +0.02 \*）。**両方が出産の代金を払えることは、近づいた側も着いた時点で確認する**（要件なので拒否。歩くのにも体力を使うため）。

- 魅力（`fitness`）＝ 魅力遺伝子 ×(1−`FitnessConditionWeight`) ＋ 体調 × `FitnessConditionWeight`（既定 0.35）。**実能力（攻撃力・理性・頭の良さ）は一切入らない**（強さと「良い相手に見えること」を1つの値に兼ねさせない）。**体調の重みを上げると個体数は増えるが、配偶者選びが「今の健康状態」だけになって遺伝する装飾という選択軸が消えるので、上げていない**（値段は個体数で約2割。数値は `HISTORY.md` 2026-09-02）。

- 遺伝子は `Agent.Genome []float64`（`engine/genome.go`）。体力上限と移動速度は個体ごと（`a.MaxVitality(cfg)` / `a.MaxSpeed(cfg)` ＝ 基準値 × 遺伝子 / 50.5）で、**体力に関する閾値（求愛条件・子の初期体力）はその個体の上限に対する割合**で持つ（絶対値だと体力遺伝子の低い個体が「一生求愛できない」崖になる）。`Gene` 定数で名前を付けた9本＝攻撃力・防御力・最大体力・移動速度・回避率・記憶容量・理性・頭の良さ・魅力。**9本すべてに役割がついた**（防御力・回避率は段階8、記憶容量は段階9）。読むときは `a.Attack()` / `a.Rationality()` / `a.Intelligence()` か `a.Gene(g)`。**9本は1つの予算を分け合う**（`a.Budget()` ＝ 合計）。初期個体だけが予算（`GeneBudgetMean` ± `GeneBudgetStd`）と配分（ディリクレ、`GeneInitAlpha`。ガンマ分布のサンプラは `engine/genome.go` に自前で実装）を抽選し、**子は予算を親の一方から継ぎ（＋`BudgetInheritSpread` の正規乱数）、遺伝子ごとに継いだ値をその予算に合わせてスケールする**。したがって**突然変異は配分を動かすだけで合計を増やさない**。`BudgetHeritability = 0` で「予算が遺伝しない世界」に切り替えられる。**予算には維持費がある**（`BudgetUpkeep`。大きな身体ほど空腹が速く進む）——これが無いと予算は世代とともに際限なく上がり、予算が制約でなくなる。

- 能力の役割: 攻撃力（体力あたりの戦闘効率）／理性（推定精度＝世界の読みのノイズ）／頭の良さ（手の評価のノイズ。戦略の幅の経路は既定で無効、`StrategyDepthUnlock = 0`）／記憶容量（覚えていられる人数・取り込む速さ・忘れる速さ）。

- 世界の1日と体内時計（`engine/clock.go`、段階18）: 世界は1000tickの周期を持ち、個体ごとに「眠りやすい時刻」が違う。**時刻で変わるのは休息の回復量だけ**（視界や食料を変えると全員に同時に効く世界の変化になり、「個体どうしが違うことが何を生むか」という問いとは別）。**体内時計は予算遺伝子ではない**——9本は「量」だが時計は**円周上の位相**で、予算に入れると「夜型は殴る力を削る」という生物がしていない取引を主張することになる。好みと同じく親から丸ごと継いで変異し、何も食わない。**回復はゼロに届かない**。**「眠っている友人は見張れない」という条件1つが機構の本体**（既存の割引に条件を足しただけで新しい項ではない）——これが「たまたま寝る時刻が違う」を「誰かが見張っている」に変え、**見張り役はルールのどこにも存在しない**。**これまでで一番はっきり世界を良くした段階**（個体数 +12.6 \*、悪化した指標なし）で、`SleepingWatch = true` にすると利益が丸ごと消えるので機序は確定。**完了条件の指標（全員が同時に寝ている割合）は最初から飽和していた**（どの条件でも 0.00〜0.01）——ハッザ族の観察は体内時計を入れる前から成り立っていた。

- 遺伝: 子の能力は**能力ごとに親のどちらかの値をそのまま引き継ぐ**（粒子的遺伝）。引き方は能力ごとに独立で、連鎖群も性染色体も無い。混合遺伝（両親の平均）は分散を毎世代半分にするので 2026-09-01 にやめた。**突然変異はまれで大きい**（`MutationRate` 2% × `MutationStd` 40）＝毎回小さく乗せると親の値が子に残らず、粒子的遺伝にした意味が消えるため。
