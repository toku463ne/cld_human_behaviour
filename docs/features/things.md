- **本（段階69、`engine/book.go`）** — **既定はオフ**（`Books`）: **3つ目の「拾えるが食べられないもの」**（`FoodBook`。石・コインに続く）と**2つの語**（`ActWrite` / `ActRead`。16・17番目）。**食べられない・腐らない・重さゼロ・手を1つ取る・食料の枠を食わない**。**運搬・贈与・売買・倉庫・発信の経路に乗る**。**読んでも消えない**（`BookSurvivesReading`）ので、**読み終えた本はこの世界で初めて「持ち主にとって本当に値打ちゼロで、他人には値打ちがあるもの」になる**＝**段階68 が「売り手は毎回損をする」と測った損を構造的に消すもの**。**書かれる値は書き手の nominal × `SkillScribe` の実効値 × `BookFidelity`**（本からの伝承は直の伝承より劣る）。**値付けは既存のものだけ**——読む＝`BookValue × LoreValue × 自分にとって新しい割合`、書く＝**その手渡しが買う信頼**。**実装前に数えて、指定どおりの形（スキルの本）には的が無いと分かった**——**ヒント枠は常に満杯**（1.98 / 1.98、空きは **0.000**）で、**世界で最良の本を全員が無料で読めても助かるのは 3.2%・増える習熟度 0.0054**（**段階31 の「上限は重みではなく記憶の枠」の3例目**）。**だから中身を2つにした**（`BookSubject`）——**この世界で場所が空いているのは地域と倉庫の知識だけ**（#41）で、**倉庫の知識には段階50 が測った賞金 +8.40 \*\* がある**。**測定（遊ぶ地図・48シード）: スキルの本は 4.29冊書かれて1回も読まれない**（`booksRead` +0.00 ± 0.00＝**数えた的がそのまま出た**）。**場所の本は読まれ、回し読みされる**（1冊あたり **4.1回**。**「読むと消える」対照は 0.6回＝6.6倍**＝**この段階が作りたかった非対称で、測れた唯一のもの**）。**それでも `storeKnown` は動かない**（+0.01）＝**倉庫の知識は薄れるので、本を読むことは一度聞かされたことと同じ**。**値打ちを16倍にすると読まれた回数は 9.08 → 22.50 と倍以上になるのに世界は動かない**＝**縛っていたのは値段ではない**。**そして段階67 がコインで測った手の取り合いが本でそのまま再現された**（`held` +0.06 \*\*、`load` −0.03 \*＝**重さゼロで手を1つ取るものは、何であっても食料を押し出す**）。**実装して初めて分かった2つ**: **一本の手では「渡すものを持つ」と「書く手を空ける」が排他**なので `addGive` から借りた値付けはいつもゼロだった／**`SkillScribe` は列挙の最後なので既定の4枠ではほとんど誰も持てない**（枠6で 0.83 → 8.62）＝**壁は本の両端にある**。**そして段階69 の売買は段階67 が無いと成立しない**（読み終えた本は手放すのに何も要らないのに、**満腹の売り手にとってコインは値打ちゼロ**なのでゼロ対ゼロになる。テストで固定）

- **売ることは手渡しでもある（段階68、`AffinitySale` / `engine/coin.go` の `saleGoodwill`）** — **既定はオフ**（0 ＝段階51 の世界そのもの）: **`sell()` が成立したとき、`giveItem` とまったく同じ呼び出しで双方向に好意を書き**、**`willSell` の売り手の側と `addBuy` の買い手の側に、その好意が買う信頼を `LoreValue × gained` として足す**（`addGive` と同じ式を1か所に）。**新しい信頼も評判も作らない。** **段階51 が好意を意図的に書かなかったのは「2つの規則が1つになって測定が読めなくなる」から**で、**その測定が済み、言ったのが「足りないのは買い手ではなく売り手」だった**ので開けた場所。**`willSell` は `CoinValue×keep > max(meal, keep) − lug` で、`max(meal,keep) ≥ keep` なので売り手は毎回 `(1−CoinValue)×keep` だけ損をする**——**埋め合わせは運ぶ手間しかなかった**。**天井は選べない**——**信頼は `AffinityTrust` で飽和するので、`AffinitySale` をいくら大きくしても値打ちは `LoreValue` = 9 を超えない**。**実装前に数えた**: 断る売り手 54.3%、断るときの平均の隔たり **15.78**、**好意2.70（贈与と同じ）で閉じるのは断りの12.6%、9.00（天井）で36.6%**＝**天井が平均の隔たりに届かないことが先に分かっていた**。**測定（遊ぶ地図・48シード・用量3点）: `sales` 5.12 → 8.00（+2.88 \*\*\*）、`salesRefused` 45.6 → 27.0（−18.62 \*\*）**＝**断りは4割減り売買は56%増**。**用量6 は 1.7 SE で予想どおり出ず、40 は 20 とほぼ同じ**（天井は保たれたが**完全に同じではない**——**値付けは飽和するが記憶に書かれる量は飽和しない**）。**代価は個体数 −9.44 \*（1.7 SE）・`starveRate` +0.41 \*・`gifts` −35.54 \***。**そして対照が代価の出どころを名指しした**——**`sellnowrite`（同じ値付けで誰の記憶にも何も書かない）が、この群で一番売れていて（9.06）、落ち込みの62%を取り戻す**＝**払ったのは取引ではなく、好意が記憶に残ること**。**理由は既に記録にある**——**好意は休息を安全に見せる**（段階9 の露出の割引）ので**この世界で好意を増やすことは net で損**（`shMemory` を6度探して出た結論と同じ壁）。**`coinHolders` は上がらず `coinsHeld` は下がる**（−3.02 \*）＝**コインが使われるようになると手に溜まらなくなる**。**`halfLife` は +48.23 \***

- **飾り物の好みと、それを欲しがれる身体（段階84、`TrinketTaste` / `AdornNeedsSurvival` / `HandOverCheapest` / `GiftPriced`）** — **2026-09-15 に前2つを既定にした**（**味 ＝1、先読みの割引 ＝オン、そして段階80 の `SalePriceSplit` も同時にオン**。**どれも飾り物・値段を入れた世界でしか読まれないので、既定の世界の指紋は1ビットも動かない**。**`HandOverCheapest` と `GiftPriced` は既定オフのまま**＝前者は飾り物のある世界で出生を払い〈−10.54 \*〉、後者は段階48 以来の贈与の測定を全部読み直しにするから。**旧世界は `cmd/devview -notaste` と `cmd/experiment` の `beforeTheFlip`**）: **段階82 が意図的に断ったもの**（「値打ちは持ち主に依らない。変わるのは物であって好みではない」）**を、その測定が済んだので開けた**。**味は円の上の位相**（`Agent.taste`。**体内時計とまったく同じ立場**＝量ではなく方向なので予算を1ミリも食わず、親の片方から丸ごと継いで漂う）で、**品の側も同じ円の一点**（`Food.Style`）。**作り手は狙えない**（`TrinketStyleAimed` がその対照）＝**歩いても働いても手に入らない欠乏**。**倍率は平均1**＝**欲しさの総量は増やさず配り直すだけ**（段階15a の食料の原則を欲求に適用）。**これがこの世界で初めての「誰が持っているかで変わる値打ち」**で、**段階79 が算術で書いた壁の唯一の抜け道**。**先読みの割引は `survives()` を値打ちに掛けるだけ**（段階73 が子に使った関数。**掛ける場所は目的の `Chance` ではなく物の値打ち**＝**欲しがることと手放すことが同じ数字を読まなければ、同じ身体が同じ tick に同じ物へ2つの値段をつける**＝段階77 の教訓）。**実装して最初に見つけたのは、飾り物も本も買えなかったこと**——**`addBuy` の入口が掲げられた品の栄養価を訊いていた**ので、**栄養の無いものは「買う」という選択肢が一度も採点されたことがない**（`CoinBuysOnlyMeals` で旧世界に戻せる。**段階51・68・69・80・82 の売買の数字は全部その世界のもの**）。**測定（96シード）: 味は個体数 +11.15 \*\*・出生を元に戻す**（飾り物は出生を 73.3 → 50.0 \*\*\* 奪っていた）、**売買 +0.34 \*\***。**偽薬**（同じ乱数を引いて効き目だけ千分の1）**は飾り物ありの世界と同じ**＝乱数列の違いではない。**贈与を殺した 2×2 でも生き残る**＝手渡しの経路も通っていない。**先読みの割引は `craftShare` を 0.07 → 0.04 にし、段階82 が壊した3倍の用量を壊さなくする**（−6.51 \*\*\* → +0.70）**うえ、そこがこの群で一番大きい市場**（売買 +0.49 \*\*、飾り物 +0.57 \*\*\*）。**それでも値段は散らばらない**（1枚超 +0.01）——**散らばらせるのは品の違いではなく余剰の分け方**（`SalePriceSplit` で +0.25 \*\*\*、**味の有無に依らない**）＝**実装前の数え上げどおり**（値段は売り手の床で決まり、床は9割の売り手で0）。**選り分けをするのは売買で、贈与ではない**（持ち主が替わって増えた好み: 売買 **+0.25 \*\*\*** 対 全体 +0.07 \*\*\*）＝**贈り物の受け手は誰も選んでいないが、買い手は自分で自分を選ぶ**。**`GiftPriced` は `addGive` が歩く代価しか払っていなかったことを直す腕**——**入れると贈与の9割が消え**（662 → 64）**個体数は +7.30 \***＝**この世界で物を配ることは net で損**

- **飾り物（段階82、`Trinkets` / `engine/trinket.go`）** — **既定はオフ**（`cmd/devview -trinkets`）: **この世界で唯一「それ自体のために欲しがられるもの」**（#109・#110 が許した意図的な例外）。**食べられず・治さず・殺さず・何も教えない**。**効用式には専用の目的 `Adorn`**（他の7つは全部手段なので混ぜない）。**地面には湧かず身体の手から出る**（`ActCraft`＝19 番目の語。**歩いて解決できる欠乏は欠乏ではない**）、**作るのに時間と体力を払う**（値段の無い利益は天井まで走る＝段階17b）、**1つ1つ値打ちが違い**（この世界で初めての「種類ではなく個体ごとの値打ち」＝段階80 の値段が散らばりうる唯一の余地）、**肉と同じ時計で腐る**（値打ちは残り時間に比例して連続的に落ちる）。**測定して初めてバグが見つかった**——**`canEat` が食べられないものを名指しで並べる形だったので、4つ目の種類は `default` に落ちて食べられていた**（**身体は飾り物を作って食べており、最初の測定の個体数 +35.56 \*\*\* はそれ**。2026-09-10 のコイン59枚と同じ形。**線は `NumEdibleKinds` に引いてあるのだから線を訊く形に直し、調理と植物の枠も同じ回で塞いだ**）。**測定（96シード）: 仕組みは全部動き、市場は現れない**——**1実行に1484個作られ73%が持つ**のに **`sales` −0.55 \*\*\*・1枚超の値段 −0.17 \*\***（**食料の向かい風の外でも値段は市場を作らない**＝#110 が用意した試験台の答え）。**増えたのは贈与 +269 \*\*\***で、**贈与を切ると同じ規則が個体数を20 奪う**（−19.99 \*\*\* 対 −1.34）＝**誰も必要としないものは渡しても誰も飢えない＝段階48 以来はじめての代価の無い贈り物**。**対照が機序を割った**（`TrinketsVanish` ＝同じ時間と体力で手に何も残らない腕は **+8.50 \***）＝**立ち止まっていることは得、物が手に残ることは（渡せなければ）損**。**用量が段階のすべて**（3倍で**決定の23%が「作る」**になり個体数 −14.29 \*\*\*・餓死率 +2.45 \*\*\* ＝#110 の警告そのもの）。**作り手の腕は育たない**（保有率 0.01＝**ヒント枠の天井の4度目**。段階31・62・69・82）ので**82d の質による裁定は実際には試せていない**。**予想は5つ書いて1つ当たり**

- **売買の値段（段階80、`CoinPrices` / `CoinPriceBlind` / `SalePriceSplit`）** — **3つとも既定はオフ**（`cmd/devview -prices`。**80a が要る**——枠のある世界では買い手が2枚目を持てないので値段は必ず1枚＝**この規則は何も足さない**ことをテストで固定）: **値段は枚数**で、**双方の限界はすでにある式を割り算にしただけ**（売り手の下限＝`willSell`、買い手の上限＝`addBuy`）。**新しい見積もりも記憶も作らず、値段はカウンターで決まり、掲げも覚えもしない**＝**#73 の「値段も帳簿も無い」を値札のぶんだけ緩めない**。**買い手は標準価格 `1/CoinValue` で採点して出発する**（特定の売り手の言い値は隠しパラメータなので、**世界の標準を仮定する**＝段階49 と同じ形）。**実装して初めて分かった算術: 並の1食では買い手の天井はちょうど `1/CoinValue`**（買うものと自分のコインが請求するものが同じ figure だから）＝**1枚超の値段が付くのは、その品が買い手にとって並の1食より値打ちがあるときだけ**（飽きの割引・治り・好意）＝**段階79 が売り手側で書いた壁の買い手側の同じ形**。**測定（96シード）: 値段は市場を作り、買い手の正しい採点が市場を閉じる**——**対照（`CoinPriceBlind` ＝値段は付くが買い手は1枚のつもりで出発する）で売買 2.06 → 3.72 \*\*\*・動いたコイン2.7倍＝P13 で初めて市場が本当に大きくなった**のに対し、**標準価格で採点させると売買は 0.85（−1.21 \*\*\*）**。**そして世界が返ってくるのはそちら**〈個体数 **+4.97 \***、**`rareTrough` 0.35 → 0.49（+0.14 \*\*）＝あるべき状態A の帯へ復帰**、餓死率 −0.37 \*〉＝**買っているのは取引ではなく、1実行あたり83回の無駄足の消滅**〈断り 86 → 2.8〉。**平坦では個体数は動かない**（−0.51）。**予想は6つ書いて4つ当たり**（外したのは「`sales` は増える」——**半分になった**——と「個体数は誤差内」）。**値段は散らばらない**（1枚か2枚、平均1.72、収まる整数は中央値1個）＝**#112(b) の相場は作らない**

- **売買を前後差に一本化する案は作らなかった（段階79、2026-09-14）** — **実装前の数え上げで決着し、コードは1行も書いていない**。**(1) 前後差は売買を見ることができない**（`pressures` が手を読む経路は `HeldMeals` ただ1つなので、**段階78a が無ければ売る前と後の差は厳密に 0.0000**）＝**同じ日に「既定にできない」と測ったばかりの規則を前提にする設計**。**(2) 78a を入れても前後差は一度も正にならない**（掃引した全状態で 0 〜 −42.6）＝**請求権は請求先より価値を持てない**（#73 の算術。`coin.go` の冒頭がすでに書いている）ので、**結局 `lug` と好意を足し戻すことになり、今の式を多くの機械で書き直すだけ**。**(3) そして壁が初めて算術で書けた**: **売り手の `coin/food` は、品が並の1食なら状態によらず厳密に `CoinValue`**（120状態中72状態で 0.5。**ずれるのは段階16 の飽きの割引のときだけ**）＝**売り手はいつも半分足りず、釣り合うのはコイン2枚**。**ところが実測でコインを持つ身体の 100.00% が1枚しか持っていない**（1人あたり **1.000 枚**、2枚以上 **0.0000**）——**手が1つで、コインを持つことは手が塞がること**だから。**清算価格は存在するが到達できない**。**残る道は3つで2つは塞がっている**（`CoinValue = 1` は #73 が禁じ、手の枠を外すのは段階76 が `rareTrough` −0.16 \*\*\* と測った）ので、**次は段階81**（コインの値打ちを、比べる相手と同じ図の固定倍にするのをやめる）＝**80 と 81 の順序を入れ替えた**

- **売り手の物差しを一本化した（段階77、`handView` / `handWorth`）** — **重複を消すだけの変更で、既定側は1ビットも変わらない**（`willSell` が食料と本について同じ算術を書き直していた。**`handViews` から1品ぶんを `handView(a, f)` として切り出し、`saleTerms` がそれを `handWorth` に渡す**）。**`lug` は外に残す**——**「手放すものの値打ち」と「持ち続ける代価」は別の量**。**石は量るが売らない**——**「入れる腕と入れない腕を対で回して決める」と計画に書いていたが、数えたら腕が要らなかった**: **売り手の側の的はゼロではない**（投擲のある世界で、何かを持っている身体の 5.3% が石を持ち、**その100%が他に売れるものを何も持っていない**。**投擲の無い世界では 0.00000** ＝`coins` の腕の `stoneHeld` 0.00 はそのことしか言っていない）**が、決め手は買い手の側**——**石には栄養も治りも `Worth` も無いので `perceive` はその持ち主を `Selling` と呼ばず、`addBuy` は即座に戻る**＝**誰も石を買いに歩いてこない**ので、**入れれば「別のものを求めて来た買い手に、一度も値付けしていないものを渡す」ことしか起こりえない**。**作法として1つ**: **重複を消す変更でも、既定の世界がその経路を踏まないなら指紋テストは証拠にならない**（既定の世界にコインは無い）——**その規則が生きている腕を前後で回して出力を比べた**

- **手の枠の既定を測り直した（段階76、2026-09-14）** — **コードは1行も変えていない測定で、既定は動かさなかった**: **枠を外すと市場は戻る**（`sales` 1.76 → 5.23 ＝ **+3.47 \*\*\***、`coinHolders` 0.49 → 0.30 \*\*\*、`gifts` +445.77 \*\*\*）**が、代価は個体数 −8.84 \*\*・世代 −0.98 \*\*\*・餓死率 +1.46 \*\*\*、そして `rareTrough` −0.16 \*\*\***（**あるべき状態A の帯**）。**段階72〜74 の3つの直しはこの代価を1ミリも和らげず**、**代価はお金が1枚も無い地図でまったく同じ大きさで出る**（−0.17 \*\*\*）＝**コインの話ではなく運ぶことの話**。**そして対照（枠なし＋重さゼロ）が罠を名指しした**——**代価は丸ごと消える**（`rareTrough` −0.02 ± 0.04）**が、同時に市場も消える**（`sales` **0.00**）。**`willSell` は `coin > food − lug` で `coin = CoinValue × keep ≤ food` なので、売り手が得をする余地は `lug` の中にしかない**＝**売買が成立する唯一の理由と、枠を外したときに世界が払う代価は、同じ1つの量**。**したがって既定は据え置き**（地図の作者の選択肢としては残る）で、**逃げ道は段階79 の側にある**（売買を `pressures()` の前後差で採点すれば、売る理由が運ぶ代価から切り離される）。**機序が1つ分かった**: **枠が噛んでいるのは「持つ側」ではなく「受け取る側」**（`giveItem` は受け取る側に空き手を要求する）——**手が塞がっているのが全瞬間の12.5% しかない平坦な世界でも贈与は +41%** ＝**贈与のおよそ29%が「手が無いから」失敗していた**
