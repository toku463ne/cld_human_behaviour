# ゲーム化（人が動かす）

**人間コントローラ、訊かれて答える遊び方、性格、贈与。**

**`docs/features.md` から 2026-09-20 に分割したもので、文章は1文字も変えていない。** **索引と書き方の決まりは `docs/features.md`。**

**ここは追記順**（`docs/features.md` にあった順のまま）**なので、探すときは段階番号か `Config` のフィールド名で grep する。**

---

- 人間操作（`engine/human.go`、段階19）: `HumanController` は `Controller` の2つ目の実装で、**UIが置いた「命令」を、訊かれたときにそのまま返すだけ**。engine は誰が操作しているか知らない（`AIController` は1行も変えていない＝**指紋テストが無変更で通ることが証拠**）。**設計上の約束は2つ**——(1) **プレーヤーに見せるのは `Perception` の中身だけ**（真の攻撃力・防御力・回避率は出さない。AIが読めないものを人に見せると別のゲームになる）、(2) **狙えるのは視界の中だけ**（`Order` が視界外の相手を断る。「知識」は縛るが「賢さ」は縛らない＝勝てない喧嘩を売る自由はある）。**engine はいつ訊くかを変えない**ので命令は据え置きで、**即時反映は既存のトリガー機構を通す**（`World.RequestDecision` → `TriggerRequested`）。**命令が流れるのは2か所だけ**: 狙いが消えた（`TriggerTargetLost` で訊かれた）ときと、**身体が変わった**とき——AIは訊かれれば全候補を採点し直すので勝手に立ち直るが、据え置きの命令は消えた相手を永遠に指し続けるため。**血統の乗り換えは同じコントローラを子に付け替えるだけ**（`World.Heirs` ＝ 生きていて成人した子。成人の線は `Agent.IsAdult` ＝ 求愛できるかと同じ線）。**「プレイヤー」も「ゲームオーバー」も engine には無い**（後継の指名も血統の終わりも `cmd/devview` 側）。**「誰として続けるか」は死んだときだけでなく、`t` でいつでも訊ける**（2026-09-06。**engine は最初からこれを許していて**——コントローラは付け替えられるもの——**縛っていたのは devview だけだった**。置いていった身体は**死なず、世界のAIに戻って自分の一生を続ける**。**血統は前に進めるもので、死ぬまで待つ列ではない**）。**死んだときに「誰として続けるか」を訊くのも `cmd/devview` 側**（2026-09-06）——**`World.Heirs`（成人した子）より広い候補を出す**のは、あらかじめ後継を指名する線と、身体が死んだ瞬間の線が別だから: 生まれたばかりの子しかいない血統は `Heirs` では空になり、**子が画面に映ったまま「血統は終わり」と言われていた**。成人前の身体は弱い手であって不可能な手ではないので、**隠さずにラベルを付けて出す**（`its child, still growing (23% grown)`）。`Perception.Trigger`（なぜ訊かれたか）はこの段階で足した——AIは読まない。

- 訊かれて答える遊び方（`engine/guided.go`、段階23）: `GuidedController` は `Controller` の3つ目の実装で、**`AIController` を内包して全部の質問に答えたうえで、転機だけ人に回す**。**AIは留守番ではなく常にその個体を動かしている側**——だから**誰も答えない誘導ノードは純粋なAIノードと1ビットも違わない**（テストで固定）。**訊くのは5つのトリガーだけ**（殴られた・目標消失・配偶者発見・破局・体力急減）で**戦闘は1戦＝1回**。**`TriggerRequested`（人が自分から訊いたとき）も転機に入れてある**——世界はこのトリガーを出さないので、これは「転機と転機の間にできることが見ているだけになる」のを防ぐための、人だけが持つ1つの動詞（実測 112 tick に1回＝一生で20〜30回。全トリガーだと 14.5 tick に1回で、その53%が「殴られた」）。**選択肢はその個体が実際に採点した候補**（`DecisionTrace.Options`）で、**メニューを別に書かない**。**並び順はその個体自身の `ChoiceNoise` を乗せたスコア順**（ノイズ抜きの順位を見せると、その身体の頭の良さ遺伝子が買っていない賢さを渡すことになる）。同じ（行動, 対象）は effort 違いをまとめて**上限12件**（メニューではなく**場**を渡す——「一番安全な手」と「一番大胆な手」はこの順位の中で隣り合わないので、何を見せるかは見せる側が決める）。**絞るときは行動の種類ごとに1つ必ず残す**（`keepAKindOfEach`）——素直な上位N件は**求愛と食事から先に消す**が、満腹なノードがどちらも安く見積もるその瞬間こそ人が口を出したい場面だから。**答えは1手であって据え置き命令ではない**（取り上げられた瞬間に使い切られる＝段階19 の「命令が流れる場合」が要らない）。**猶予60tick**を過ぎた質問には答えられない。狙えるのは視界の中だけで、検査は `World.Answer` が行い `OrderHuman` と同じエラーを返す。**`Config` には1つも足していない**（質問の間隔も猶予も世界のルールではないのでコントローラのフィールド）。

- 節目に決める性格（`engine/disposition.go`、段階23）: 人が動かせるのは**好み3つ**（`RiskWeight` / `CompetitionWeight` / `ShockRisk`）＝**段階12a が「正解が世界に無いので学べない」と切り分けた側**で、人に渡しても何も上書きしていない唯一の量。**読み方は「世界の値の何倍か」**（3つは単位が違うので倍率でしか足せない）。**合計は継いだもので、変えられるのは配分だけ**（`World.SetDisposition` は与えられた比率を継いだ合計に合わせて縮める）——用心深くするぶんは他の2つから出すしかない＝**取引が必ず発生し、最適値に固定して逃げ切れない**。上限（`maxPreferenceFactor` = 4）はそのまま。**何を「節目」と数えるかは engine の外**（`cmd/devview` が 乗り換え・成人・ペア成立・出産 の4つを見る）。

- 贈与（`engine/endow.go`、段階27）: **engine の中で唯一、継承も獲得もしていないものを個体に渡す操作**（`World.Endow(id, gene, value)`）。**シミュレーションの側からは誰も呼ばない**（規則も、コントローラも、出生も）。理由は操作性——予算は固定で配分は遺伝するので、**渡された身体が速さにほとんど使っていないと、人が動かす世界は糖蜜になる**。**世界を速くするのではなく主人公に良い身体を渡す**（世界を速くすると、測定した世界と遊んでいる世界が別物になる）。**新しい予算で払う**（他の遺伝子から取ると、プレーヤーが同意していない取引になり、主人公が静かに脆くなる）。**足した量を返す**ので、UIが「これは世界がやったことではない」と表示できる。**贈与は血統に残る**（予算は遺伝するので主人公の子は増えた予算を継ぐ）——避ける方法は「誰の予算が本物か」という第2の規則を作ることだけで、そのほうが悪い。


- 指1本で遊ぶ（`cmd/devview/touch.go`、`TODO.md` の9番。2026-09-20）: **タップで狙い、同じところをもう一度タップで既定の行動、長押し（0.5秒）でメニュー**。**engine は1行も変わっていない**——ここにあるのは入力の層だけで、命令は今までどおり `OrderHuman` を通り、同じ理由で断られる。**キーもマウスも残る**（開発はこの機械でやる）。**指とマウスは1つの層に入れてある**（`pointer`）ので2つの入力経路が食い違わない。**既定の行動は4つだけ**——食料＝食べる／外敵＝攻撃／人＝観察／地面＝そこまで歩く。**人を2タップで殴らない**のは、取り消せないことを2タップにしないため（攻撃は長押しのメニュー）。**長押しのメニューはその狙いに意味のある命令だけ**を並べ、**数字キーでも選べ、外をタップすれば閉じる**（キーボードの無い端末で閉じられるように）。**そしてメニューは質問にも使う**——後継選び・求愛の返事・訊かれるモードの質問・節目の選択の4つは「短い一覧から1つ選ぶ」で同じ形なので、**どこをタップしてもその選択肢が出る**（**数字キーだけだった4つが指で答えられるようになった**。新しい訊き方は1つも足していない）。**段階19 の2つの約束はそのまま**（見せるのは `Perception` の中身だけ／狙えるのは視界の中だけ。見えていない相手を長押しすると、その地面を狙う）。**判定は時間で、フレーム数ではない**——**フレーム数は2度間違いだった**: 遅い端末では長押しが1.5秒になり、**実測でブラウザが1秒に4フレームしか描かない状況があった**。**押している間に1フレームも来なかった長押しは、離した時点で長押しとして扱う**。**指がずれたら（8px 超）どちらでもない**。**ブラウザで実際に確認した**（WASM + 合成タッチイベント。タップで狙い、2度目で `walking to the ground at 164,560`、長押しで4項目のメニューが出た）


- 円ではなく絵で描く（`cmd/tiles` と `cmd/devview/tiles.go`、`TODO.md` の10番。2026-09-20）: **身体と物は1枚のシートから貼った絵**（16px 四方・透過・灰色で描き、貼るときに `ColorScale` で色を付ける）。**`-circles` で以前の円に戻せる**（2026-09-20 より前のスクリーンショットはその描き方）。**絵は `cmd/tiles/art.go` に1文字1ピクセルで書いてある**——**地形・地域・天気・植物・外敵を文字で描くのと同じ形**（決定#133）で、**この project に絵描きはいないが、文字で描く習慣はある**。**状態は4つ**（立つ・歩く・食べる・戦う）×2コマで、**向きは進行方向に左右反転**、**大きさは体力上限**（円の半径と同じ量）、**色は性別＋ID から引いた小さなばらつき**（遺伝子とは無関係＝群衆が同じ絵の繰り返しに見えないためだけ）。**円が持っていた読みは全部残っている**——**輪の太さ＝攻撃力、輪の色＝状態、尾＝速さ、帯＝空腹**、そして**「円の塗り＝残り体力」だけは絵にできないので緑の帯になった**。**シートは1枚**（同じテクスチャからの描画は何枚貼っても1バッチ）で、**ファイル名に中身のハッシュが入り**、**manifest を読んで全部揃ってからゲームを始める**（1コマ目に穴が空いた世界を見せない）。**ネイティブは埋め込み、ブラウザは `fetch`**——**15MB の wasm と 1.4kB の絵は変わる頻度が違う**ので、絵を直すたびに wasm を配り直さずに済む。**画面の外は描かない**（`onCamera`）——**遊ぶズームでは 270 のうち 52 しか画面に無い**。**測定（同じ wasm・`-circles` と対）: ブラウザで 11.0 → 14.4 fps**（絵のほうが速い。**ebiten の vector は Go 側で三角形に分解するので wasm では高い**）。**ネイティブ（WSLg のソフトウェアGL）は 10 → 11 fps で雑音の中**
