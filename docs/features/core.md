# 土台と道具

**engine の骨組み、種族、乱数、トレース、テスト、測定器、保存と読込、地図の読み込み、開発ツール。**

**`docs/features.md` から 2026-09-20 に分割したもので、文章は1文字も変えていない。** **索引と書き方の決まりは `docs/features.md`。**

**ここは追記順**（`docs/features.md` にあった順のまま）**なので、探すときは段階番号か `Config` のフィールド名で grep する。**

---

- `engine`: シミュレーション本体。描画・通信を一切知らない。`NewWorld(Config)` で生成し、`Step()` で1tick進める。読み出しは `Agents()` / `Foods()` / `Stats()` / `Tick()` / `AgentByID()` / `Opinions(id)`。

- `engine.Config`: 全パラメータのフィールド化。テストはここを1つずつ潰して各ルールを分離して検証する（例: `MutationStd = 0` で突然変異を止める、`RiskDecayPerTick = 0` で忘却を止める）。

- 種族: human と enemy の2種族。**同じノード構造・同じ意思決定エンジン**で、違いは予算の抽選範囲と食性だけ（enemy のほうが大きく、肉しか食べない）。求愛は同種内のみ。異種族は効用式に「倒せば肉になる相手」として載る（`Perception` の `AgentView.Prey` / `Meat`）。外敵は繁殖もするが、この広さでは捕食者だけで安定しないので地図の外から一定間隔で入ってくる（`EnemySpawnTicks`）。

- **Tiled で描いた地図を読む（2026-09-19、`engine/tiled.go` / `engine/regionshape.go`、`cmd/devview -tiled`）**: **`.tmj`（Tiled の JSON）を読んで、タイルレイヤーを地形に、オブジェクトレイヤーの矩形を地域にする**。**`engine` はファイルを知らない**——**バイト列を受け取って `Config` が要るものを返すだけ**で、**ファイルを読むのは devview（将来はブラウザの fetch）の仕事**（`save.go` と同じ立場）。**読むのは2レイヤーだけ**で、**それ以外（装飾レイヤー・余分なタイルセット・独自フィールド）は全部無視する**。**タイルが何の地面かはタイルセットのタイル自身のプロパティが言う**（`kind` ＝ flat / rough / water / high / slope、`height` ＝ 1〜9）——**描いていないタイルと空のセルは平地**なので、**地図はいくら飾ってもよい**。**回転・反転のフラグは落とす**（描き方の話で、engine の話ではない）。**読めないものは2つだけ**（**圧縮されたタイルレイヤーと、別ファイルのタイルセット**）——**どちらも Tiled の選択肢であって必須ではなく、読むには圧縮の依存かファイルアクセスが要る**ので、**エラーメッセージで「Tiled 側でこう保存し直せ」と言う**。**地域は自由形状になった**（`Config.RegionShapes`。**空なら今までどおり `RegionCols` × `RegionRows` の等しいブロック**）——**矩形は地図に対する割合（0〜1）で持ち**（同じ絵がどんな大きさの世界でも同じ country を表す）、**描いた外側は「それ以外の場所」という1つの地域**になり、**重なったら後の矩形が勝ち**（描画ソフトと同じ）、**各矩形は `shelter` / `food` / `special` / `enemies` を持てて 0 は「世界が抽選したまま」**、**そして `goal` の印を持てる**（**engine は1度も読まない**＝`World.GoalRegions()` で取り出せるだけで、クリア判定はゲーム側。**配ったスナップショットが自分のゴールを連れて行く**ための場所）。**位置から地域を引くのは O(1) のまま**（200×200 の索引表を世界を建てるときに1度作る。**解像度は `Config` に置かない**＝世界の規則ではなく測る側の目盛りと同じ立場で、空間インデックスのセル幅と同じ理由）。**実装前に数えて設計が決まった**: **`regionIndexAt` は1tickに3〜10回しか呼ばれない**（＝**索引の速さは守るべきものではなかった**）、**地域数に比例するのは `worthOfRegion`**（12地域で15回/tick、108で122、768で**1,900**）**と1体あたりの記憶**（**48バイト × 地域数**＝12地域で576B、768地域で36KB）、**そして個体数は地域数では動かない**（6シードで 30〜53 のばらつきの中）。**この最後の1つは1シードでは逆に見えた**（89 → 48 → 7 と崩れるように見えた）＝**単一シードで見た「崩壊」は雑音だった**。**同じ日に「発生タイル」の層も足した**（`Config.SpawnMap`、`engine/spawnmap.go`）——**2枚目のタイル層を1セル1文字で塗ると、そこにしか湧かなくなる**（`p` 植物／`f` 魚／`e` 外敵／`F` 植物と魚／`*` 全部）。**意味はタイル自身の `spawn` プロパティ**なので、**地形と同じタイルセットで両方描ける**。**量は1ミリも変えない**——**`FoodSpawnRate` が何本生えるかを決めるのは今までどおりで、この層は「どこに」だけを言う**＝**段階15a の総量保存が塗られたタイルの中で閉じる**（**塗った世界と塗らない世界で同じ本数が生えることをテストで固定**）。**陸に塗られた魚は無視する**（拒否ではなく無視＝**段階42 の「魚を生やすのは水の中だけ」を絵に壊させない**）。**外敵について塗るのは「到着する場所」**で、**子は親のところで生まれる**。**何も塗られていない2枚目の層は「塗っていない」と同じ**（飾りのための層で世界が止まらない）。**実装は既存の形をなぞっただけ**——**セルの一覧を世界を建てるときに1度作り**（`w.water` と同じ）、**引くのは `rng.Intn(len(cells))` と一様な位置の2回**（重みつきの地域抽選と同じ回数）。**受け入れ条件は段階21 と同じ形**——**描いた世界と、同じことを手で書いた世界が、500tick 走らせて1ビットも違わない**（テストで固定）。**保存と読込にも乗る**（`RegionShapes` は `Config` の一部なので保存され、**索引は読込時に作り直す**＝地形と同じ「保存せず導出する」扱い。**テストを書いて初めて、読込時に索引を作っていない欠けが見つかった**）

- **商売がどこで成り立っているかを測る（`engine/trade.go`、段階75）** — **規則ではなく測定**: `World.Trade()` が、**調理済みの品が人手に渡った経路**（贈与／売買）と、**渡された側がそれを自分で作れたかどうか**、そして**断られた組が再会したときに成立に転じたか**（回数・間隔・売り手の2つの図のどちらが動いたか）を返す。**既存の手渡しと売買の行に相乗りするだけで、世界に書き込まず乱数も引かない**（テストで固定）。**同じ回に `willSell` を `saleTerms` に割った**（比較の2つの辺を別々に返すだけで、比較そのものは同じ式。**両方とも売り手の数字**——買い手には閾値が無いので、**断りが成立に転じることは常に売り手が考えを変えたということ**）。**測定で2つの前提が崩れた**: **調理は「移動では解決できない欠乏」ではない**（人手に渡った調理品のうち受け取った側が自分では作れなかったものは **0.00** ＝**`CookQuality` の既定が 1 なので腕前に差が生まれようがない**＝**測っているどの地図も調理を技能にしていない**。地図の作者がそうした世界を足しても **0.06 \*\*** どまりで、**上回った量の平均はゼロ・個体数 −13.92 \***＝**段階38 の上限の式どおり**〈保有率 0.09 × 実効値 0.16〉）／**決裂は最終**（再会 121.04 回に対し成立に転じるのは **0.08** ＝ **0.07%**）。**そして断りの89%は同じ組の訊き直し**〈135.58 回の断りのうち 121.04 が再訪＝**別々の組は 14.5 組・1組あたり 9.3 回・間隔 15.3 tick**＝**買い手はたった今断られた相手に、歩き去らずにもう一度訊いている**〉＝**`salesRefused` を単独で読んではいけない**（初回の断りは `salesRefused − saleMet`。**段階68 の −18.62 \*\* も「訊く回数が減った」ぶんを含む**）。**逆向きの発見が1つ**: **成立した売買 1.88 のうち 57% が調理済みの品**（持っている身体は9%）＝**今あるわずかな市場は調理品の市場で、買い手は選んでいて売り手が惜しんでいる**

- **手が塞がっているとき、塞いでいるのが何かを測る（`engine/carry.go` の `CarryUse.Full` / `Blocked`、段階91）** — **規則ではなく測定**: **手に空きが無い身体の割合**と、**そのうち飾り物が枠を取っている割合**。**枠が何を数えているかを item ごとに訊く**（`slotsTaken` と同じ問いなので2つが食い違えない）ので、**`CarrySlotsWeigh` が入った世界では飾り物の `Blocked` は構造的に 0**——**それがこの測定の存在理由**（「飾り物が手を塞ぐ」が、その腕で起きうることなのかを先に言う）。**世界に書き込まず乱数も引かない**（テストで固定）

- 両岸を測る（`engine/banks.go`、段階37）— **規則ではなく測定**: `World.Banks(divideX)` が世界を縦の線で割って、**両岸がどれだけ互いを見ているか**（`crossShare` ＝視界に入っている組のうち線をまたぐ割合、`crossIndex` ＝岸を無視して組にしたときの期待値で割ったもの、**`crossDry` ＝水の上に立っている者を除いた同じ値**）と**両岸がどれだけずれているか**（`bankGeneGap` ＝予算比のベクトルの全変動距離、`bankCountryGap` ＝同じ地域についての信念の差／信念の平均）を返す。`BankTracker` は同じ集団を追って **`bankMoves`（線をまたいだ回数）と `bankBoth`（一生のうち両岸に立った個体の割合）** を返す。**線は測る側が与える**（川を抜いた対照には線を導ける地形が無く、対照は腕と同じ物差しで測らなければ比べられない）。**地域グリッドは川に合わせて描き直さない**（#61。地形と地域が別の地図であることは段階22 で確認した設計）。**数えるのは人間だけ**（外敵は場所ではなく獲物についていく）。**世界には一切書き込まず、乱数も引かない**（テストで固定）。**測定結果**: 川は**視界だけ**を分ける（`crossDry` 0.17 → 0.01、幅を視界より広げると 0.00 ＝下限）が、**集団は分けない**（`bankGeneGap` +0.01、`bankCountryGap` −0.00、`gapRel`・`halfLife` も動かない）——**水の上の14%が両岸を同時に見ており**、**一生のうち両岸に立つ個体が半分いる**（`bankBoth` 0.53。池の対照 0.48 より**多い**）。**あるべき状態 B〜E は地理では達成されない。**

- 血統: 子は `ParentIDs`、親は `ChildIDs` を記録する。

- 乱数は `World` が持つ `*rand.Rand` 1本。同じ `Config`（同じ `Seed`）なら常に同じ結果になる。コントローラも `Perception.Rand` 経由でこれを使う。

- 意思決定トレース（`engine/trace.go`）: `Decide()` 1回分の記録。「どのトリガーで呼ばれたか（`Trigger`）」「比較した候補ごとの効用の内訳（`Utility`：目的ごとの `Goal{Value, Chance}`、リスク・体力コスト・時間コスト）」「頭の良さによる評価ノイズ（`Noise`）と実際に比較したスコア」「選ばれた行動」を持つ。効用の合計は `Utility.Total()` ＝ Σ(Value×Chance) − Risk − VitalityCost − TimeCost で、効用式の唯一の実装でもある（トレースが式とズレようがない）。

- トレースは**追跡対象に指定したノードだけ**記録する。`World.TrackDecisions(id, true/false)` で開始・停止、`DecisionTraces(id)`（古い順、直近16件）と `LastDecisionTrace(id)` で読み出す。記録はノードの死後も残る（死に際に何を考えていたかが一番読みたい）。指定していないノードは何も記録しない。

- 再判断トリガーは `Trigger` として名前が付く（spawned / target lost / goal reached / attacked / vitality drop / idle / food in sight / bond ended / controller set）。`AIController` 以外のコントローラ（将来の人間操作）でも、トリガーと最終行動だけは `engine` 側が記録する。

- 挙動の指紋（`engine/golden_test.go`）: 既定条件・シード1〜3を5000tick回したときの個体数・出生・死亡・戦闘数・世代数と平均値を固定値で押さえたテスト。**「速くするだけの変更」が世界を変えていないことを、同じバイナリ内の比較では証明できない**ために置いてある（2026-09-04 の記憶キャッシュがまさにこの用途で、**数値を1つも書き換えずに通ったことが挙動不変の証拠**になった）。ルールを意図して変えたときは、その変更と同じコミットで数値を更新する（赤いテストを緑にするために書き換えない）。

- テスト: `engine/world_test.go`（ルールごとの単体テストと、8000tick回す統合テスト）と `engine/decision_test.go`（シナリオテスト）。後者は状況を手で組み立てて `Decide()` を1回呼び、選ばれる行動をassertする（格上に守られた食料／格下との食料争い／逃げ場のない被攻撃／満腹で消耗している／餓死寸前で求愛を検討すらしない、など）。効用の内訳やそもそも候補に挙がったかまでトレース経由で確認しているものもある。

- ベンチマーク: `engine/bench_test.go` に `BenchmarkEngineStep` / `BenchmarkEngineStepCrowded` / `BenchmarkDecide`。

- 空間インデックス（`engine/grid.go`、非公開）: 一様グリッド。ノードと食料をセルに登録し、「この近くに誰がいるか」を全体走査せずに答える。近傍を訊く3か所（`perceive()` の他個体と食料、`nearestFoodInSight`、`exchangeReadings`）がこれを通る。**世界のルールを何も変えない**（同じシードなら1ビットも変わらないこと）のが唯一の条件なので、セル幅は `Config` ではなく `PerceptionRadius` から導出する。**インデックスは差分更新せず、移動・出生・死・食料の増減で「古い」印を付けて、次に問い合わせが来たときにまとめて作り直す**（1tickあたり実質2回）。返す候補は**必ず添字の昇順**——知覚は他個体ごとに乱数を引くので、走査順は同じシードが再現するものの一部だから。**移動ループの途中で問い合わせると毎回作り直しになる**ので、動かす前か後に訊く（実測で1tickあたり1.05回）。**個体数が数百のうちは全走査のほうが速く、効き始めるのは500〜600体から**（数値は `HISTORY.md`）。

- `engine.World.Clusters(linkDist)`: 集団の構造（単連結の連結成分。クラスタ数・サイズ分布・最大成分の割合・個体ごとの所属ラベル `Labels`）。読み取り専用の解析で、ノードは集団IDを持たない。連結距離は `engine.DefaultClusterLinkDist = 30` 固定（`Config` に入れない＝世界のルールではなく測る側の目盛りだから。距離が違う測定値どうしは比べられない）。`Spacing()` と同じく O(n²) なので間引いて測る。

- `engine.World.ClusterGaps(linkDist)`: 集団間の距離分布（各集団から最も近い別の集団までの最短距離。平均・中央値・下位1割・密度で割った相対値）。単独個体は集団としても対象としても数えない。**連結距離より短い値は原理的に出ない**（それ以内なら同じ集団になるため）。相対値は**両端を較正済み**（構造なしの配置＝0.98、格子状に避け合った配置＝1.92）なので、1未満＝偶然より寄り集まっている、1超＝避けている、と読める。**ただし `gap`（絶対）と `gapRel`（配置）は別のことを言う**——避ける規則を強くすると個体は離れるが集団の数も減るので、分母（その数の集団を無作為に置いた間隔）が分子と一緒に上がり、`gap` が38%動いても `gapRel` は動かない（2026-09-05）。**規則が密度そのものを動かすときは、正規化した指標だけを読まない。**

- `engine.MembershipTracker`: 同じ顔ぶれが一緒に居続ける時間（membership half-life）。一定間隔で `Observe(w)` を呼ぶと、同じクラスタにいた**2体の組**が何tick後まで同じクラスタに居続けるかの生存曲線を貯め、半減期を返す。クラスタは合体・分裂するので「同じクラスタ、のちほど」は定義できないが「この2体はまだ同じクラスタか」は定義できる、というのが組で測る理由。**片方が死んだ組は離れたと数えない**（在籍時間ではなく寿命を測ってしまうため）。世界には一切書き込まない。

- `engine.FightTracker`: 戦闘を「相手が誰か」で分ける。**素直な「集団内戦闘率 ÷ 集団間戦闘率」は測れない**（打撃が届く `CombatRadius` はクラスタの連結距離より短いので、殴り合う2体はつねに同じクラスタにいる＝集団間戦闘は稀ではなく不可能）。代わりに、同じ遭遇（`CombatRadius` 以内にいる組）を「`DefaultCompanionLag` tick前から同じクラスタにいた組（仲間）」と「そうでない組（よそ者）」に分け、**遭遇あたりの**戦闘率とその比を出す。比が1を下回るほど「仲間とは争わない」。世界には一切書き込まない。

- `engine.CensusTracker`: 種族ごとの個体数。一定間隔で `Observe(w)` を呼ぶと直近 `DefaultCensusWindow`（5000tick）の窓の中の**種族ごとの平均・最小・最大**を返す。1tickの数え上げでは共存しているかどうかは決まらない（あるべき状態Aが窓の平均で書かれているのはそのため）ので窓で持つ。読むのは振れ幅ではなく **Trough（窓の最小値 ÷ 平均）＝振動の谷が0にどれだけ近づいたか**。振動は許容されるが、谷が0に触れた種族だけは戻ってこない（移入が無いので0は吸収状態）。**絶滅は窓ではなく実行全体で覚える**（窓が死を通り過ぎると見えなくなるため）。種族の一覧は持たず、実際に現れたラベルを数えるだけなので、段階11 で種族が増えてもこのファイルは触らない。世界には一切書き込まない。

- `engine.Spacing()`: 個体の散らばり具合（視界内の他個体数・最近傍距離・一様分布と比べた集まり具合）。`Stats()` と別なのは O(n^2) だから。協力を入れる前後で「群れているか」を測るために用意した。

- 世界を外から変える（`engine/edit.go`、段階22）: **`SetTerrain` / `SetRegion` / `Tune` / `SetDifficulty` / `Inspire` は `Endow` と同じ立場**——**シミュレーションの側からは誰も呼ばない**（規則も、コントローラも、出生も）。**乱数を1つも引かない**（エディタで敷いた世界が、設定ファイルで敷いた世界とまったく同じに走るため）。**個体群には触らない**（地面を変えるのと個体を動かすのは別の行為で、後者は `Repopulate`）。**世界の建て方の規則を再適用しない**（地形と食料の結びつけ〈段階33〉は世界を建てるときの規則で、**最初の編集からあとは地域は管理者のもの**）。**調整できるルールは6つだけ**（#50。食料・予算・予算のばらつき・競争心・戦闘の見積もり長・突然変異率）で、**それぞれ測定済みの範囲を持ち、外れた値は「拒否せず警告する」**——動かない世界を作る自由は管理者にあるが、それを作っていることは知らせる。**難易度は予算だけ**（`Difficulties`。`measured` が `HISTORY.md` の全数値が取られた世界そのもの）。**`Inspire`（2026-09-08）は天才イベントを手で起こす**——**天才の出生と同じ2つ**（学んだことを置く枠を1つ増やす／すでに持っているスキルを跳ね上げる）**だけを、乱数を引かずに**行う。**無いカテゴリは発明しない**し、**新しい思いつきも引かない**（引くと編集が世界の次の一手を変えるため。**空いた枠は誰かの思いつきが埋める**）。**枠の代金は `Endow` と同じく新しい予算**。

- 保存と読込（`engine/save.go`、段階21）: **世界まるごと**（`Config`・地形・地域・食料・全個体の記憶と信念とヒント・`tick`・乱数の位置）と、**個体群だけ**（`Node`）の2つを JSON で出し入れする。**「他所で育ったパラメータの読込」「進めた世界の配布」「天才の配置」は同じ1つの機能の応用**（#48）。**受け入れ条件は指紋テストと同じ形**——保存 → 読込 → N tick が、保存せず N tick と**1ビットも違わない**（500tick 先まで比較。**保存漏れは差分として必ず出る**ので、ファイルどうしを比べるのではなくこの形で書く）。**乱数は「種と、いくつ引いたか」を保存して読込時に引き直す**——Go の `math/rand` の状態は取り出せず（`MarshalBinary` も `GobEncode` も無い）、**生成器を差し替えると記録済みの全測定値が再現できなくなる**ため。**5000万回の引き直しで0.2秒**（10万tick分より多い）。**形式は JSON**（読める・手で直せる。Go の float64 は往復で完全一致）。**コントローラは世界の状態ではない**（読み込んだ世界は全ノードがAI＝段階19 の線）。**個体群に持ち込めるのは「その身体が何であるか」だけ**（遺伝子・性別・種族・好み・信念・ヒント・体内時計）で、**他人の名前を含むものは持ち込めない**（記憶・血統・ペア・地域の知識＝別の世界ではその名前が誰も指していない）。**読み込んだ世界は自分の `Config` を連れてくる**（世界を記述するフラグは `-load` のとき無視される）。
