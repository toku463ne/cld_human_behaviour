- **水の中にいることが体力を取る（段階99、`WaterDrain` / `WaterDrainKnown`、`engine/terrain.go` の `soakOf`）** — **既定は0＝無効**（`cmd/devview -soak` / `-soakblind`）: **段階34 から段階98 まで、水は「移動への通行料」だけだった**（`WaterMoveCost` = 3.0 は `moveCostOn` を通り、**その課金は「動いた tick」にしかない**）ので、**川の中で立ち止まっている身体からは1ミリも取っていなかった**——**そして実測で、水の上の body-tick の 36.9% は身体が静止している**（段階97 が「立ち止まることだけが遅くならない」と測った穴の裏側）。**足したのはセルの性質1つ**（`terrain.Drain`。`Cost` / `Slow` / `Drown` と同じ置き場所）で、**`chillOf`（気候）には混ぜない**（気候は地域、水はセル、地図の作者が別々に設定する）**が、単位と入り先は同じ**なので `metabolise` では1つの引き算、効用式では **`placeDrain(s) = s.Chill + s.Soak`** として読む。**これで先読み（`pressures`）・休息の見積もり・食事の見積もりが新しいコードなしに読む**＝**段階85 がその経路をわざわざ作った理由がそのまま効いている**。**そして `recoverable()` は場所の目減りを引くので、「ここで休むこと」の値打ちだけが水の中で選択的に下がる**（テストで固定）——**これがこの段階が段階86〈寒さ〉と違うと言えた唯一の理由**で、**寒さは地域〈幅400〉なので歩いても寒いまま、水はセル〈幅77〉なので2歩で出られる**。**測定（96シード・基準 `riverswim`）: この鎖で初めて「知っていること」が行動を変え、それでも居場所は動かない**。**動いたこと**——**感じる腕は感じない腕より水の中で立ち止まる割合が低い**（0.37 対 0.38、**−0.02 \*\*\***）＝**段階34 の溺死・段階86 の寒さ・段階98 の泳げないことの値段は3度とも「知らない」対照と区別がつかなかった**ので、**初めての「選択」の痕跡**。**動かないこと**——**`onWater` は +0.01 \***（感じる腕と感じない腕の差は **+0.00**）、**個体数の差も誤差内**（+3.40 ± 6.12）＝**立ち止まるのを少しやめることと、水から出ることは別**。**そして場所に紐づけることに値打ちは無い**——**同じ量を世界じゅうに一律に配る対照（気候として 0.0074/tick。体力の総取り分は 9089 対 7315 で揃えた）と区別がつかない**（+4.31 ± 6.75）＝**段階98 と同じ結論の2度目**。**代価は用量が決める**: **回復速度（0.09/tick）の5分の1なら測定上タダ**（**+0.30 ± 6.54**、ただし餓死率 +0.38 \*\* と `dIntelligence` +3.71 \*\* は動く）、**半分で −17.56 \*\***、**回復を打ち消す量で −43.98 \*\*\***、**遊ぶ地図では割合として倍払う**（36.72 → 23.97 ＝ **−12.75 \*\***）。**そして水が集団に課している代価の大半はこの目減りではなく通行料のほう**——**`WaterMoveCost` を 1 にした腕は、同じ目減りを受けながら +22.76 \*\***（`wetStill` も 0.31 まで落ちる＝**立ち止まるのをやめさせたのは、休息を高くすることではなく移動を安くすること**）。**測定器の落とし穴を1つ見つけた**——**`swimWet` は「コスト1超の地面に立っている身体の泳ぎ」なので、`WaterMoveCost` = 1 の腕では測る地面が消えて 0.00 になる**（段階97 の `Wading()` の中立値と同じ型）

- **場所の天気（段階85、`ClimateMap` / `ChillDrain` / `engine/climate.go`）** — **既定は天気のない世界＝1ビットも変わらない**（`cmd/devview -cold`、`cmd/experiment` の `cold`）: **天気は地域の性質**（4×3 の地域に、地図の絵を各地域の中心で読んで入れる。**`.` と `1`〜`9`、文字は2つ目の天気のために予約**）。**セルに置かなかったのは、場所について学んで伝える仕組みが全部地域に乗っているから**（段階15b・15c・29・35）。**取るのは体力の目減りで、飢えとまったく同じ行**——**だから先読みは新しい規則なしに寒さを見る**（`pDrain` がそのまま読む）**し、それを打ち消すものは食料と同じ勾配で値段が付く**（この project で効いた規則＝治る肉・調理と同じ形）。**危険のうち「自分の代謝」の側に置いた**——**今入っている打撃は2つ目の窓へ持ち越さない**（段階67）**が、場所は身体が考えているあいだに暖かくならない**（テストで固定: 同じ量なら、寒さは2つ目の窓へ運ばれ、打撃は運ばれない）。**継ぎ目は2つだけ**（`chillOf`＝寒さが数になる唯一の場所／`wardsOff`＝**持っているものが天気にどれだけ答えるか。今は常に0**で、**形だけ決めてある**: 手の中のものの性質であること・**差し引きではなく割合**・**効用式ではなくここで読む**）。**編集と保存は段階21・22 の立場のまま**（`SetClimate` は乱数を引かず、地域ごと保存される）。**数を入れると（段階86）: 寒さは飢えと寒さが奪う体力の 60% を取るのに、身体は寒い側にいる割合が偶然どおり**〈+0.02 ± 0.02〉——**足元の寒さは全候補を等しく押し上げるので比較から約分される**。**「感じない」対照と区別がつかない**＝**効き目は全部選別**。**動かしたのは食料だけ**〈+0.11 \*\*\* / −0.24 \*\*\*〉。**代価は個体数 −19.11 \*\*・餓死率 +0.48 \*\*\***

- **足元の地面（段階57、`RegionAbilitySpread`）** — **既定はオフ**（0）: **実効値 ＝ 遺伝的素質 × 年齢補正 × 性別補正 × 足元の地面**で、**掛け算は `Agent.Ability` の1か所のまま**。**地面が動かすのは「今日この身体に何ができるか」であって「どれだけ入るか」ではない**——**上限（`MaxVitality` / `MaxSpeed` / 記憶の枠 / 手の数）は `Agent.capacity` を通って地面を読まない**（**上限が地面で動くと、境界を1歩越えただけで自分の上限を超えた体力を持つ身体ができる**。速さを外したのは段階20 の「倍率は速度ではなくコストに掛ける」と二重計上しないため）。**スキルとの唯一の違いは持ち歩けないこと**。**知覚に載るのは足元だけ**（`Self.Footing`。**規則は1つも読まない**）。**測定（48シード）: 何も動かない**——`standGain` +0.01 \*（**用量を倍にすると +0.00＝用量に応じない**）、`regionsSeen` は下がるどころか **+0.14 \***、`oneRegion` 不動。**実装前に数えた的は大きかった**（一生に世界の49%を歩く）ので、**「発火しない」型の失敗ではない**。**理由は約分**——**殴れる距離にいる組の100%、連結距離30 以内の97% が同じ地域**（地域は 200×200）なので、**その地域の全員に同じだけ掛かる倍率は、勝ち負けを決める相対的な比較から消える**。**そして対照のほうが世界を動かした**（`RegionAbilityCarried`＝同じ倍率を出生地から引いて持ち歩く＝スキルと同じ可搬なもの。強い用量で個体数 −8.40 \*、`halfLife` −9.38 \*\*、`dIntelligence` −6.82 \*\*）＝**遺伝しない当たり外れを身体ごとに配ると、選択そのものが薄まる**。**「居場所を動かせない」理由は、6度目にして可搬性ではないと分かった**。**続けて `RegionFavourSpread`（段階57c）で約分そのものを止めた**——**地域ごとに贔屓する遺伝子を変え、9本の平均を1に正規化する**（良い地域／悪い地域は作らない）ので、**同じ場所に立つ違う建て方は違う倍率を受ける**。**それでも並び替えは起きない**: **一番合う地域は平均より 7.63%／15.51% \*\*\* 良い**のに、**取れたのはその2%**（`suitGain` +0.32 ± 0.20 \*）で、**しかも出生地の好みを持ち歩く対照が同じ大きさを出す**（+0.30 ± 0.21 \*）＝**観測された並び替えは全部「自分に合う地域で生まれた身体が少し多く生き残る」ぶん**。**理由は一生のうちに平均されること**（一生に12地域のうち5.9 に立つ）。**そして「場所ごとに違う方向の選択は多様性を保つ」という古典的な予想も外れた**（強い用量で `sdPower` −1.65 \*・`sdIntelligence` −1.21 \*＝**薄まる**）。**2つの形で2つの別の壁に当たり、共通の3つ目は「効用式が移動先の地面を知らないので、離れることに値段が付かない」こと**

- 水は死ぬことがある（`engine/terrain.go` の `drownings`、段階34）: **水のセルで過ごす1tickごとに、一定確率でその身体は終わる**（`DrownChancePerTick` = 0.0002。**既定は非ゼロだが、平坦な世界には水のセルが無いので乱数を1つも引かず、以前の測定値は1つも動かない**）。**地面そのものが命を奪う最初の規則**。**継続ダメージではなく即死の確率**——削り合いにすると防御で割ることになり**防御に2つ目の役目がつく**（#58）。**閾値は無い**（水に入るかどうかは効用比較のまま。足したのは `Utility.Hazard` ＝「その手が身体を水に留める見込みtick数 × 確率 × `LifeValue`」の1項だけ）。**死因は専用のバケツで、排他**（`Stats().DrownDeaths`。殴られていた身体が溺れたら殺しには数えない——`starved` は「他の死因が名乗り出なかったぶん」なので混ぜると全A/Bに紛れ込む）。**汎用のハザード表は作っていない**（#60。2つ目の危険な地面が出たときに共通化する）。**実装前に数えたら前提が1つ崩れた**——**個体は川を渡っておらず、川の中で暮らしている**（水の上が全tickの14.5%、1回の滞在が平均127tick・最長3143tick）ので、**「速い個体はサイコロを振る回数が少ないから報われる」は成立しない**（実測 `shSpeed` −0.01 \*\*＝むしろ買われなくなる。段階20 と同じ向き）。**測定（river、24シード×20000tick）**: 溺死は死因の11%、個体数 −17.3 \*\*、`killShare` −0.10 \*\*\*、餓死率 +0.27 \*、**総死亡数は不動**（溺死が殺しと餓死を置き換えた）、**しかし `onWater` は +0.00**。**一番の発見は、足元の危険を効用式から抜いた対照（`DrownKnown = false`）と有意差が1つも出ないこと**＝**この規則の効き目は全部「選別」で「選択」ではない**（罰は選択肢1つあたり 0.8 ＝ その個体自身の評価ノイズ 20 の25分の1。**重みを上げる道は無い**——5倍で個体数18・外敵が絶滅する）。**したがって「水を避ける」を作るのは段階35（危険を場所として覚え、伝える）であって、危険の強さではない**（段階14→15b→15c、段階29 に続く3度目の同じ形）。**地形アームは再ベースラインされた**（段階20・29・33 の `river`/`country` の数値は「溺れない世界」のもの＝対照アーム `riverdry`/`countrydry`）。

- 溺死は伝わる（`engine/regionlore.go` の `danger` と `witnessDrowning`、段階35）: **地域ごとの信念の2本目**（その地域で1tick過ごすと死ぬ確率）。**#53「地形の信念は1スカラー」への意図的な例外**——#53 が禁じたのは**地面の種類ごとの信念**で、これは**帰結の種類ごとの信念**（何を奪われるか／出てこられるか）。荒れ地と川はどちらも高く、片方だけが殺す。**知る道は3つで、どれも既存の形**: 立つ（足元の危険を訪問の平均に畳み込む＝段階29 と同じ）、**見る**（視界内で誰かが溺れると、見ていた全員が**死んだ場所の地域**について**被害者の足元の真値**を `DrownWitnessLooks` = 20 回の「見た」ぶんの重みで取り込む）、聞く（`exchangeRegions` に相乗り）。**減衰なし**（コストと同じ率を共有）、**記憶の枠は食わない**、**効用式への入り方は段階29 と同じ**（門は食料の記憶の鮮度、順位だけ変わる）。**値付けに新しい定数は無い**（危険 × `RegionDangerTicks` = 700 × `LifeValue` ÷ `RegionDrawValue`＝段階34 の式を食料の単位に戻しただけ）。**測定: 知ることは起きる。ただし伝えなければ起きない**（信念と真値の相関 0.77／細かい地域では 0.98。**目撃だけで伝承を切ると 0.33 ＝「立つだけ」の 0.37 と同じ**——溺死1件の目撃者は6.3人でも一生に見るのは1件あるかないかなので、**地図に変えているのは伝承**）。**しかし行動は変わらない**（`onWater` +0.01 \*、**溺死はむしろ +3.75 \***）。個体数は +14.5 \* 上がるが、**信念が不正確な腕でも同じだけ上がる**＝効いているのは知識ではなく「どこかの評価が下がって遠出が減ったこと」。**理由を4つ潰した**: 重み4倍でも粒度9倍（108地域・相関0.98）でも川を世界の端に移しても `onWater` は動かず、**「良い地面へ行く」手は全決定の7%も選ばれている**（`drawShare`）。**残ったのは食料**——**段階33 の設定（行きにくい地面は痩せている）を入れた世界でだけ溺死が17%減る**（−4.33 \*\*、代価は個体数 −6.9 \*）＝**段階33 の結論（避ける理由と食べる理由が別々の地図に乗っているかぎり、避けることは食料を捨てること）が危険についても成り立った**。**目撃者スキャンは共通化していない**（#60。段階31 が2つ目の実例なので、切り出すのは31 の側の仕事になった）。

- 地形の下ごしらえ（`engine/terrain.go`）: 移動の体力コストが `w.moveCostOn(x, y, effort)` → `w.terrainAt(x, y)` を通る。**今は世界じゅうが `flatGround`（コスト倍率1）を返すので挙動は完全に不変**（指紋テストが無変更で通る）。狙いは**速さに「有利な場所と不利な場所」を作ること**——速さは9本で一番買われている遺伝子（予算比0.230）なのに何とも取引していないので、「速くて脆い／遅くて頑丈」が並存しない。**倍率は速度ではなくコストに掛ける**（速度を落とすのは effort がすでにやっていることで、二重にすると測定で区別できなくなる。またコストにすれば、荒れ地を速く渡ることが速さと体力の取引そのものになる）——**2026-09-18（段階97）に水だけがこの禁を解かれた**。**解けた根拠は対照アーム**（`waterslowfree` ＝ 遅いが高くない水は単独で効くので、速度の倍率と effort は区別できる）**と、2つ目の理由が3度反証されていること**（段階20・33・57 が `speedGap` 0.00）。**他の地面には今も速度の倍率を置いていない**。**地域ブロック（段階14）とは別物**——地域は「世界が何をくれるか」の単位、地形は「移動が何を要求するか」の地図。**コントローラは今も平坦だと思って計画する**（`Perception` に地形は載っていない）ので、この食い違いを埋めるかどうかは地形本体の段階で決める。

- **地域を塗る（2026-09-20、`engine/regionshape.go` / `engine/tiled.go`、`Config.RegionMap`）**: **地域の描き方が2つになった**——**矩形**（2026-09-19 から）と、**1セル1文字で塗る**（`Config.RegionMap` ＋ `RegionShape.Key`）。**塗ったほうが強い**: **どんな形でもよい**（L字、分かれた谷、曲がった岸）**のに対し、矩形は矩形にしかなれない**。**矩形を残したのは「西の4分の1」を1行で言えるから**で、**片方が他方の劣化版だからではない**。**両方が同じセルについて言っていたら塗りが勝つ**（**セルを塗るほうが、そのセルについて細かく言っている**）。**塗られていないセルは「それ以外の場所」**（矩形の外側と同じ）。**Tiled では `region` プロパティ（名前）を持つタイルで塗った層**で、**同じ名前のタイルはどれだけ離れて塗っても1つの地域**（`shelter` / `food` / `special` / `enemies` / `goal` も同じタイルが持つ）。**タイル層の役割は順番ではなく中身で決まるようにした**——**地形だけが「最初の層」**で、**それ以降は地域を塗っていれば地域、湧く場所を塗っていれば発生タイル**（**2026-09-19 の「2枚目＝発生タイル」のままでは、地域だけ描いて発生タイルを描かない地図が誤読される**）。**地形が中身で決まらないのは、1枚のタイルが「何の地面か」と「何が湧くか」を同時に言えるから**（魚の湧く水タイル）で、そこには見分ける手がかりが無い。**engine 側は `TerrainMap` / `SpawnMap` と同じ「1セル1文字＋凡例」の形**に揃えた（凡例＝`RegionShapes` の `Key` と数字）。**位置→地域は O(1) のまま**（200×200 の索引表に塗りを書き込むだけ＝**矩形が安かったのではなく、索引が最初から形を選ばなかった**）。**世界の規則は1つも増えていない**——**塗らない世界は1ビットも変わらない**（テストで固定）。**同じ日に、描かれた地域を見えるようにした**: **`World.Regions()` が返す枠を、地域が描かれているときは実際の位置から作る**（それまでは `RegionCols`×`RegionRows` の格子の枠を返していて、**描いた世界では嘘だった**）。**塗られた地域の枠は「その地域を囲む箱」**（L字を囲む箱は L字ではない＝**正確な答えは `regionIndexAt` だけ**という断り付き）。**`cmd/devview` は描かれた世界では地域を格子ではなく格子状に問い合わせて塗る**（`World.DrawnRegions()` で分岐。120列の粗い格子＝**見せたいのは「地域がどこまで届くか」であって縁の1ピクセルではない**）

- **豊かさを塗る（2026-09-20、`engine/rich.go`、`Config.RichMap`）**: **「どこに食料が生えるか」を、地域（＝信念の粗い区画）から切り離した。** **既定はオフ**（塗らなければ1ビットも変わらない。乱数も1つも余分に引かない＝テストで固定）。**凡例は1セル1文字で桁÷5**（`5` 普通・`0` 不毛・`9` 豊か）で、`TerrainMap` / `SpawnMap` / `RegionMap` と同じ形。**触ったのは2箇所だけ**——**どの区画に生えるか**（`pickFoodRegion` の代わりに、塗りの重みでセルを引く）と、**`richnessAt`**（`seedFrom` が「どの株の子か」を重み付けるのに使う）。**塗ると世界の側の重み付けは走らない**（`FoodSpread` を引かず、地形との相関と水辺も動かない）——**作者が言ったことに二つ目の答えを足さない**ため。**地域には塗りの平均が入る**ので、**地域を読む側（信念・スキル・寒さ）は今までどおり粗い区画を読み、しかも本当のことを読む**。**総量は変わらない**（`FoodSpawnRate` のまま。テストで固定）。**Tiled では `rich` プロパティ**（0〜2の数。**発生タイルと同じ層に載せてよい**＝1枚のタイルが「どこに」と「どれだけ」を同時に言える）。
  - **形を決めたのは実装前の数え上げだった**（`PLAN.md` P16-2）。**題は「豊かさグリッドを細かくし」だったが、細かくするのは測定上は逆向きの操作**——**48区画・108区画にすると `richGain` が 0.07 → 0.03/0.04 と半減し（どちらも \*\*）、48 と 108 は区別がつかない**。**区画が視界（130）より小さくなった時点で効果が失われ、それ以上細かくしても変わらない**（どこに立っても複数の区画が視界に入り、身体が経験する豊かさが世界平均に近づく）。**既定の12区画（200×200）だけが視界より大きい。** **したがって作ったのは「細かいグリッド」ではなく「作者が塗れるグリッド」で、既定の粒度は変えていない。**

- **寒さと防寒着（2026-09-20 の測り直し。規則は1行も足していない）**: **段階86 が「寒さは居場所を動かさない」と測り、段階87a が防寒具を作り、2026-09-20 にその2つを殺す強さの寒さで合わせた。** **`ChillDrain` 0.02 では寒さは誰も殺さないので防寒着は何も動かさない**（`coat` / `coatfull` / `coatwarm`。24シードで `pop` +7.25 ± 11.14 ＝誤差の中）。**0.05 にすると全部が動く**（24シード・対の差）: **`pop` +42.54 \*\*\***（41.5 → 84.0）／**`collapsed` −0.29 \*\*\***（0.50 → 0.21）／**`starveRate` −2.06 \*\*\***（3.83 → 1.77）。**寒さは飢えを通して殺していた**ので、防ぐと餓死が減る。
