## 1. 作る値打ちはある——**大きい関係の4分の3は、効用式が書いていない**

**目盛りについて1つ訂正しておく。** **`corrNoise` は「1つの候補を採点するときにこの身体が乗せる誤差の標準偏差」**で、走行中に測って 10.4〜11.4（`ChoiceNoise` 20 の世界なので上限20、平均その半分あたり）。**`controller.go` の `addWarmth` のコメントにある「評価ノイズ 139」は別の量**（同じ決定の候補の散らばりの側）なので、**この2つを混ぜて読まないこと。** 以下で「大きい」と言うときの目盛りは前者。

**この項目の門は `corrUnwritten` で、通った。** **判定は「その鍵で決めたときに期待できる値打ち（起きたときの値打ち × 起きる頻度）に対して、効用式がその手に付けていた期待値が半分に満たない」**こと。**二重計上にならない関係が、どの世界でも32〜40本ある。**

**この判定は2度書き直した。そして2度とも、直すたびに数が減った。** **最初に出した 145.6 / 141.0 / 167.3 は、両方の誤りを含んでいる。**

1. **比べる相手が「生命の項」だけだった。** **そのせいで「求愛 → 子」が必ず『書いていない』側に落ちた**——**求愛は体力を払って子を買う手なので生命の項は負**だが、**式は子を `Offspring` でちゃんと値付けている**。**全ゴールの和と比べるように直して 145.6 / 141.0 / 167.3 → 128.9 / 122.8 / 148.5**
2. **桁が揃っていなかった。** **`Value` は「そのイベントが起きたときの値打ち」で、`Pred` は「値打ち × 確率」の期待値。** **うまくいった求愛が子1人ぶんの値打ちを持つのは当たり前**で、**それを「うまくいくかどうか分からない求愛」への期待値と比べれば、世界中のどの関係も『書いていない』ことになる**。**両方を期待値にして 128.9 / 122.8 / 148.5 → 38.1 / 31.9 / 40.3**

**2度目の直しで4分の1になった。** **門は通ったまま**だが、**「大きい関係の75〜80%が未知」と最初に書いたのは間違いで、正しくは「身体が頼れる関係（`corrActed` 86〜100本）のうち37〜41%」。**

**ただし `corrVarying` は4分の1しかない**（50〜54 / 181〜209）。**残りは自分の状態から引く鍵で、同じtickのどの候補にも同じ値が乗る**——**行動どうしは区別するが、同じ行動の相手違いは区別しない**。**段階86 の「全候補を等しく持ち上げる項は誰も動かさない」に半分だけ当たる。**

## 9b. 逆伝播——**物に値打ちを戻すと、硬貨と肉が浮き、植物が沈む**（2026-09-23・ユーザの提起）

**ユーザの案**: **合成は中間項を落としてしまう**（「掲げる → 硬貨 → 食べた」を合成すると硬貨が消える）**ので、良い結果に至ったリンクに登場した物のほうに点を配れば、物への値打ちがそこで生まれるのではないか。** **悪い結果には減点する**（**ユーザ自身の「片側だけ学ばせない」という規則をこの案にも適用した**）。

**これは合成の追加ではなく代替**（両方やると同じ食事を2度数える）で、**しかも桁違いに安い**——**鍵空間ではなく物の種類8つ**。**そして合成で消える中間項が戻る**ので、硬貨を拾う・捨てない・渡さない理由がちゃんと式に残る。

**計器に足して測った**（物が手に入ってから窓の中で起きたイベントの値打ちを、符号つきで走る平均。`Gain` は**どのイベントも平均するといくらか**からの差）:

| 物 | 手に入った | 手を離れた | `Gain`（`countmarket`） | `Gain`（30tick窓） | `Gain`（平坦） | 手にとどまる |
|---|---:|---:|---:|---:|---:|---:|
| **硬貨** | 999 | 270 | **+0.89** | **+1.23** | — | 578 |
| **肉** | 129 | 124 | **+0.46** | **+1.76** | **+1.67** | 154 |
| 飾り物 | 4361 | 698 | +0.02 | −0.06 | — | 442 |
| **植物** | 751 | 722 | **−1.03** | **−1.41** | **−0.24** | 298 |
| 皮・魚・本・石 | 0 | 0 | 0 | 0 | 0 | — |

**機構は働く。** **符号も順序も筋が通っている**——**肉は一番大きく**（飢えた身体を一気に戻す＝段階39 の `MeatHeal` がそのまま出ている）、**硬貨がそれに次ぎ**、**植物は負**（持っている＝まだ食べていない＝空腹のまま歩いている）。

**ただし用量が小さい。** **`corrNoise` 10.4〜10.6 に対して最大 +1.76**——**評価誤差の6分の1**。**そのままの重みで効用式に足しても、段階86 の寒さと同じで誰も動かない。**

**そして交絡がある。** **硬貨を持っている身体は「手が空いていて、飢えていない身体」**でもあるので、**硬貨が良い結果を引き起こしたのか、良い状態の身体が硬貨を持てるのかを、この計器は分けられない。** **本体を作るときは「同じ物を同じだけ拾うが、値打ちは決定に届かない」対照**（`lessonblind` 形）**が要る。**

**皮がゼロなのは規則がオフだから**（`WardNeedsHide`）。**「皮 → 防寒着 → 寒さが止まった」という、この世界で報酬が確実にある鎖はまだ測っていない**——**次に測るならそこ。**

## 9c. 合成——**素朴にやると桁を間違える。原因は基底率の掛け算**

**（状況, 手）→ B と B → C をつないで（状況, 手）→ C を作り、同じ三つ組を直接観測した値と突き合わせた。** **`Direct` を持っているのがこの検定の全部**で、**合成が直接観測と合わないなら、それは世界に無い規則を身体に持たせることになる。**

**最初の素朴な合成は、直接観測の 13〜30倍を主張した。** 例: `closeness buy got thing safe` が**合成 431.67 に対し直接 0.00**。

**原因は算数で、もっと早く気づくべきだった**——**`pairs[b][e] / events[b]` は「b 1回あたり e が何回続くか」**で、**e が b よりずっと頻繁なら、この比は基底率そのものになる**。**「硬貨1枚のあとに回復が23回続く」は本当だが、それは回復が常に起きているからで、硬貨のせいではない。**

**基底率を超えた分だけを使うように直した**（`excess = 1 - before[b]/rate`）。

| 腕 | `corrComposeErr`（合成 ÷ 直接観測） |
|---|---:|
| `count`（平坦・窓700） | **1.36 ± 0.28** |
| `countmarket`（窓700） | 7.86 ± 5.81 |
| `countnear`（窓30） | 10.11 ± 8.17 |

**平坦な世界では合成は正直**（1.36倍）。**物が売り買いされる世界では8〜10倍に過大申告する**（誤差も大きい）。**理由は物のイベントが束になって来ること**で、**2つのリンクが独立という仮定が崩れる。**

**したがって合成を本体に入れるなら、(a) 基底率を引くこと、(b) 直接観測できる三つ組では直接観測を優先すること、の2つが要る。**
