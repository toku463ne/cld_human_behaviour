### コードを読んで確かめたこと（2026-09-20。**着手前の数え上げとは別で、これは「今どうなっているか」**）

- **殴打は全員が動いたあとに解決され、溺死の判定はそのあと**（`engine/world.go` の `Step`: `perform` → `resolveAttacks` → `metabolise` → `drownings`）。**押し込んだ先の水は、同じ tick のうちに効きます**——**新しい順序を作らなくてよい。**
- **`resolveAttacks` はループの中で空間インデックスに訊く**（20tick に1回、`exchangeReadings` → `appendAgentsInSight`）。**`moveDir` は `invalidateIndex()` を呼ぶ**ので、**押す処理を素直にそのループの中に書くと、そのtickは殴打ごとにグリッドを作り直します**（`CLAUDE.md` のコーディング規約が名指ししている形）。**押し先を溜めてループの外で一度に適用する**のが素直で、**攻撃の解決順に結果が依存しなくなる副次効果もあります。**
- **`canStep` は段差を拒む**（`engine/terrain.go`。**下りも `from.Slope` が無ければ不可**）。**したがって「崖から落ちる」はノックバックが `canStep` を無視しないと起きません。** **水は段差ではないので、押し込むほうは素直に通ります**——**1 の本命は水で、崖は付け足し。**
- **hunch は生涯学習しない。** 経路は3つだけ——`drawHints`（建国者の抽選）・`inheritHints`（親から枠ごと。天才誕生でだけ1枠まるごと差し替わる）・`exchangeHints`（**空き枠にだけコピー**）。**「自分の経験から新しい hunch を作る」経路はこの世界に1つもありません。** **2-2 はその1本目になります。**
- **hunch の状況（`HintFeature`）は8つで、全部 `Perception` から来る。** **「水の上にいる」も「殴られている最中」もありません。** **そして特徴を1つ足すと `drawHint` の抽選が変わるので、規則をオフにしても世界が変わり、指紋テストの数値は全部動きます**（`CLAUDE.md` の `numActionKinds` と同じ罠）。**足すなら意図した変更として、同じコミットで指紋を更新する。**
- **好意は「負」を受け付けない。** `addAffinity`（`engine/memory.go`）は **`amount <= 0` を黙って捨てます**——**`Opinion` の設計そのもの**（Risk ＝「この相手に何を払わされたか」、Affinity ＝「これは自分の側か」）。**3-2 はここに正面から当たります。**
- **3-1（外敵討伐を見た者の好意）はもう実装されている**——段階31b の `witnessKill`（`engine/witness.go`）で、**分岐は「自分と同じ種族の者が、別の種族を殺したのを見た」**、重みは `AffinityWitnessKill`（既定 2）、計数は `avengeSeen`、腕は `noavenge` と `avengehigh`。
- **死の目撃という走査も、もう2つ乗っている**（`forEachWitness`）——**殺し**（段階31）と**溺死**（段階35 の `DrownWitnessLooks` 20 ＝**既定オン**）。**「死亡イベントが視界内に発信される」は新規ではありません。**
- **死の直前の状況は、死んだ身体がもう持っている**——`attackerID` / `lastAttackTick`（殴られた相手といつ）・`drowned`・立っている座標（＝そこの地形）。**したがって「殴られている最中に、水で死んだ」という鍵は、誰にも輪バッファを持たせずに `kill` の時点で組み立てられます**（2 の設計で一番効く逃げ道。下記）。

### 1. 被弾ノックバック（#136。戦闘×地形の連動）

- **やりたいこと**（ユーザ原文の要約）: **殴られたら、打撃の重さ（攻撃力）に応じて攻撃者→被攻撃者の向きへ強制移動させられる。** **重い身体ほど押される距離が短い。** 狙いは「**殴られて水に押し込まれる → 溺死**」「**崖際で殴られて落ちる**」という戦術的な地形利用。
- **既にあるもの**: 殴打の解決と溺死判定の順序（上記）／水が「死ぬ場所・遅い場所・消耗する場所」であること（段階34・97・99）／**押された身体が考え直すトリガー**（殴られた・体力が減った）／**押された先の危険を効用式で読む経路**（`Perception.Self.Drown` → `Utility.Hazard`）。**つまり、押したあとに必要なものは全部ある。**
- **壊してはいけないもの**:
  - **移動ループの中でインデックスに訊かない**（上記。**押し先を溜めて、ループの外で一度に適用する**）
  - **効用式に「押されるかもしれない」という項を足さない。** **ノックバックは選べない結果として身体に起きること**（段階24 の隙・段階54 の怯えと同じ立場）。**避ける判断は、押されたあとに既存の `Hazard` が行う。**
  - **攻撃側有利を保つ**（`CLAUDE.md`）。**向きは同じ**（殴られる側のコストが上がる）**が、距離を取らせることは逃走の補助でもある**ので、**`fights` が減る向きにも働きうる**。両方見る。
  - **渡れない地形は作らない（段階20）の裏返し**——**押しが `canStep` を無視すると、歩いて行けない所へ暴力で行けるようになります**。**下りだけ許すのは筋が通るが、決定として書くこと。**
  - **ペアと子**（`PartnerID != 0` は `stepPaired` で連れ立ち、子は `keepToGuardian` で親の近くに留められる）。**押しがその拘束と矛盾したときの扱いを決める。**
- **着手前に数えること**:
  - **的の大きさ**（段階62 の式＝保有率 × 実効値 × 的の大きさ）＝**「押した先が水になる位置」で起きた殴打の割合**。**今の指標には無いので、計数を1本足して先に数える。** **`onWater` 0.08〜0.14 は上限の目安にしかならない**——**すでに水の中にいる身体を押しても新しいことは起きない。**
  - **押す距離の見当**: **1tick の歩幅（`speedAt`）と水域の幅の比**。**歩幅より短い押しは次の tick に歩いて戻れるので、たぶん何も変えません。**
  - **予想を書く**（測定前に）: `drowned` / `drownShare` が `river` と `countryskill` で上がる／`onWater` はほとんど動かない／**平坦な世界では1ビットも動かない**／`fights` の向き。
**決まったこと（2026-09-20・ユーザの判断＝決定事項#136）**

- **崖落ちを作る。** **押しは下りに限って `canStep` を無視する。** **上りは無視しません**——**暴力で高台に上がれるようにはしない**（段階20 の「渡れない地形は作らない」を、逆向きに壊さないため）。**落ちるのは一方通行で、戻るには坂を探すことになります。**
- **落ちたら追加ダメージ。** **落差（`height` の段数）に比例させ、殴打と同じ tick に、殴打の続きとして課金する。**
- **これで死因のバケツは1つも増えません。** `kill` は **`a.lastAttackTick >= w.tick-1` を戦闘死の条件にしている**ので、**落下で死んだ身体は自動的に戦闘死に入り**、`recentAttackers` に押した者がいるので **claim（段階41）も `witnessKill`（段階31）も既存のまま動きます。** **`CLAUDE.md` の「死因は排他」はそのまま。**
- **対して、押して溺れさせた死は `drowned` のバケツのまま**で、**`kills` にも `witnessKill` にも入りません**（`kill` は `drowned` を先に見る）。**つまり「押して溺れさせた者」は、14 の好意の連鎖には乗りません。** **乗せるかどうかは着手時に決める**（乗せるなら、溺死の witness 経路に「押した者」を渡す1行）。
- **落下ダメージの強さは「即死装置にしない」ことで決める。** **1発で死ぬ大きさにすると、崖は地形をやめて扉になります**（段階20 の線。飛行型に `FlyCost` を必ず払わせたのと同じ理由）。**目安は1打撃（`damagePerTick`）の何倍か**で、**落差1段ぶんが1打撃を大きく超えないところから始める。**

**追加で数えること（崖の側）**: **高台のあるマップ**（`country` / `countryskill`）**で、高台の縁からノックバック距離の内側で起きた殴打の割合**／**落差の分布**（1段が大半なら、段数に比例させる意味は薄い）。

#### 実装前に数えた（2026-09-20・4シード × 20000tick・`country` の地図。**この数え上げがこの段階の形を変えました**）

**数え方**: 一時のテストで、1tickごとに解決された殴打すべてについて、**殴られた身体を「攻撃者→被攻撃者」の向きに d だけ押したらどこに着くか**を引き、**そこが水か／歩いては降りられない段差の下か**を数えた（`canStep` が拒む降りだけを「落ちる」と数えた）。**押す距離は決め打ちの4通り**。

| | 1実行あたり | 殴打に対する割合 |
|---|---:|---:|
| 殴打（解決された打撃） | 12195 | — |
| 殴られた時点で既に水の中 | 404 | 0.033 |
| **押した先が水**（d=5 / 10 / 20 / 40） | **16 / 30 / 80 / 250** | **0.0013 / 0.0024 / 0.0066 / 0.0205** |
| **押した先が崖の下**（同上） | **774 / 1002 / 1327 / 1781** | **0.063 / 0.082 / 0.109 / 0.146** |
| 落差の分布（d=10） | **全部1段** | — |
| 1tickの歩幅 / セルの大きさ | **1.94 / 50×50** | — |

**この数え上げで、この段階の本命が入れ替わりました。** **崖は水の25〜50倍の的**です。**理由は地図の形**——**水は幅2セルの帯1本で、身体はそれを避けて暮らす**（水の中にいるのは殴打の3.3%）**のに対し、高台は食料と結びついた広い面で、その縁は長く、人はその上で暮らしている**。**「押して溺れさせる」は絵としては分かりやすいが、世界の中ではほとんど起きません。**

**そしてもう1つ、水のほうは的が小さいだけでなく、効き目も無い**: **溺死は tick あたり 0.0002**（`DrownChancePerTick`）なので、**押し込まれた身体が10tick 水にいても死ぬ確率は 0.2%**。**1実行に16〜250回の押し込みでは、増える溺死は0.03〜0.5体**で、**元から17〜27体ある溺死の中では見えません**。**つまりこの段階が世界を動かすなら、それは落下ダメージの側からです。**

**数えて決めたこと**: **`KnockbackDist` の既定の目安は 5**（**`CombatRadius` 15 の3分の1＝押しても取っ組み合いは続く**。**歩幅1.94 の2.5歩ぶん**）。**20 を超える押しは間合いを切る**ので、**別の腕（`knockfar`）として測る。**

#### 実装後の予想（2026-09-20・**測定前に書いた**）

**腕は4つ**——`knock`（`country` ＋ 押し5）／`knockfar`（同 ＋ 押し20）／`knocknofall`（同 ＋ 押し5・落下ダメージ0）／`knockflat`（平坦な世界 ＋ 押し5）。**対照は `country` と `baseline`。**

- **`knocked` は殴打とほぼ同数**（`knockShare` > 0.9）。**押しが効かないのは「重なって立っている」ときだけ。**
- **`knockFell` は1実行に 400〜800**（**上の数え上げの 774 より少ないはず**——**実際の押しは「landed damage ÷ AttackDamage」で割り引かれ、守りに入っている身体には満額入らない**）。**`knockWet` は 10〜20。**
- **`drowned` は動かない**（上の計算。**誤差の中**）。**これが外れて溺死が増えたら、押し込まれた身体が水から出られていないということ**で、そのときは `wetTicks` を見る。
- **`killed` は上がる**（落下が1実行に 1600 前後の体力を余分に取る＝殴打の総ダメージの2割ほど）。**`pop` は下がる**が、**誤差に隠れる可能性がある。** **`collapsed` は変わらない。**
- **`knocknofall` は `country` と区別がつかない**はず——**5の押し（2.5歩）は、食料のレースにも戦いの間合いにもほとんど影響しない**。**これが対照の役目で、もし差が出たら「効いているのは落下ではなく位置の乱れ」という別の話になる。**
- **`knockfar` は `fights` を1割以上減らす**（**押し20 > `CombatRadius` 15 ＝毎回間合いが切れ、攻撃側は歩いて戻る**）。**`killShare` は下がる。** **落下は増えるので、`pop` への符号は読めない**——**ここは予想を立てない。**
- **`knockflat` は誤差の中**（**押し込む先の地形が無いので、残るのは位置の乱れだけ**）。**これが外れたら、位置の乱れそのものが世界を動かしているということ。**
- **見た目**（`cmd/devview`）: **殴り合いが少しずつ場所を移していく**。**高台の縁での戦いは、片方が落ちて終わる。**
