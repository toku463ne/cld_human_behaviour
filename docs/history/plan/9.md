## 段階97：水の中では遅い（#126。ユーザの「水中の移動に違和感がある」から）【完了・2026-09-18。**既定はオフ**】

**水は移動コスト（`WaterMoveCost` = 3.0）にしか効いておらず、速度は地形を読まない。** 結果、**水の中でも陸と同じ速さで進む**。ここで足すのは**速度側の倍率1本**と、**`SkillSwim` がそれをどれだけ取り戻すか**。

### これは段階20 の決定を部分的に取り消す（先に書いておく）

**段階20 は「倍率は速度ではなくコストに掛ける」と決めており**（`HISTORY.md` 2026-09-06）、**理由は2つあった**。**その2つを今の記録で点検する**:

1. **「速度を落とすのは effort がすでにやっているので、二重にすると測定で区別できない」** → **対照アームで区別できる**。`effort` は身体が選ぶもの、地面の倍率は世界が課すもので、**片方を1に固定した腕を対で回せば分離する**（`waterslowfree` ＝ 遅いが高くない腕）。**当時これを書いた時点では地形そのものがまだ無かった**（`PLAN.md` 767 行目は「地形の下ごしらえ」の項）
2. **「コストに掛ければ『荒れ地を速く渡る』が速さと体力の取引になり、段階7c 以来現れていない『速くて脆い／遅くて頑丈』の並存を作る唯一の見込み」** → **これは測定で外れている**。**段階20 が `speedGap` を倍率 1.5／2／4 のどれでも 0.00 と測り**、**段階33 が「行きにくい地面は速い個体と遅い個体を選り分けない、は交絡ではなくこの世界の事実」と結論した**（食料の相関を入れて頭打ちを破ってもなお 0.00）。**段階38a・57・57c も同じ場所で空振りしている**

**つまり、コストに掛けると決めた理由のうち、1 は対照で解け、2 は既に反証されている。** **したがって取り消すのは「速度に掛けてはいけない」という禁止であって、「コストにも掛ける」は残す**（水は**遅く、かつ高い**）。

### 形

- **速度の倍率はセルの性質**（`terrain.Slow`）。**`Drown` と同じ置き場所**で、**今は水だけが1以外を持つ**（`cfg.WaterSpeedShare`）。**水を名指しする関数を書かない**のは、2つ目の遅い地面が出たときに行を1つ足すだけで済むようにするため（#60 の「2つ目が出たときに共通化する」の逆の側＝**置き場所だけ先に正しくしておく**）
- **既定は 1.0 ＝無効**。**名前と既定は `NursingSpeedShare` の前例に揃える**（速度の倍率で、1 が「この規則は無い」）
- **掛ける場所は `Agent.speedNow`**——**`Agent.MaxSpeed`（上限）には掛けない**。**段階57 がここに線を引いてある**（上限が地面で動くと、境界を1歩越えただけで自分の上限を超えた体力を持つ身体ができる）。**`speedNow` は「今日この身体がどれだけ出せるか」の層**で、**育児の遅さ（段階66）がすでに乗っている層**＝**新しい層を作らない**
- **身体に1tick 1回だけ書く**（`Agent.wading`、`World.wade()`）。**`standOnGround`（段階57 の `footing`）・`nurse`（段階66）と同じ形**で、**速度を読む4か所（歩く・かわす・構える・自分を見る）が同じ数字を読む**＝段階66 が書いた「揃えなければ3つの別の身体になる」。**1tickぶんの古さが代価で、それはこの tick の他の全部が払っている代価と同じ**
- **スキルは別の目盛り**（`SkillSwimSpeedRelief`）。**`SkillSwimRelief`（溺れにくさ）に相乗りさせない**——**相乗りさせると `swimdead` の対照が2つの半分を同時に消す**ので、「泳ぎは溺れないことを買うのか、速さを買うのか」が測れなくなる。**段階62 の `SkillWard` が1つの数字を2つの半分で共有しているのは、あの2つが「本当の効き目」と「その値付け」という同じ1つの事実の両面だったから**で、**ここは本当に別の2つの効き目**
- **効き方は `groundCostFor` と同じ形**（**1に届かないぶんだけが軽減される**＝どれだけ上手くても水が陸より速くはならない）
- **水に住む外敵は遅くならない**（`EnemyKind.Water`）。**溺れないのと同じフラグ、同じ1つの事実**（段階63）
- **知ることは切れる**（`WaterSlowKnown`。`DrownKnown` / `ChillKnown` と同じ形）。**切った腕では世界は同じだけ遅くするが、身体は自分の脚をいつもの速さだと思う**

### やらないこと（先に書く）

- **地域の信念（段階29 の移動コスト）には畳み込まない。** あれは1スカラーの**コスト**の記憶で、**同じ地面について2つ目の量を同じスカラーに入れると、何を思い出しているのか言えなくなる**（#53 の「地形の信念は1スカラー」）
- **`WaterMoveCost` は下げない**（ユーザの指定）。**その結果、同じ距離を渡る体力の代価は倍率のぶんだけ自動的に上がる**——**コストは tick あたりで課金されるので、半分の速さは倍の tick になる**。**これは隠れた用量なので、それを切り離す腕（`waterslowfree` ＝ `WaterMoveCost` = 1）を対で回す**

### 予想（測定前に登録。2026-09-18）

1. **`onWater` は下がらない。むしろ上がるか動かない。** **理由は構造**——`moveCost` は**足元の地面しか読まない**ので、**陸に立っている身体は前方の水が遅いことを知りようがない**（入ることに値段が付かない）。**一方、水の中に立っている身体は全部の移動候補を等しく遅く見積もる**ので、**約分されて比較から消える**（段階57・86 と同じ形）が、**移動しない候補（休む・観察）だけは遅くならない**ので、**残る差は「出ていくのが高い」**。**予想は +0.00 〜 +0.03**
2. **`drownRate` は上がる。** **溺死は滞在 tick 数への課金なので、半分の速さは滞在をおよそ倍にする**。**用量 0.5 で +50% 以上**
3. **`crossIndex` / `crossDry` は動かない**（段階37 と矛盾しない）。**川が視界を分けているのは幅と視界の関係であって速度ではない**。**`bankBoth`（一生のうち両岸に立った割合 0.53）は下がりうる**が、**crossDry は 0.01 の床にすでに張り付いている**
4. **個体数は下がる。** **水は既に3倍高く、そこに滞在時間の倍率が掛かる**ので、**遊ぶ地図で −10 以上**、**river でも −5 以上**
5. **`speedGap`（速い身体が安い地面に、遅い身体が高い地面にいるか）は動かない。** **段階20・33 が3度 0.00 を出した量で、速度に掛け替えても同じ**——**理由は同じで、避けるには前方の地面を知る必要があるから**。**これが外れたら段階20 の2つ目の理由が生きていたことになる（そのときは既定を入れる根拠になる）**
6. **「知らない」対照との差は出ない、または小さい。** **段階34 の溺死・段階86 の寒さ・#76 の拘束と同じ形**（効き目は全部「選別」）。**ただし #76 と違い、知ることが害になるとは予想しない**——**遅さは「出ていくのが高い」としか言わないので、無差別に近いはず**

## 段階98：泳げない身体にとっての水（#127。ユーザの提起）【完了・2026-09-19。**既定はオフ**】

**`DrownChancePerTick` はスキルの有無に関わらず一律で、`SkillSwimRelief` は軽減側にしか効いていない。** つまり**この世界には「泳げないこと」の値段が無い**——泳ぎを持たない身体と持つ身体は、同じ川に同じ確率で取られる（**実効値が 0.1 前後しかないので、軽減側は実質ゼロ**）。ここで足すのは**無スキル側の底上げ1本**で、**`SkillSwim` の習熟度がその倍率を現状まで戻す**。

**狙い（ユーザの言葉）**: **段階97（水の中では遅い）と合わせて、陸生物にとって水を「遅く、かつ本当に死にうる」場所にし、川を渡るハードルを上げる。**

### 先に書いておく（この段階が当たると分かっている壁）

1. **一律の引き上げは段階34 がすでに測っており、世界が壊れる**——**確率を5倍にすると個体数18・外敵が絶滅**。**したがってこの段階の主張は「水をもっと危険にすること」ではなく「危険に個体差をつけること」のほうにしかない**。**一律の腕に勝てなければ、この規則は存在理由が無い**
2. **実効値が低すぎて、線形では一律とほとんど同じものになる。** **段階97 が数えた通り、水の中に立っている身体が実際に持っている泳ぎは 0.072〜0.119**（保有率 0.22〜0.26 × 実効 0.18〜0.41）。**`1 + (F−1)(1−s)` の形にすると s ≈ 0.1 では罰の9割が残る**＝**`DrownChancePerTick` を上げるのと区別がつかない**。**ユーザの「習熟すれば現状程度に近づく」を満たすには、カーブが実際に到達できる習熟度で1に戻らなければならない**
3. **天井は適性遺伝子（`SkillSwim` は体力）。** **段階62 が「実効値が伸びないのは天井にした遺伝子が買われていないから」**と結論しており（防御力は予算比 0.06）、**体力はそれよりは買われているが、天井そのものを買わせる経路が要る**——**この段階が成功するとすれば、そこが「泳ぎに初めて本物の選択圧がかかる」経路になる**

### 形（**実装前の数え上げで (b) に確定した**）

- **カーブ1本に一本化する**: `p = t.Drown × mult(s)`、**`mult(0) = DrownUnskilledFactor`（>1）、`mult(1) = 1 − SkillSwimRelief`**。**既存の `SkillSwimRelief` はこのカーブの下端として残す**＝**同じ1つの効き目についてスキルを2か所で読まない**。**段階97 が `SkillSwimSpeedRelief` を別目盛りにしたのは「溺れないこと」と「遅くならないこと」が別の2つの効き目だったから**で、**ここは同じ1つの効き目に旋盤が2本乗るので、逆に一本化する側**（段階62 の `SkillWard` が1つの数字を共有した理由と同じ判断）
- **既定は `DrownUnskilledFactor` = 1 ＝ 今日と1ビット同じ**（指紋テストが無変更で通り、**段階34・35・38b・42・63・97 の記録がそのまま読める**）
- **中間の形は2案だった**: **(a) 線形**（`mult = 1 + (F−1)(1−s)`）／**(b) 到達できる習熟度で1に戻る**（`DrownSkillFull`）。**数え上げが (b) を選んだ**——**分布が二峰性で、川で育った身体でも 0.525 止まり**なので、**(a) ではその身体ですら罰の大半を払う**。**(a) は腕（`sinklinear`）として回し、結果は `sink3` と区別がつかなかった**（+1.83）
- **掛ける先は `drownChanceFor` の1か所だけ**。**`Self.Drown` が既に個体ごとの figure を返している**（`perception.go` の `drownFelt`）ので、**効用式（`Utility.Hazard`）・知覚・`cmd/devview` の表示は1行も足さずに追随する**
- **外敵**: **水に住む種類（`EnemyKind.Water`）は今までどおり免除**（段階63 の同じ1つの事実）。**陸の外敵には掛かる**——**段階34 の「外敵が絶滅」を用量で再現しうる**ので、**人間と外敵の列を分けて読む**（段階60 の教訓: `pop` だけ読むと逆に見える）
- **地域の危険の信念（段階35）は地面の性質のまま**（`regionlore.go` は `ground.Drown` を読み、`witnessDrowning` も被害者の足元の真値を取り込む）。**個体の倍率をそこに掛けるかどうかは決める点**——**掛けると信念が身体ごとの量になり、伝承で共有する意味が変わる**（「あそこは危ない」が話し手と聞き手で別の数字になる）。**既定は掛けない（場所の危険は場所の性質）を提案し、掛ける腕を対照として回す**
- **知ることは切れる**（`DrownKnown` が既にある。**今回は倍率のぶんも一緒に隠れる**）

**今の水は「移動への通行料」であって「消耗」ではない。** `WaterMoveCost` = 3.0 は `moveCostOn` を通り、**その課金は `if !moved { return }` の後にある**ので、**水の上で立ち止まっている身体からは1ミリも取らない**。**そして先読みが読む消耗速度（`pressures` の `own`）は `projectedDrain(空腹) + Chill` の2つだけ**なので、**川の中の身体と岸の身体は、空腹が同じなら生命の項がまったく同じ**。

**ここで足すのは、場所が毎tick取る目減り1本**——**段階85 が寒さのために作った経路にもう1種類を乗せるだけ**で、**先読みは新しいコードなしにそれを読む**。

### この段階が段階86（寒さ）と違うと言える唯一の理由（先に書く）

**段階86 は同じ形の規則で不発だった**（寒さは飢えと寒さが奪う体力の60%を取るのに、寒い側にいる割合は偶然どおり）。**理由は約分**——**足元の寒さは全候補を等しく押し上げるので、勝ち負けを決める比較から消える**。**この段階も足元を読むので、同じ約分を受ける。**

**それでも効きうる経路が1つだけある**: **`recoverable()` は場所の目減りを `incoming` として引く**（`controller.go:672` が `s.Chill` をそこに渡している）ので、**休息の値打ちだけが、水の中で選択的に下がる**。**他の手の値打ちは下がらない**（生命の項の共通の押し上げは約分される）。**つまりこの規則は「水の中で立ち止まること」を名指しで高くする。**

**そしてそれは段階97 が測った穴そのもの**——**「立ち止まることだけが遅くならないので相対的に勝ち、川の中で立ち止まることはこの世界で一番してはいけないこと」**。**実測で、水の中の tick の 36.9% は身体が静止している。**

**寒さとの決定的な違いは地面の大きさ**: **寒さは地域（幅400）の性質なので、休息をやめて歩いても寒いまま**。**水はセル（幅76.8）の性質なので、2歩で外に出る。**

### 形

- **セルの性質に1つ足す**（`terrain.Drain`。`Cost` / `Slow` / `Drown` と同じ置き場所で、**今は水だけが0以外を持つ**＝`WaterDrain`。2つ目の湿った地面は `cellFor` に1行）
- **既定は 0 ＝無効**（段階85〜97 の世界と1ビット同じ。指紋テストが無変更で通る）
- **数になる場所は1つ**（`World.soakOf(a)`）。**`chillOf` には混ぜない**——**気候と地面は別の事実で、地図の作者は別々に設定する**（`ClimateMap` と `TerrainMap` が別の地図である、という段階85 の線）。**ただし単位も入り先も同じ**なので、**`metabolise` では `chill + soak` として1つの引き算にする**

- **`WaterDrainKnown` が対照**（段階34 の `DrownKnown`・段階86 の `ChillKnown`・段階97 の `WaterSlowKnown` と同じ形。**同じだけ取るが身体は感じない**）
- **水棲の外敵は免除**（`EnemyKind.Water`。溺れないのと遅くならないのと同じ1つの事実＝段階63）
- **泳ぎは効かない**（既定）。**`SkillSwim` にはすでに2つの目盛りがある**（溺れにくさ・遅くならなさ）ので、**3つ目を同じ回で足すと、どれが効いたか測れない**。**足すとしたら次の段階**

## 段階100：一歩先の地面を読む（#129。ユーザの「一歩先のセルを読ませる案。理性による読み精度誤差も入れたい」から）【完了・2026-09-19。**既定はオフ**】

**段階20 以来、効用式は「この先も足元と同じ地面」と仮定している**（`moveCost` が `s.Ground` ＝足元だけを読む）。**その結果、地形について「その手がどこへ連れて行くか」を値付ける項が1つも無く**、段階34・35・63・98・99 の5度にわたって「危険でも消耗でも人は水から出ない」が出た。**ここで足すのは、候補が向かう方向の1セル先を読むこと**と、**その読みに理性の精度が効くこと**。

### なぜこれを P16（地図を作者に開く）より先にやるか（2026-09-19・ユーザの判断）

**段階35 は「信念と真値の相関が 0.98 まで上がっても行動は変わらない」と測っている**（粒度9倍・108地域でも `onWater` は動かず）。**その不発の理由が「地形について行き先を値付ける項が効用式に1つも無いこと」なら、この段階がそれを入れた瞬間に、細かい地図は初めて効く先を持つ。** **逆にここでも動かなければ、段階35 の不発は粒度の問題ではないと確定し、Tiled による自由な地域も細かい豊かさグリッドも「測定で効くもの」としては期待しないことになる。**
