## ゲーム化とマップエディタ（段階19〜22・2026-09-05 追加）

**ここまでの段階が「世界のルールを作る」ものだったのに対し、ここからは「その世界を人が触れるようにする」段階です。** 目指す最終形は次のとおり（管理者の言葉で）:

- 管理者がマップに地形（川・高台〈スロープを通ってしか上れない。高台の上にさらに高台を作れる〉・植物の生えやすい土壌・休息の露出＝隠れやすい場所）を配置して世界を始める
- ノードの初期値は乱数でもよいが、**別の世界ですでに育ったパラメータ**を読み込ませることもできる
- ある程度進めた世界の状態を**保存し、他のユーザ（プレーヤー）に提供**できる
- **天才は基本、管理者が配置する**
- プレーヤーは1ノードを選んで操作し、**子が十分育ってから操作を子へ転移**しながら、その世界を生き延びる
- **難易度は予算で調整する**

**順序は 19 → 20 → 21 → 22 で確定しました**（理由は `TODO.md` の P5）。要点だけ書くと、**20（地形本体）を 21・22 より前に置く**のは、地形の未決（高さをどう表現するか）が「21 が何を保存するか」「22 が何を編集するか」を決めてしまうためです。**19 を先頭に置く**のは、19 だけが世界の状態の形にまったく依存せず（触るのは `Controller` という境界だけ）、しかもゲーム化の一番の不確実性を今の平坦な世界のまま確かめられるためです。

**測定を伴うのは 20 だけです。** 19・21・22 は世界のルールを1つも変えないので、`cmd/experiment` の対を取る必要がありません（代わりに**指紋テストが無変更で通ること**が受け入れ条件になります）。**2026-09-05 に段階23 を足しました**（遊び方そのもの。19 と同じく世界のルールを変えないので、20 の前に通しました）。

**決定事項#51（2026-09-05）**: **人が節目に動かせるのは好みの「配分」であって「値」ではない。** 合計は継いだもので変えられません。理由は2つ——(1) 3つは単位が違うので、倍率にして合計を固定するのが唯一の足し方であり、これは予算制（遺伝子9本が1つの予算を分け合う）とまったく同じ形で、この世界の既存の語彙で説明できます。(2) 自由設定にすると最適値が見つかった時点で毎回同じ設定になり、**節目の選択が形骸化します**。合計を固定すると「用心深くするなら競争心を削る」という取引が必ず発生します。

**確かめて分かったこと（この段階の本体）**

- **`Perception` の情報量は足りていた。** 操作画面は `Perception` の写しだけで作れて、なお「何をすべきか」が読める（自分の体力・空腹・今いる地面の休みやすさ・見えている相手の推定と不確かさ・見えている食料と競合相手の距離）。**足りないと感じたのは情報ではなく、いつ訊かれるか**のほう

## 段階23：選択を要求されるゲーム（転機の一手と、節目の性格）【完了・2026-09-05】

**目的**: 段階19 の完了条件が出した答え——「**足りないのは情報でも行動語彙でもなく、いつ訊かれるか**」——にそのまま応える。**世界のルールは1つも変えない**（指紋テストが無変更で通ることが受け入れ条件）。

**先に測った**（既定条件・4シード・のべ80000エージェントtick）。設計はこの数字の上に載っている。

| | 頻度 | 内訳 |
| --- | --- | --- |
| 全トリガー | **14.5 tick に1回** | 殴られた 52.8%／idle 20.0%／goal reached 18.2%／target lost 5.4%／mate in sight 1.6%／bond ended 0.8%／vitality drop 0.5% |
| 転機だけ（戦闘は1戦＝1回にまとめる） | **112 tick に1回** | 一生で20〜30回 |
| 戦闘の開始だけ | 323 tick に1回 | |

`-slow`（1/5 ＝ 24 tick/秒）で全トリガーは**0.6秒に1回**。段階19 が「リアルタイムで操縦」に感じられたのはこれで、難易度ではなく**質問のレート**の問題だった。

### 23a：転機の一手（`engine/guided.go`）

- [x] `GuidedController` ＝ `Controller` の**3つ目の実装**。`AIController` を内包し、**全部の質問に答えたうえで、一部を人に回す**。AIは「人が留守のときの代役」ではなく**常にその個体を動かしているもの**
- [x] **訊くのは転機だけ**（既定＝殴られた・目標消失・配偶者発見・破局・体力急減）。**戦闘は1戦＝1回にまとめる**（`fightGap`）——毎tick「殴られています、どうしますか」は何も訊いていないのと同じ
- [x] **選択肢はその個体が実際に採点した候補**（`DecisionTrace.Options`）。メニューを別に書かない
- [x] **自分の `ChoiceNoise` を乗せたスコアで並べる**。ノイズ抜きの順位を見せると、**その身体の頭の良さ遺伝子が買っていない賢さ**をプレーヤーに渡すことになる
- [x] **同じ (行動, 対象) は1つにまとめる**（effort 違いを並べない）。上限5件
- [x] **答えるのは1手であって据え置き命令ではない**。取り上げられた瞬間に使い切られ、次からはまた自分で採点する＝段階19 が要した「命令が流れる場合」がここには要らない
- [x] **猶予**（`grace`、既定60tick）。古い質問には答えられない（`ErrQuestionStale`）——遅れて答えるのは「もう無い世界」に対して行動すること
- [x] **狙えるのは視界の中だけ**（段階19 の約束2）。答えの検査は `World.Answer` が行い、`OrderHuman` と**同じエラー**（`ErrOrderUnseen` / `ErrOrderInedible`）を返す
- [x] **`TriggerRequested` も転機に入れる**（遊んで直した。世界はこのトリガーを出さないので、これは人だけが持つ動詞＝「今なにを考えている？」。**転機はわざと稀なので、これが無いと転機の間にできることが見ているだけになる**）
- [x] **受け入れ条件（実測で確認）**: 誰も答えない誘導ノードは、**純粋なAIノードと1ビットも違わない**（`TestUnansweredGuidingChangesNothing`）。質問は世界に何の痕跡も残さない

## 水辺の危険と伝承（段階34〜37・2026-09-07 追加）

- **段階24 の轍を踏まない。** 規則の効き目の上限は発火頻度で決まります。**実装の前に「水のセルに乗っているtickが1実行に何回あるか」を数えます**
- **段階17 の轍を踏まない。** 水辺を豊かにすることは食料の分布を動かすので、**総量は保存します**（#62、段階15a の原則）
