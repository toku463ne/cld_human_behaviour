## 段階7c：遺伝子ベクトル化と予算制

**目的**: 能力3つを `Genome []float64` に置き換え、9種の遺伝子を予算制（予算は親から継ぐ）で導入する。**魅力もここで入れる**（後から遺伝子を足すと、予算も測定のベースラインも取り直しになるため）。

- [x] `Agent.Power/Rationality/Intelligence` を `Genome []float64` に置き換える（インデックスは定数で名前を付ける）
- [x] 遺伝子9種にする: 攻撃力・防御力・最大体力・移動速度・回避率・記憶容量・理性・頭の良さ・**魅力**
- [x] **初期個体の予算だけ抽選する**（`GeneBudgetMean` / `GeneBudgetStd`）
- [x] **初期個体の配分はディリクレ分布から引く**（`GeneInitAlpha` ≈ 0.5〜1。決定事項#24）。α を `Config` に出し、`cmd/experiment` で振れるようにする
  - [x] 標準ライブラリにガンマ分布のサンプラは無いので自前で書く（外部依存を増やさない方針）。Marsaglia–Tsang 法（`NormFloat64` + `Float64` だけで書ける）＋ α<1 用のブースト（`U^(1/α)` を掛ける）で足りる。**乱数は `World` の `*rand.Rand` 1本を使う**
  - [x] **一様乱数の正規化は使わない**（#24）。ちなみに一様の正規化はディリクレ α=1 と等価ではない（α=1 が欲しければ指数乱数を正規化する）
  - [x] 引いた配分を予算に掛けたあと、**遺伝子1本あたりの範囲 1〜100 でクリップして再正規化する**。α が小さいほど極端な配分が出るので、クリップで予算が食い違わないようにする（クリップ後の合計が予算とズレたままだと「予算に対する比率」の測定が狂う）
- [x] **子の予算＝親の予算 ＋ 正規乱数**（平均0・標準偏差 `BudgetInheritSpread`。決定事項#2）。**どちらの親から引くかは 50% のランダム**で、遺伝子の独立分配（#4）と同じ引き方にする。**両親の平均は取らない**（平均は毎世代ごとに予算の分散を半分にするので、混合遺伝をやめた 7b の判断と逆向きになる）
- [x] `BudgetHeritability` を残し、0（毎回抽選＝旧仕様）と 1（親から継ぐ＝既定）を同じバイナリで切り替えられること。0〜1 の連続値にすると「平均への回帰」もこの1本で表現できる
- [x] 継承時の正規化（親から引いた値を、子が継いだ予算に合うようスケール）
- [x] 天才2段階（`GeniusRate` / `GreatGeniusRate` と、それぞれの予算）。`TicksPerYear`（出発点 500。**秒換算は使わない**。**値の確定は段階7d**。上の未決を参照）で「10年に一度」を出生あたりの確率に換算する
- [x] 既存の `Power` の役割（`damagePerTick`）を攻撃力に、`MaxVitality`・`MaxSpeed` を遺伝子に置き換える
- [x] **`fitness` を魅力遺伝子で置き換える**（`world.go:11` の `fitnessPowerWeight` ほか4つを廃止し、`fitness = 魅力遺伝子 × 体調` にする）。パワーに「戦闘に勝つ」と「配偶者を得る」の2役を持たせない

- [x] `cmd/experiment` の能力指標を**絶対値から予算に対する比率へ変更する**（予算抽選のばらつきを拾わないため）
- [x] **段階12 のヒント枠（決定事項#23）が後から同じ予算を食うことを見込んでおく。** 遺伝子9本の配分で予算をぴったり使い切る前提に較正すると、ヒント枠を足したときに全体の水準が下がって過去の測定と比較できなくなる。枠の予算消費量は段階12 で決めてよいが、**`Genome` の表現は「9本＋後から足す可変長のヒント枠」を受け入れられる形**にしておく

## 地形の下ごしらえ（段階番号なし・いつでもよい）

**目的**: 速さが「体力と取引する」形になる唯一の見込みが地形なので、その前の下ごしらえを2つ済ませておく。

**地形全般（川・高低差など）は環境と食料生態系（段階14〜18）の最後**に置きます（2026-09-03）。地形が入るまで水散布は見送り（#44）、`cmd/devview` の地域ブロック（#38）は段階14 で先に入るので、**地形のパッチは地域ブロックとは別物**（地形はコストの地図、地域は食料と休息と将来のリセットの単位）である点に注意してください。

段階7c の完了条件（「大きくて遅い個体」と「小さくて速い個体」の並存）は 2026-09-01 の実測で**起きないと分かりました**。速さと体力はどちらも「殴る」に対抗して買われる**同じ側**の遺伝子で、互いに競合しないためです（相関 +0.147、割合どうしの基準線 −0.125。`HISTORY.md` 追記25）。**速さは効いていないのではなく、9本の中で一番買われています**（予算比 0.230）。足りないのは「速さが有利な場所と不利な場所」で、それを作れるのが地形です。

- [x] **食料レースの勝率に速さを入れた**（2026-09-04）。到達時間の比に置き換え、相手の速さは隠しパラメータなので世界の基準速度を仮定する（`RaceOnDistance` で旧ルール）。**両者は同じ effort で動くと仮定する**ので effort は約分され、残るのは脚の差だけ。**予想（`shSpeed` が上がる）は外れ、動かなかった**——速さはすでに到達tick数を通じて移動コスト・時間コストに効いており、`pGet` は二次的な経路だった。**この空振りは下の表の仮説（足りないのは場所差）を裏づける。** 値段はほぼゼロ（個体数 +1.4 誤差内、餓死率 +0.59 \*）で、**地形が入れば距離と時間は本当に食い違う**ので先に通した。**1回目の実装（自分の effort 対 相手の全力）は個体数を3分の1にした**（`HISTORY.md`）
- [x] **移動コストを地形照会関数経由にした**（2026-09-04、`engine/terrain.go`）。`w.moveCostOn(x, y, effort)` → `w.terrainAt(x, y)`。世界じゅうが `flatGround` を返すので**挙動は完全に不変**で、指紋テストが無変更で通ることがその証拠。**倍率は速度ではなくコストに掛ける**（速度を落とすのは effort がすでにやっていることで、二重にすると測定で区別できない。コストに掛ければ「荒れ地を速く渡る」が速さと体力の取引そのものになる）。**位置を引数に取る**——引数の無い版は、地形が入る日に全呼び出し元を直すことになるため。**コントローラは今も平坦だと思って計画する**（`Perception` に地形は無い）ので、その食い違いを埋めるかは地形本体の段階で決める

### 地形の種類と、それぞれが効かせるもの（2026-09-01 の見込み）

**どれを入れるかで効く能力が変わります。「地形を入れる」と一括りにしない。**

| 入れるもの | 何の価値が上がるか | 速さ × 体力の並存への効き |
| --- | --- | --- |
| **移動コストの地域差**（坂・ぬかるみ） | 速さ**の場所依存** | **本命。** 開けた場所は速い個体、荒れた場所は頑丈な個体という住み分け（ニッチ）ができ、集団全体で見たとき速さと体力の相関が初めて負になる見込み |
| **障害物**（通れない） | **頭の良さ**（経路選択） | 間接的。距離がユークリッドでなくなるので、直線距離で移動時間を見積もっている今の効用式がズレる。障害物は「速さ」より「知能」を効かせる変更 |
| **隘路・チョークポイント** | **防御力** | 逆方向。逃げ場が無い場所では回避が効かず、守りが強くなる |
| **遮蔽**（見えなくなる） | **回避率・知覚** | 視界が円で固定なので、**段階13（視界のグリッド化）とセットでないと効かない** |

### ニッチが成立する条件（入れる前に確認すること）

- **混ざりすぎないこと。** 局所適応は、個体が自由に動き回って混ざると洗い流される。今の世界は顔ぶれの半減期が約30tickで全員が動き回っている。**地形はコストと同時に「混ざりにくさ」も作る**ので地形自身が解決する見込みはあるが、確認は要る
- **1パッチあたりの個体数が足りること。** 世界は 800×600・視界130・個体数111（2026-09-01）。**パッチを大きく取りすぎると局所適応の前にパッチが絶滅する。** 出発点はパッチ2〜3個
- **測り方が変わる。** 相関を集団全体ではなく**パッチごとに測って比べる**。全体の相関が負になるだけでは不十分で、**「開けた場所の平均速さ ＞ 荒れた場所の平均速さ」**まで出て初めて「ニッチによる並存」と言える（全体の相関だけでは単なる分散の増加と区別がつかない）
