## 2026-09-22 明るさが「誰の血筋か」を言う（`bodyPaint` / `TINTED` / `SHADOW`）

**精霊のキャストが白く描かれているのは、色をビューアが決めるため**でした。その色をようやく配線しました。**ユーザの指定は3つ**——**外敵はなるべく暗く塗り、輪郭は塗りより明るく／プレーヤーを一番明るく、他のノードはそれより暗く／プレーヤーの直属の子はプレーヤーと同じ色に。**

### 人（掛け算でできる）

| 誰 | 何色 |
|---|---|
| プレーヤー本人と、その血筋が産んだ子（`lineKids`） | **絵に描かれたまま**（`colorOwnLine` ＝ 白。世界で一番明るい） |
| それ以外の人 | **暗く**（`colorStranger`。ID から ±16 のゆらぎを足す） |
| 誰も操作していない世界 | **全員そのまま** |

**子を「少し暗く」しないのが設計です**——**血筋は1つのもので、この画面が答えるべき問いは「60体のうちどれが自分のか」**。**性別は失われていません**——**精霊は頭の形で言う**（丸い耳／炎のような房）ので、**色を血筋に使えるようになった**のがこの cast の要点そのものです。

### 獣（掛け算ではできない）

**掛け算は明るさを引くことしかできない**ので、**白い身体はどんな色を掛けても一番明るいまま**です。**だから貼る前に焼きます**（`SHADOW`）——**輝度を逆向きに写像して、白いところを暗く（30,27,36）、暗い輪郭を明るく（198,206,224）**。**獣は色を掛けません**（掛けると裏返しが元に戻る）。**これで獣は「人と同じ光でできていないもの」として、色を1つも使わずに読めます**——**色は血筋の印**、という規則が世界に1つだけになりました。

### `tint` の旗は大きさではなく並びが決める

**以前は「16px＝灰色の置き絵だから色を掛ける／32px＝描かれた絵だから掛けない」**でした。**精霊は32pxで、かつ色を掛けるために白く描かれている**ので、**大きさでは区別できません**（`TINTED`＝並びが言う）。**`--carry` もこの旗を持ち越すようにしました**——持ち越していなかったせいで、**3枚を経由した精霊が灰色で届きました**。

- **`lines.png`**（森の床の上に、血筋＝明るい／他人＝暗い／獣4体格を並べたもの）で対比を確認。
- テスト2本——**血筋は絵のまま・他人は必ずそれより暗い**（400体ぶんのゆらぎを全部確かめる。「少し暗い子」が入り込まないため）と、**人は色を掛け・獣は掛けない**（manifest の旗）。

## 2026-09-22 血筋の光を敷き、獣を人より大きくした

**光の3種**（輪・粒・波紋。精霊のシートに描かれて眠っていたもの）**を貼りました。**

| 誰 | 何が出るか |
|---|---|
| プレーヤーの身体 | **足元の波紋＋身体を囲む輪**（金＝`colorPlayed`） |
| 血筋の子 | **舞う粒**（淡い金＝`colorKin`） |
| それ以外・誰も操作していない世界 | 何も出ない |

**明るさがもう言っていることを、1体にだけもう一度言います。** **二重に言う価値があるのはここだけ**で、**60体の中で最初に見つけなければならないのが played の身体**であり、**画面外へ出て戻ってくるのもそれ**だから。**3つの役は形から決まりました**——**波紋は群衆に強い**（重なっても縁が残る）、**輪は引いた絵に強い**（小さくても輪郭に沿う）、**粒は輪と見間違えようがない**。**`frame()` ではなく名前で直に引きます**——`standIn` は無い絵を一番近い身体で代用するので、**誰かの後光として身体が描かれる**ことになるため。

### 獣の大きさの下限を人に合わせた

**`minRadius` が 3.5**（人の3分の1）**でした。** **円だった頃はそれで正しい**——半径＝体力上限で、**軽い獣は本当に身体が小さい**。**描かれた獣になると「大人に混じった子猫」**で、**この画面が唯一間違えてはいけないこと**（獣とは自分を食うもの）**を偽っていました**。

**今は `minRadius = bodyRadius`（9.0）、`maxRadius = 16.0`。** **実測**（4体格・4000tick後）: **飛行 9.1〜12.5／大型 14.1〜14.9／小型 11.8〜18.2／水生 17.5**、**人の大人は 9.0**。**一番軽い獣が大人と同じで、重いものは2倍**——**絵の依頼でも「大型は人の1.5倍」と言っていたので、絵と画面がようやく同じことを言います。**

## 2026-09-22 獣の大きさをもう一度、そして他人の色を遺伝子から

**「まだ小さいし、画素数が粗い」**という指摘。**両方とも、測ると理由が同じところにありました**——**この画面は身体を「幅」で大きくしている**のに、**目が比べているのは高さ**だということ。

### 高さで揃える

| 描かれ方 | 幅に対する高さ |
|---|---|
| 人（立つ） | **0.94** |
| 獣・大型 | 0.58 |
| 獣・小型 | 0.50 |
| 獣・飛行 | 0.53 |
| 獣・水生 | 0.39 |

**半径（＝幅の半分）を人に合わせると、獣は人より低くなります**。**一番軽い獣の高さが大人と同じ**になるところまで上げました——**`minRadius` 9 → 16、`maxRadius` 16 → 24**。**大型で人の1.5倍**（絵の依頼文が言っていたのと同じ）。

### 粗さはセルの大きさだった

**クリップは自分の大きさを持ち、ビューアが画面上の大きさに合わせます。** **獣は32px以上に描かれる**ので、**32pxのセルで切ると毎回拡大**（人は縮小）——**それが「粗い」の正体**でした。**元の絵は1体160px幅**あるので、**獣だけ64pxのセルで切ります**（`CELL`）。**描き直しは頼まずに済みました。**

### 他人の色は遺伝子から

**ID から引いた無意味なゆらぎをやめ**（「複雑さに遺伝子は無い」と書いてあったもの）、**予算の行き先を色にしました**——**赤＝攻撃・防御・体力、緑＝速度・回避、青＝記憶・理性・知能**（群ごとに平均してから比を取るので、3つの群と2つの群が数で不公平にならない）。**明るさには乗せません**——**明るさは「誰の血筋か」の答えに取ってあり**、同じチャンネルに2つ目の意味を乗せると1つ目が壊れます。**どの遺伝子でも血筋より暗いことをテストで固定**（2000通りの genome）。

**2度やり直しました。** **1度目は広げすぎ**（`spread` 2.4 → 0.9）——**予算は実際に偏って使われる**ので、広げると**どの身体も原色の角に着地**し、**白い身体の後ろに控えるべき群衆が白より大声**になりました。**2度目で作り方そのものを変えました**——**一定の明るさに揃える（割り算）をやめ、灰色に1段足す（足し算）**に。**揃える作り方が原色の原因**でした: **暗いチャンネルが強い混色**（赤や青が優勢な身体）**は、狙いの明るさに届くまで大きく掛けられ、上に振り切れて飽和します**。**足し算はそれができません**——どのチャンネルも1段しか動かないので、**元の灰色のまま色みだけが乗ります**。

**実測**（既定の世界を3000tick）: **予算の比は 0.10〜0.60 に散らばり**、色は **rgb(132,132,155)・rgb(128,165,126)・rgb(165,134,120)**——**藤色・セージ・砂**。**原色も蛍光色も出ません。**

### 倒れた身体も、生きていたときの色で

**どの系統の身体が死んでも白く倒れていました**——**白はこの世界で「あなたのもの」を意味する唯一の色**なので、これは一番まずい嘘でした。**原因は、倒れた身体だけが色を掛けられていなかったこと**（薄れる透明度だけを掛けていた）。

**色は身体と一緒に覚えます。** **engine は死んだ身体をその tick のうちに消す**ので、**描くときには何も残っていません**——**倒れた場所を覚えるのと同じところで、そのとき描いていた色も覚えます**。テストで固定（血筋の2体は白、他人の2体はそれぞれの遺伝子の色）。

## 2026-09-22 獣の粗さは倍率の問題、落ちているものは見えなかった

**「外敵の輪郭はやはり粗い」**——**64pxでも足りていませんでした**。**遊ぶ倍率は2.5**で、**人は32pxのクリップから45pxに描かれ（1.4倍）、一番重い獣は120px**。**64pxでは1.9倍の拡大**で、**最近傍で拡大するので縁がブロックになります**（縮小される人は起きない）。**96pxにすると1.25倍**で、**人より細かくなりました**。**絵の描き直しは要りません**——元の絵は1体160px幅あり、足りなかったのは常にセルのほうでした。

**「食料が背景と同化して見えにくい」**——**描かれた地面は苔と土**で、**その上の小さな緑の点は画面で一番見えないもの**です（そしてプレイヤーが一番よく探すもの）。**同じ絵を1.7倍に拡大し、蛍光の黄緑（`#DFFF4F`）で後ろに敷きます**。

- **1pxずつずらした4枚を重ねる「本物の輪郭」は失敗**しました——**身体に隠れてほとんど見えません**（オフラインで4色×4種類を並べて確認）。
- **色は種類ごとではなく1色**。**緑の植物の下に緑の光では光になりません**（これも並べて確認）。**光が言うのは「ここに何か落ちている」**で、**何かは中の絵が言います**。
- **この世界で蛍光色を使うのはここだけ**です。**身体の色は読み**（誰の血筋か・何に予算を割いたか）**なのでくすんだ色に抑えてあり**、**落ちているものは読みではなく目印**なので、大声を出してよい。

## 2026-09-22 自然死は肉にならない（`MeatFromKills`。既定はオフ）

**「外敵が自然死で肉になるのはおかしい」**（ユーザの指摘、画面を見て）。**engine は stage 11 から、死因を問わず全部の死体を肉にしてきました**——餓死も寿命も溺死も。

**規則ではなく旗にしました**（`Config.MeatFromKills`、既定オフ）。**これは食料供給の規則**で、**外敵は肉しか食べません**から、入れると**彼らが生きている糧の一部が消えます**。「もっともらしいか」の話が「世界が保つか」の話に化ける典型で、`CLAUDE.md` の「個体数に触れる変更は長い地平で読む」に当たります。

### 測る前の予想（2026-09-22）

- **`meatDropped` は 15〜30% 減る。** 20000tick では `killShare` が 0.78——**死体の4分の3はもともと殺されたもの**なので、消えるのは残りの4分の1ぶん。**長い地平では寿命死が増えるので、もう少し大きく出る**はず
- **`enemies` は減る**（肉しか食べない）。**10%以上**
- **`pop`（人）はほとんど動かない。** 肉は治すが、外敵が減れば殺されも減る。**±10% 以内**
- **`starved` は増える**
- **`collapsed` は両腕とも 0 のまま**

**予想は4つとも外れました**——「肉が15〜30%減る」「外敵が10%以上減る」「人はほぼ変わらない」「餓死が増える」。**実際には供給は1つも減らず、外敵も人も増え、餓死は減りました。**

**外れた理由がこの規則の正体です。** **減ったのは供給ではなく無駄**でした——**自然死の肉は「その身体がたまたま居た場所」に落ちる**ので、**5分の1が誰にも食べられずに腐っていました**（`meatSpoilShare` 0.21）。**倒された身体の肉は、倒した者がすでに立っている場所に落ちます**。だから**食べられる割合が 0.78 → 0.97** になり、**同じ量の肉が、それを必要としている口に入る**。**そして大きくなった世界はより多くの死体を出すので、殺しから来る肉が、消えた自然死のぶんをそのまま埋めました**（`killed` +2200 \*\*\*）。

**「もっともらしいから」入れた規則が、測ったら世界を大きく安定させた**——という記録です。**12シード中1本あった崩壊が0本になりました。**

**形について決めたこと**

- **Tiled の語は `nest` ではなく `rate` と `cap`。** **`nest: true` は既に色板に塗られている**ので、**数に読み替えると同じ語が2つの意味を持ちます**。**`nest` と `roam` は「実装しなかった語」として `tiled/properties.md` に書き直しました**（巣は `enemy` を塗ったセルそのもの、半径は `EnemyKind.Roam`）。
- **定員が数えるのは「その巣の `Roam` の中に立っている同種」。** **外敵は自分がどの巣の出かを持っていません**（`NestInherited` は測って既定にしなかった）**し、プレイヤーが「この辺は危ない」と言うときに数えているのも同じもの**です。**`HomeX/HomeY` で数える案には倒しませんでした**——空間で数えても発火します。
- **`0` の意味を2つに分けました**: **`rate: 0` は「ここからは来ない」、`cap: 0` は「ここは誰も抱えない」**（＝そこからは湧かない）。**定員そのものが有るかどうかは `Config.NestCap`** で、**セルの数字が「定員なし」を意味することはありません。**
