## 2026-09-16 段階92：痛い贈与と、血縁というもう1本の道——誰に渡すかが初めて動いた

### 数えている途中で、構造がひとつ見つかった

**血縁は最初から `AffinityKin` = 22 を持ち、それは信頼の飽和点 `AffinityTrust` = 20 を超えている。** **したがって `trustBought` は親子についてゼロを返し、`addGive` は `gained <= 0` でそこを抜けていた**——**自分の子に何かを渡すことは、候補に挙がってすらいなかった。**

**実測の「贈与の6%しか血縁に行かない」は、他人を好んでいるのではなく、この飽和だった。** **#121 が「trust を底上げするな、直交する2本目を足せ」と書いたのは正しかったが、理由はもう1つ深いところにあった。**

### 形（どちらも新しい概念はゼロ）

- **92a**: `gift -= GiftSelfLookahead × spareWorth`。**`GiftPriced` は同じ引き算の 1.0 版**（テストで固定）
- **92b**: `gift += GiftKinWeight × takerWorth(渡る物)`。**`takerWorth` は `handWorth` をもう一度引くだけ**で、**体力だけ相手のものに差し替え、空腹は標準（`StarveHunger`）を仮定する**（段階49 の脚・段階80 の標準価格と同じ立場）。**先読みは入れ子にしない**
- **知覚に増えたのは `AgentView.Kin` の1つ**。**血縁は `isKin`（直系1ホップ）で読み、好意は使わない**——**好意は稼げるので、血縁度に使うと「行動で変えられない係数」という性質が壊れる**
- **`gained <= 0` の早期 return は、血縁の枝があるときだけ通さない**（上の飽和のため）

### 目盛りは実装中に決まった——価格は好意の10〜30倍ある

**手の中の食べ物は、その身体にとって 18〜94 の値打ちがある**（空腹度で振った実測）。**贈与が買う好意は最大 2.7。** **だから「価格の1%〜2%」でようやく釣り合い、4分の1でほとんどの贈与が消える**。**段階84d・88 が2度測った「値段を付けると交換が消える」は、この引き算そのものだった。**

## 2026-09-16 段階93：飢えを「締切」ではなく「速度」で読む——壁は消えた。市場はそれでも開かない

**P14 の診断（余裕のある身体は勾配が平らなので何も欲しがらない）に、この群で唯一まっすぐ当たる段階。** **的は `oneHorizon` の1行**——**タンクが窓より長くもつ身体は、どれだけ速く減っていようと 0**。**入れたのは重み1つ**（`LookaheadReadsRate`。**既定は0＝それ以前の全世界**）で、**締切の読みとハザードの読み（`1 − exp(−窓/残りtick)`）を混ぜる**。**混ぜる形にしたのは、消えない裾は全員の危険を一様に持ち上げるから**——**一様な持ち上げは `LifeValue` を上げることと同じ**で、それは段階67 が単独で測った別の規則。

## 2026-09-16 段階94：欲求という4本目の選好——手で置いた定数は、選択が選ぶ値より低かった

**効用式の「危険の側」には3つの選好があったが、「目的の側」には個体差が1つも無かった**（`OffspringValue` は全員共通の 42）。**4本目として「子が何の値打ちか」を足した**（`MateWeightSpread`。**既定は0＝それ以前の全世界と1ビット同じ**）。

**置き場所は予算の外**——**体内時計の位相（段階18）・味の位相（段階84）と同じ立場**で、**「もっと買える量」ではないものを予算に入れると、生物がしていない取引を主張することになる**から。**実装は `lore` 構造体に1フィールド**で、**継承（粒子的＋変異）・伝承（`meet`）・初期分散（`spreadAround`）・保存・知覚は既存の経路にそのまま乗った**（新しい機構はゼロ）。

## 2026-09-18 段階97：水の中では遅い——`onWater` が倍になったのは選択ではなく算術

**ユーザの「水中の移動に違和感がある」から。** 水は移動コスト（`WaterMoveCost` = 3.0）にしか効いておらず、**速度は地形を読まなかった**ので、**水の中でも陸とほぼ同じ速さで進んでいた**（実測で陸の **0.978 倍**）。

### 段階20 の決定を、水についてだけ部分的に取り消した

**段階20（2026-09-06）は「地形の倍率は速度ではなくコストに掛ける」と決めており、理由は2つあった。** 今の記録で点検した:

1. **「速度を落とすのは effort がすでにやっているので、二重にすると測定で区別できない」** → **対照アームで解ける。** **`waterslowfree`（遅いが高くない水）は単独ではっきり効く**（個体数 −23.65 \*\*\*、`onWater` +0.14 \*\*\*）＝**速度の倍率と effort は区別できる**
2. **「コストに掛ければ『荒れ地を速く渡る』が速さと体力の取引になり、段階7c 以来現れていない『速くて脆い／遅くて頑丈』の並存を作る唯一の見込み」** → **これは測定で3度反証されている**（段階20 が `speedGap` を倍率1.5／2／4 のどれでも 0.00、段階33 が「交絡ではなくこの世界の事実」、段階57・57c も同じ場所で空振り）

**取り消したのは禁止だけで、「コストにも掛ける」は残した**（水は**遅く、かつ高い**）。**掛ける先は `speedNow`（今日出せる速さ）であって `MaxSpeed`（上限）ではない**——**段階57 が引いた「上限は地面を読まない」線はそのまま**。

**性能は測って変わらない**（`BenchmarkEngineStep` 757,862 → 758,067 ns/op、`BenchmarkDecide` 20,695 → 20,575 ns/op）。**規則がオフの世界では `World.wade()` が入口で戻り、`speedNow` に分岐が1つ増えるだけ**。


## 2026-09-19 段階98：泳げない身体にとっての水——狙った選り分けは作れて、その選り分けに値打ちが無かった

**ユーザの提起から。** `DrownChancePerTick` はスキルの有無に関わらず一律で、`SkillSwimRelief` は軽減側にしか効いていなかった（しかも実効値が 0.09 なので実質ゼロ）＝**この世界には「泳げないこと」の値段が無かった**。**足したのは倍率1本**（`DrownUnskilledFactor`。既定 1 ＝無効）で、**既存の軽減と1本のカーブにした**——無技能で この倍率、**`DrownSkillFull`（0.5）でちょうど元の確率**、そこから `SkillSwimRelief` が下へ続く。**同じ1つの効き目についてスキルを2か所で読まないため**で、**段階97 が速度を別の目盛りにしたのとは逆の判断**（あちらは「溺れないこと」と「遅くならないこと」という別の2つの効き目だった）。

**規則は完璧に効いている。** `drownTaken`（溺れた身体の泳ぎ）は **0.05 → 0.03** で、**一律の腕では 0.05 のまま**＝**同じだけ溺れさせても、溺れる人が変わった**。`wetGreen`（水の中で泳ぎを持たない割合）も 0.65 → 0.55（5倍で 0.38）。

**それでも、危険を配り直すことに値打ちは無かった。** **同じ平均倍率を全員に配る一律の腕のほうが個体数は多く**（+8.46 \*）、**全員を3倍にする腕は溺死がもっと多い**（`drownRate` +0.09 \*、溺死 +8.72 \*）**のにさらに多い**（+10.20 \*）。**どちらも 1.2〜1.5 SE なので「一律に勝てなかった」までしか言えない**が、**「ばらつきが買うものがある」という主張はこの測定では立たない**（段階95 の「水準は効き、ばらつきは効かない」と同じ形）。

### 予想は7つ書いて3つ当たり・2つ外れ・2つ半分

**1.（当たり）`drownRate` は用量どおり上がり、溺れるのは泳げない身体。** +0.22／+0.37／+0.66 \*\*\*、`drownTaken` 0.05 → 0.03。

**2.（当たり）`onWater` は動かず、「知らない」対照と区別がつかない。** +0.01〜−0.02 で、`sinkblind` も同じ。**4度目**（段階34 の溺死・段階86 の寒さ・#76 の拘束）。**そして今回は滞在の内訳まで数えた**——**滞在はむしろ少し延び**（116.9 → 127.5 tick）、**歩いて出て終わる割合が 96.0% → 91.5%、死んで終わる割合が 4.05% → 8.50%**＝**身体は早く出るようにならず、出る前に死ぬようになっただけ**。

**3.（半分）個体数は下がる／外敵のほうが先に減る。** 下がり方は予想（3倍で −20 以上）を大きく超えた（**−40.50 \*\*\***）が、**外敵が先ということはない**（人間 −40%・外敵 −36% でほぼ同じ）。

**4.（半分）`crossDry` は不動・`bankBoth` と `bankMoves` は下がる。** 下がる（−0.07 \*\*／−1.36 \*\*）が、**`crossDry` も −0.00 \*\* とわずかに動く**。**そして「知らない」腕でも同じだけ下がる**ので、**渡らなくなったのではなく渡る身体が減っただけ**。

**5.（外れ・逆向き）泳ぎへの選択圧が出る → 出ないどころか下がる。** `swimReal` −0.08 \*\*、`swimWet` 不動、**天井の遺伝子（体力）の予算比 −0.01 \*\***。**数え上げでも分布は動かない**（保有 0.285 → 0.296、p90 は 0.525 のまま）。**機序: 世界が貧しくなると予算が削られ、スキルの天井を買う余裕が先に消える**——**スキルを値打ちのあるものにする一番素直な方法（それを持たないと死ぬ）が、そのスキルの天井を買えなくする**。

**6.（当たり）「知らない」対照は害にならない。** +6.43（誤差内）＝**段階97 の +17.04 \*\* との最大の違い**。**理由は予想どおり**——**遅さは移動をともなう手を全部一様に高くした**が、**溺死は「その手が身体を水に留めるtick数」に比例するので、出ていく手と留まる手を区別する**。

**7.（外れ）一律の対照に勝てるかは五分 → 負けた。** 上記のとおり。

### 約分では説明できない不発だった（これが段階34・86 との違い）

**段階57（足元の地面）と段階86（寒さ）は「共通項だから比較から消える」で説明がついた。** **今回は消えていない**——**水の中の身体が採点する候補の間で、`Hazard` の開きは 1.80 → 5.21 に広がる**（床は 0.016 → 0.052）。**それでも行動が変わらない理由は大きさのほう**: **その身体自身の評価ノイズ（`ChoiceNoise` ≈ 20）に対して4分の1**しかない。**段階34 が「罰は選択肢1つあたり 0.8 ＝ノイズの25分の1」と書いた比が、3倍の用量で6分の1になっただけ**で、**足りない**。

### 決めたこと

- **既定は `DrownUnskilledFactor` = 1（無効）。** **規則は狙いどおり動き、狙った選り分けを作る**が、**どの用量でも個体数を払い**、**同じ水準を一律に配る腕に勝てない**。地形の他の性質と同じく**地図の作者が入れるもの**
- **`DrownSkillFull` = 0.5（到達できる習熟度で1に戻る）**。**線形（1）は腕に残す**——測定では `sink3` と区別がつかなかった（+1.83）が、**「1に戻る点をどこに置くか」は分布を見て決める設計判断なので、既定は分布に合わせる**
- **`DrownBeliefPerBody` = false。** **場所の危険は場所の性質**（true は一番悪い腕）
- **水上の食料アクセス制限（案2）は、この結果では復活の候補に戻る**——**この段階が `onWater` を動かせなかったから**。ただし**段階34・35・63・98 の4度で「危険では人は水から出ない」が確定したので、次に試すなら危険ではなく食料の側**（段階36 が唯一動かした経路）

**性能は変わらない**（`BenchmarkEngineStep` 757,862 → 755,768 ns/op、`BenchmarkDecide` 20,575 → 20,711 ns/op）。**既定の世界では `drownFactorFor` が入口で 1 を返すだけ**で、**指紋テストは無変更で通る**。
