## 2026-09-20 地域をタイルで塗る——オブジェクト層が要る理由は、3つのうち2つが間違いだった

**`TODO.md` の1番（Tiled）の続き。** **ユーザの問い「地域レイヤーが『オブジェクト層』である必要は？なぜタイル層ではダメ？」に、要らないと答えて足したもの。**

**前日に挙げた3つの理由を数え直した結果**:

- 「地域1つにつきタイルが1枚要る」——**Tiled では普通のこと**（弱い理由）
- 「タイル層だと地域が何百にもなりかねない」——**間違い**。**地域の数は塗ったタイルの種類の数**であって、塗ったセルの数ではない
- 「位置→地域の索引が要る」——**反論になっていない**。**200×200 の索引表はすでにあり**、**タイル層はその表を直接埋めるだけ**

**本当の違いは1つだけだった**: **数字がどこに付くか**。**矩形は1つ1つが自分の数字を持つ**（見た目の同じ2つの場所を別の値にできる）。**タイル層は「塗った色＝その地域」**なので、**数字はタイルの種類に付く**。**その代わりに、塗りは矩形にできない形になれる**（L字、分かれた谷、曲がった岸）。**それでどちらも残した**（**同じセルについて両方が言っていたら塗りが勝つ**＝細かく言ったほうを採る）。

**足したもの**:

- **`Config.RegionMap []string`**（1セル1文字）＋ **`RegionShape.Key`**（その文字）。**`TerrainMap` / `SpawnMap` と同じ「1セル1文字＋凡例」の形**に揃えた
- **Tiled の読み取り**: **`region` プロパティ（名前）を持つタイルで塗った層**が地域。**同じ名前のタイルは離れて塗っても1つの地域**で、**数字は同じタイルが持つ**（`shelter` / `food` / `special` / `enemies` / `goal`）
- **タイル層の役割を、順番ではなく中身で決めるようにした。** **地形だけが「最初の層」**で、**それ以降は塗っている中身で地域か発生タイルかが決まる**。**前日の「2枚目＝発生タイル」のままだと、地域だけ描いて発生タイルを描かない地図が誤読される**。**地形だけ中身で決められないのは、1枚のタイルが「何の地面か」と「何が湧くか」を同時に言えるから**（魚の湧く水タイル）
- **`World.Regions()` が返す枠を、地域が描かれているときは実際の位置から作るようにした。** **それまでは `RegionCols`×`RegionRows` の格子の枠を返していて、描いた世界では嘘だった**（前日の矩形でもすでに嘘だった）。**塗られた地域の枠は「囲む箱」**で、**正確な答えは `regionIndexAt` だけ**
- **`cmd/devview` は、描かれた世界では地域を格子状に問い合わせて塗る**（`World.DrawnRegions()` で分岐、120列の粗い格子）。**L字を矩形で塗ったらその絵自体が嘘になる**ため

**壊していないことの確認**: **塗らない世界は1ビットも変わらない**（テストで固定。指紋テストも無変更で通る）。**保存と読込に乗る**（`RegionMap` は `Config` の一部で、索引は読込時に作り直す＝前日に見つけた欠けと同じ経路）。**`go test -race ./...` 全緑。**

**目視**（`cmd/devview -tiled`、40×30 タイルの見本）: **L字に塗った「the bend」が L字のまま緑に出て**、川の蛇行・高台と斜面・右上の荒地も絵のとおりに出た。**このとき前のセッションのdevviewが生き残っていて、同名ウィンドウの古いほうを2回撮っていた**（記憶にある落とし穴をそのまま踏んだ）——**撮る前に `ps` で確認する**。

## 2026-09-20 タイルの語彙を先に決めた——種類を増やす前に、名前だけ決めておく

**ユーザの提起**（「植物の種類、外敵の種類を今後増やしていきたい。その前提でタイルを作りたい。プロパティの指定方法は？」）**から。** **`engine` は1行も変えていない**——**決めたのは名前だけで、実装は P16-2 と P16-3 のとき。**

**決めたこと（決定事項#133。設計は `PLAN.md` の P16-5）**:

- **植物の種類で `FoodKind` を増やさない。** **種類は `Food` のフィールド**（`Special` / `Cooked` / `Style` / `Made` と同じ立場）。**理由は `cook.go` が #80 で既に名指ししていた**——**`NumEdibleKinds` は `dietVariety` の目盛り**なので、**4つ目の可食 kind は段階42 以降の記録を全部「別の測定」にする**
- **外敵の種類は `EnemyKinds` の行を1つ足すだけ**（段階59）。**種ではなくタグ。**
- **魚は外敵の一種**（ユーザの指定）。**したがって種類の表は「植物」と「外敵」の2つだけで、3つ目は作らない**——**水の生き物はすでに `EnemyKind.Water` の行**（段階63）。**`fish` という種類名の語は予約しない。** **ただし `spawn: fish` は別物として残る**（**食料アイテムの魚が湧く場所**であって、生き物の話ではない）。**「魚を生き物にする」は 2026-09-13 の「作らない」のまま。**
- **地図は名前だけを運び、数値は運ばない**（数値は `Config` の表）。**同じ数字を2箇所に置くと必ず片方が古くなる**という、文書の分担と同じ理由

**書いたもの**: **`tiled/properties.md`**（地図を描く人が読む一覧。**engine が今読む語の正はここ**）と、**`tiled/samples/001_3division.tmj`**（その語を一通り使った30×20の見本と、そのタイルセット）。

**予約語の衝突を1つ見つけた**: **`kind` は地形専用**で、**知らない値を1つ書くと地図全体が読み込みエラーになる**（`groundChar` が拒否する）。**逆に、知らない「名前」のプロパティは黙って無視される**（`propString` / `propNumber` は名前で引くだけ）ので、**将来用の語を今日書いておける**のはそのおかげ。

### 数えて分かったこと——届かない地面は食料を飲み込む

**見本が本当に遊べるか確かめるために腕を分けた**（20000tick・6シード・平均個体数）:

| 腕 | 平均個体数 |
|---|---|
| 平坦な世界 | 149.8 |
| 地形＋発生タイル＋地域（＝見本） | 127.7 |
| 地形＋発生タイル | 107.0 |
| 地形＋地域 | 47.8 |
| **地形だけ** | **3.8** |

**地形だけの世界が壊れる理由は、地形の costs ではなかった**（溺死を切っても 12.8、移動コストを全部1にしても 36.5 にしかならない）。**原因は食料の枠**——**`MaxFoodItems` は世界全体で1つ**で、**ランプの無い高地に生えた植物は誰にも食べられないまま枠を占め続ける**。**その割合は時間とともに増える**（シード1・tick 500 → 8000 で **高地と水の上の植物が 35% → 53%**、**個体数 64 → 13**）。**発生タイルを陸だけに塗ると 0% のまま、個体数 60 → 73。** **つまりこの見本は「発生タイルが陸だけに塗ってあること」で成立している。**

**もう1つ、開始時の一度きりの代価**: **初期配置は地形を見ない**ので、**この地図では 70体中10体（14%）が高地の上に生まれる**。**tick 2000 までに 3%、10000 で 0%** になり、**そのあと個体数は 125 まで戻る**。**破綻ではなく、開始時の目減り。**

**目視**（`cmd/devview -tiled`、3枚）: **川・東の海・中央台地（崖の線）・その中の閉じた湖・4本のランプ・外周の高地リング・1セルの高地**が絵のとおりに出た。**台地と外周には誰もいない**——**発生タイルが高地に1枚も塗られていないので、行く理由が無い**。**tick 10080 で pop 63・gen 5**、**死因は 20000tick で 365死のうち kills 301・餓死50・溺死14**。

**そして絵に出ない発見が1つ**: **魚が1匹も食べられていない**（`FishEaten: 0`）。**`FishShare` の既定は 0**（段階42「魚がいるかどうかは地図の作者が言うこと」）で、**Tiled の地図には「魚がいるか」を言う手段が無い**——**`spawn: fish` は「どこに」であって「あるか」ではない**。**24枚の青いひし形は今のところ効いていない。** **これは P16-2（地図が数値をどこまで言えるか）の具体例として残す。**
